# The tenancy guard's allow-list: SQL statements over a root table (or reads of
# a read-scoped or keyed child table such as audit_log) that may legitimately
# leave a table without its project predicate. One `path:line reason` per line,
# path relative to the repository root, line = the line the guard reports: the
# statement's use site — the line of its first unscoped table name when the SQL
# is written there, or the line naming the package-level constant that holds
# it. A constant shared by several statements is therefore listed once per
# unscoped use, each with its own reason, and a new use is a new finding.
# `#` starts a comment.
#
# Before adding an entry, prefer scoping the statement. An entry is right only
# when the statement must span every project (maintenance, metrics, reset,
# backup, storage moves), runs in a worker that works from a photo uid with no
# request project, or addresses a row the same transaction already resolved
# inside the project. The reason must say which.
#
# The guard fails on an entry whose line no longer holds an unscoped statement
# ("stale allow-list entry"): when a file shifts, move its entries with it.
