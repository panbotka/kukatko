# The footer floats mid-screen on every short page

The application shell has no minimum height, so on any page whose content is shorter than
the viewport the footer sits directly under the content with a large empty band beneath it.

## Evidence

Measured on `/people` in a 1440x900 window:

```
viewportH 900 · footerBottom 451 · gapBelowFooter 449
```

Half the screen below the footer is empty. This affects every empty state — `/people`,
`/albums`, `/labels`, `/saved`, `/favorites`, `/trash` — which is exactly what a new
instance shows most of.

## Requirements

- On a page shorter than the viewport, the footer sits at the bottom of the viewport.
- On a page taller than the viewport, the footer stays at the end of the content and
  scrolls with it. It must not become a fixed bar overlaying the page.
- The behaviour must hold at phone width as well as desktop, and must not introduce a
  vertical scrollbar on a page that would otherwise not have one.
- Watch out for the mobile bottom navigation bar: the footer must not end up hidden behind
  it or push it around.

## Testing

Add a style test asserting the shell's minimum-height and the footer's top-margin
declarations, following the existing pattern of the style tests under `web/src/styles`.
