# Curator role 3/5 — albums, labels, upload, bulk

Move the remaining 14 endpoints onto `RequireCurator` and close the line with a
field-level check on the one endpoint that mixes curation with metadata.

Read `docs/superpowers/specs/2026-09-26-curator-role-design.md` sections 3 and 4 before
starting. Requires steps 1 and 2.

## Requirements

- Move to `RequireCurator`:
  - `internal/organizeapi`: all ten album and label writes, `DELETE` included.
  - `internal/expandapi`: `GET /albums/{uid}/similar`, `GET /labels/{uid}/similar`.
  - `internal/ingest`: `POST /upload`.
  - `internal/bulkapi`: `POST /photos/bulk`, subject to the field check below.
    `POST /photos/bulk/location-summary` stays on `RequireWrite`.
- `internal/bulk` gains a pure predicate over `Operations` answering whether the batch
  asks for anything beyond album and label membership. It performs no I/O and lives next
  to the type it judges.
- `bulkapi`'s handler consults it: a caller who only `CanCurate()` and sends a batch that
  touches title, description, capture date, location, clear-location, archive or hide is
  refused with 403 before any row changes. An editor is unaffected.
- The per-user operations `Favorite` and `Rating` are allowed for a curator: a viewer can
  already set both one photo at a time, so bulk must not be stricter than the single-photo
  route.
- A viewer must still get 403 on every one of these routes.
- Tests: a unit test for the predicate covering an album-only batch, a batch carrying a
  capture date, a batch carrying a location, and the favorite/rating exception; plus a
  curator case in the boundary tests of `organizeapi`, `expandapi`, `ingest` and
  `bulkapi`, including a curator's mixed batch being refused.
- Docs: `docs/API.md` guard column for the moved routes and the bulk field rule,
  `docs/PACKAGES.md` for `internal/bulk`.

## Implementation notes

- Authorizing inside the handler is not a new pattern here: comments and saved searches
  already do ownership checks behind `RequireAuth`.
- Known pre-existing failure: `web/src/pages/ReviewPage.test.tsx`, case "leaves no
  snapshot behind a finished round", fails on main under the full vitest suite and passes
  in isolation. If `make check` is red only there, it is not this task's regression.
