# Mobile Filter Drawer Footer and Slimmer Library Chrome

Two mobile findings from docs/UX_RESEARCH.md: the filter drawer has no footer — no live result count and no explicit way to apply/close (N16); and on a phone roughly 350 px of an 852 px viewport is controls, pushing photos and the timeline rail off screen (N19).

## Requirements

- The mobile filter drawer gets a sticky footer with: a primary button showing the live number of matching photos ("Zobrazit 1 234 fotek" / "Show 1,234 photos") that closes the drawer, and a secondary reset action.
- The count updates as the user changes filters (debounced; reuse the total the photo list API already returns). While the count is being fetched the button shows a loading state — never a stale number presented as current.
- Slim down the controls above the mobile grid so more of the viewport shows photos; secondary controls collapse behind a menu or into the drawer. The timeline rail must remain reachable.
- No desktop regressions — the desktop layout stays as it is.
- cs + en i18n for all new copy.

## Implementation notes

- Known repo gotcha for tests: an open Offcanvas is a portal — query via role=dialog and within(), and phone behavior needs a matchMedia override; see existing drawer tests.
