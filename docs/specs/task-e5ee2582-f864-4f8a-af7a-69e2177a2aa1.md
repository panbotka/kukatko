# Family network 3/3 — retire the directional walks

Remove what the network view made dead, so the endpoint has one behaviour and the package
has one walk.

Read `docs/superpowers/specs/2026-09-26-family-network-view-design.md` sections 4 and 7
before starting. Requires steps 1 and 2, and must not run before the page no longer sends
`direction`.

## Requirements

- `GET /subjects/{uid}/tree` loses the `direction` and `generations` parameters and always
  answers with the network.
- A member carries only the signed `generation`; the unsigned `depth` field and the
  `partner` flag are removed, the latter because a network has no line to be married into.
- `family.Store.Ancestors`, `family.Store.Descendants`, `ancestorsSQL`, `descendantsSQL`,
  `clampGenerations` and the parameter parsing in `internal/familyapi/decode.go` go, along
  with the tests that covered only them. Confirm by grep that nothing else calls them
  before deleting.
- `internal/photos/store_query.go` and its `familyDepthLimit` are **not** touched: the
  `family:` search filter keeps its own walk and keeps meaning the descendants of a root
  plus their partners.
- `MaxDepth = 20` stays, as the cycle guard it has always been.
- Tests: the endpoint's contract after the removal, including that a request carrying the
  old parameters is not broken by them.
- Docs: `docs/API.md`, `docs/PACKAGES.md`, and `CLAUDE.md` only if a package changed shape.

## Implementation notes

- Section 7 of the design explains why the tree page and the `family:` filter now answer
  different questions on purpose. Leave that divergence in place and make sure the
  documentation says so, otherwise a later reader will unify them.
