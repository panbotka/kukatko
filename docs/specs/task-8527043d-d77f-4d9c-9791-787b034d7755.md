## What is wrong

Switching the UI language to English changes every visible string, but `<html lang>` stays `cs`.
A screen reader therefore announces English content using Czech pronunciation rules, and the page
misreports its language to anything else that reads the attribute (translation tooling, search
indexers).

Found during the v0.24.0 pre-release walkthrough on box staging. **Pre-existing — not introduced by
the v0.23.0..e1b50f5 range**, which only added task strings to `i18n/locales/{cs,en}`. Severity: NIT
(accessibility correctness, no functional breakage).

## Reproduce

1. Sign in on box staging (http://100.127.79.1:6490, `admin` / `adminadmin`).
2. Go to `/account` and click **English**.
3. Confirm the UI really switched — the navbar reads `Library / Albums / Labels / Search / Browse`.
4. In the console:

   ```js
   ({ htmlLang: document.documentElement.lang, i18n: localStorage.getItem('i18nextLng') })
   ```

Observed: `{ htmlLang: "cs", i18n: "en" }` — the attribute never follows.
Expected: `htmlLang` tracks the active i18next language (`en` here, `cs` after switching back).

## What to do

Wire the attribute to i18next rather than leaving it on whatever the server rendered: set
`document.documentElement.lang` on the initial language resolution **and** on every `languageChanged`
event, so it is correct both on first paint and after a switch. The natural home is wherever i18n is
bootstrapped in `web/src/i18n` — check whether a provider or an effect in `App.tsx` is the better
seam, and follow whatever pattern the file already uses.

Worth a quick look while you are there: whether anything else assumes a static `lang` (CSS
`:lang()` selectors, hyphenation rules, `Intl` formatting).

## Done when

- Switching cs → en → cs updates `document.documentElement.lang` each time.
- The attribute is already correct on first paint for a user whose stored language is `en`
  (no flash of `cs`).
- A frontend test covers the switch (Vitest, in the i18n or App test file, asserting the attribute
  after `changeLanguage`).
- `make check` passes; docs updated only if a rule or component contract changed
  (`docs/FRONTEND.md` if the i18n bootstrap gains a documented responsibility).
