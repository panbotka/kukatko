# Photo reads are scoped by project

## Context

Kukátko is multi-tenant: `photos.project_id` exists (transitional DEFAULT = bootstrap project), routes are mounted under `/api/v1/p/{project}` (plus unprefixed aliases → `v`), `auth.ProjectUIDFromContext(ctx)` gives the current project, and `internal/projecttest` offers the two-project harness (`Seed`, `AssertInvisible`, `AssertSameShape`, `AssertStoreScoped`, `AssertListExcludes`). Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4, 3.1, 6; read `docs/PACKAGES.md` for `internal/photos`, `internal/query`, `internal/photoapi`. Step 11 of 40. This step covers the **read side** of the photo core; the write side, media bytes and worker loaders are the next step.

Scoping convention (used by every scoping step): a store method that touches a root table takes `projectUID string` as the first argument after `ctx`; it **never** defaults it — an empty value returns a typed `photos.ErrNoProject` (a programming error). Handlers pass `auth.ProjectUIDFromContext(ctx)`. At the HTTP layer a foreign row is a 404 **indistinguishable** from a missing one.

## Requirements

- `internal/photos.Store` read methods: list/browse (all orderings and cursors), timeline, counts and stats, detail by uid, lookup by file hash, lookup by PhotoPrism/photosorter uid (joins `photoprism_aliases` with `project_id`), the "what has been computed" readers used by `/photos/{uid}` (faces roll-call, places, HLS renditions, edits, comments listing, ratings/favourites of the caller), the slideshow/neighbour queries (prev/next), the `task=` listing. Each gets `projectUID` and the predicate `photos.project_id = $n` (or on the joined root).
- `internal/query` → SQL compilation in `internal/photos`: the compiled WHERE always starts with the project predicate; every filter key (`uid:`, `hash:`, `album:`, `label:`, `person:`, `family:`, `place:`, `camera:`, `type:`, dates, `task:`, free text, OCR text…) is evaluated inside the project. Add a compiler test that the emitted SQL for each registered key (`query.Keys()`) contains the project parameter — iterate the registry, do not hand-list keys (see the "query key parity guard" test pattern in `internal/globalsearchapi`).
- `internal/photoapi` read handlers (list, search, detail, timeline, stats, neighbours, counts) and `internal/globalsearchapi` pass the project; foreign uid → 404 same shape as missing (delete the `t.Skip` left in the harness's worked example).
- Isolation tests: `AssertStoreScoped` for list, timeline, stats, by-hash, by-alias; HTTP: detail, search with one value for every key kind (`album:`, `person:`, `label:`, `uid:`, free text), global search, neighbours; `AssertSameShape` for detail.
- Docs: `docs/PACKAGES.md` (`internal/photos` scoping convention — make it the canonical description that later steps point to), `docs/API.md` (the 404 rule).

## Out of scope

Write methods (edit, rating, archive, visibility, comments write), thumbnails/download/rendition bytes, `mediaurl`, worker loaders, any other package.
