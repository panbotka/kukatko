# Bigger, clickable photos on the review-decisions page

The admin page listing one user's sorting decisions (`/audit/reviews?user=…`, "Rozhodnutí v
třídění") shows every decision with a 48×48 thumbnail that is not a link. This is the page where a
wrong Ano/Ne gets spotted, so the photo has to be big enough to judge and one click away from being
fixed.

## Requirements

- Each row's thumbnail is a link to that photo's own detail page, navigating inside the app
  (client-side routing, same window), with an accessible label saying what the link opens.
- The thumbnail is markedly bigger than today — about 96 px square on desktop. It stays a square
  centre crop served by a registered thumbnail size (`tile_224`); never link the original or an
  aspect-preserving rendition into the table.
- On a phone the row still fits: the thumbnail may shrink, but the table must not start scrolling
  horizontally and the other columns must stay readable.
- The link is reachable by keyboard with a visible focus ring.
- A decision whose photo is missing, or whose thumbnail fails to load, renders the blank well
  exactly as it does today — no link, and the row keeps its height.
- Coming back from a photo returns to the same page, the same Ano/Ne filter and the same offset (the
  view already lives in the URL — keep it that way).
- Update the page's tests for the link and the new size, and keep the existing thumbnail and
  empty-well tests passing.

## Implementation notes

- The whole change is in `web/src/pages/ReviewDecisionsPage.tsx`: `DecisionThumb` and the
  `THUMB_SIZE` constant. Note that a centre-cropped `tile_*` size is the right source here (a
  `fit_*` rendition would not fill a square box).
- The page is described in `docs/FRONTEND.md` — update that entry if its description stops being
  accurate.
- Frontend only — no API and no backend change.
