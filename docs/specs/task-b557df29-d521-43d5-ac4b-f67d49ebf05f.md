# Viewer: half of the chrome hides when idle

UI/UX review finding #11 (2026-10-11). In the photo viewer (`/photos/:uid`) the toolbar and the prev/next arrows fade out after ~2.6 s without pointer activity, but the back button and the title (date · place) stay visible. The result looks like a broken toolbar rather than an intentional "immersive" mode. On a desktop with a mouse, auto-hiding the chrome at all is questionable: the pointer resting on the page is not a reason to remove controls.

## Requirements
- When the chrome hides, it hides as a whole: back button, title, toolbar, arrows. When it shows, everything shows. (The info/faces side panels are independent and unaffected.)
- On devices that have hover (`(hover: hover)`), do not auto-hide the chrome; it stays visible while the viewer is open (optionally hide only when the pointer leaves the window or after a much longer idle, 8 s or more). On touch devices keep the current tap-to-toggle and auto-hide behaviour.
- Keyboard focus inside the chrome always keeps it visible.
- Keep the existing CSS data attribute / class mechanism; adjust the rules and the timer gating rather than inventing a second mechanism.
- Update the viewer chrome tests (there are tests around `data-chrome="hidden"` and the hide timer) for the new rules; use the touch-detection helpers the tests already use.
