# Open a photo from the sorting game inside the app

In the sorting game (Třídění, `/review`) the "Otevřít fotku v nové záložce" control — and its `o`
keyboard shortcut — calls `window.open(..., '_blank')`. In the installed PWA there are no tabs: the
photo opens in the app window itself, the player has no back button, and the run is gone. Make that
route work inside the app.

## Requirements

- Activating the control (click, tap, or the `o` key) navigates to the photo's own detail page
  inside the app via client-side routing, in the same window. No `window.open`, no `target="_blank"`.
- The control stays a real anchor carrying an `href`, so a modified click (Ctrl / Cmd / middle
  button) and the browser's own "open link in new tab" still work on desktop.
- Coming back to the game (browser or system back, or the affordance below) lands the player on the
  same card, with the round's progress and the session tallies intact. Going to look at a photo must
  not cost the run. If the game does not yet keep a snapshot of a run in progress, add one
  (`sessionStorage`, scoped to the signed-in user, ignored when it is unreadable or belongs to
  another account) — a working return path is the whole point of this change.
- The photo detail page, when it was reached from the game, shows a clearly visible way back to
  sorting at the top of the page. An installed PWA has no browser back button, so this is the only
  guaranteed way home. Label it via i18n in both locales (Czech default), and do not show it when
  the page was reached from anywhere else.
- Every card that carries the control behaves the same way: the question stage, the outlier card,
  the duplicate pair, and the "jen pro radost" breather.
- The control's wording no longer promises a new tab: update `review.openPhoto` in both locales
  (the `aria-label`/`title` it feeds must stay an accurate description of what happens).
- Tests: the control navigates in-app instead of opening a window (the existing tests assert
  `window.open` — they need rewriting, not deleting); the `o` shortcut does the same; the back
  affordance shows on the detail page when it came from sorting and not otherwise.

## Implementation notes

- The anchor lives in `web/src/components/review/ReviewStage.tsx`, `ReviewOutlier.tsx`,
  `ReviewDuplicate.tsx` and `ReviewBreather.tsx` (several of them through `ReviewPhoto.tsx`); the
  keyboard twin is `openPhoto` in `web/src/pages/ReviewPage.tsx`, which also owns the single
  `photoDetailPath` helper.
- The destination is `web/src/pages/PhotoDetailPage.tsx` (route `/photos/:uid`). React-router
  location state is the natural carrier of "came from sorting"; a URL query parameter is acceptable
  too, but then it must not break the "Back always works" convention.
- Frontend only — no API and no backend change.
