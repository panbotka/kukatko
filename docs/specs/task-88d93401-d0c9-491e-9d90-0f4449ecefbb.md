# `kukatko ctl`: the rest of the curation surface

Close the gaps that stop `ctl` from doing everything a curator does to a photo short
of changing its state on disk: albums and labels beyond creating them, stacks,
non-destructive image edits, saved searches, similarity and comments.

## Requirements

- **Albums and labels** gain update and delete. Today `ctl` can create an album and
  add photos to it but cannot rename it, edit its description or remove it — an
  agent that can only ever add is not curating, it is accumulating.
- **Stacks**: group RAW+JPEG or edited variants of one shot, ungroup one photo,
  ungroup all, and set which variant is primary. Grouping never merges — the
  commands must not suggest otherwise.
- **Image edits**: read a photo's current non-destructive edit and write a new one
  (crop, rotate, brightness, contrast). Saving a neutral edit is a legitimate reset,
  not a no-op, and must be supported.
- **Saved searches** ("smart albums"): list, create, update, delete. They are
  strictly per-user — a foreign one answers 404 and the CLI must surface that as
  "not yours", not as a crash.
- **Similarity and duplicates**: list a photo's visually similar neighbours with
  their distance; confirm or dismiss a duplicate pair. Merging duplicates is
  destructive and belongs with the guarded commands, not here.
- **Comments**: read a photo's thread and write into it. Reading matters most —
  a thread often holds the only record of who, where and when, which is exactly what
  an agent needs to date a photo.
- Everything supports `-o llm`.

## Implementation Notes

- Cobra command in `cmd/kukatko/ctl_*.go`, client and renderer in `internal/ctl/*.go`,
  a `_test.go` next to each. This is a CLI layer over `internal/organizeapi`,
  `internal/stacks`, `internal/photoedit`, `internal/savedsearchapi` and
  `internal/comments` — no new domain logic.
- **Comments may be written only under the agent's own account.** The audit trail
  records the token's owner as the author, so writing through a human's token would
  put words in that human's mouth. The MCP server forbids comments entirely for this
  reason; the CLI is allowed them because the account is distinct.
- Builds on the `-o llm` format from the earlier `ctl` task; depend on it rather than
  reinventing it.
