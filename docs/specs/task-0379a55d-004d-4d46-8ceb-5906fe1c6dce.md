# A video tile shows that the clip is still being prepared

A video tile in the library grid carries a play badge with the clip's duration. The badge is
drawn purely from the media type, so it looks identical whether the clip is ready to stream or
was uploaded ten seconds ago and has not been encoded yet. Clicking the second kind may lead to a
video the browser cannot decode.

Give the badge a quiet indication that the streaming version is still being prepared. The grid
does not have that information today, so this task adds the cheapest possible signal for it.

## Requirements

### The signal

- Rows in the library listing and in search results carry, for videos, whether the clip has at
  least one encoded streaming rendition. The photo detail already carries exactly this as an
  `hls` boolean; use the same field name and meaning on list rows so a client has one concept,
  not two.
- The field is only meaningful for videos. Do not emit it for stills.
- The instance capabilities response gains a flag saying whether video streaming is switched on
  for this instance, mirroring how the existing feature flag there is shaped. With streaming off,
  no video will ever have a rendition and the tile must show nothing unusual.
- Cost is the whole point of this task: fold the lookup into the existing listing query. A listing
  page must not gain a query per row, and the plan for a plain library page must not degrade.
  Check the query plan against the test database and record what you measured in the performance
  document.

### The tile

- When streaming is on for the instance and a video row has no rendition, the play badge gains a
  small, quiet indicator that the clip is still being prepared — a glyph beside the play mark,
  not a second badge and not a colour that reads as an error.
- The play affordance itself stays. The clip may well be playable already through the original
  file; the indicator is information, not a block.
- The indicator carries an accessible name so it is not a decorative glyph with no meaning.
- With streaming off, or for a clip that has a rendition, the tile looks exactly as it does today.

## Documentation

The new response fields go into `docs/API.md`, the capability into `docs/API.md` and
`docs/OPERATIONS.md` where the instance flags are described, the tile into `docs/FRONTEND.md`,
and the query-cost measurement into `docs/PERF.md`.

## Tests

Integration tests for the listing field — a video with a rendition, a video without one, a still —
and component tests for the tile in all three states plus the streaming-off case. A virtualised
grid mounts no items under the test renderer, so test the tile component directly rather than
through the grid.
