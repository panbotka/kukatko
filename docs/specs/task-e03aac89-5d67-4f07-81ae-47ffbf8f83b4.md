# Make the public upload-link page foolproof on a phone

Almost everyone opens `/u/:code` (`UploadLinkPage`) on a phone, often a non-technical relative. Make it as simple and as hard to break as possible: one obvious action, an unmissable progress bar with a time estimate, and protection against cancelling or interrupting a batch by accident.

## Requirements

- **One obvious path, mobile first:** one large full-width "Vybrat fotky" button as the primary action (the drop zone is secondary/desktop only). Show the "Od koho?" field before the picker, but keep it optional and never blocking. Keep the text minimal, with large tap targets (at least 48 px), checked at 360 px width.
- **Three clear states:** *pick* → *uploading* → *done*. While uploading, the page shows only the progress and a short "Nechte stránku otevřenou" notice. The done screen is unmistakable: a big check mark, "Hotovo, nahráno N fotek", a "Nahrát další" button, and the existing registration offer.
- **Visible progress:** a large overall bar with a percentage and "X z Y fotek". It stays visible while the per-file list scrolls (sticky). The per-file `UploadQueuePanel` is collapsed by default behind a "Podrobnosti" toggle.
- **Time estimate:** a remaining-time estimate from the measured throughput (bytes/s, smoothed, e.g. a moving average). Show "zbývá asi 3 min" only after a few seconds of data, round it to human units, and never let it jump wildly. While there is no data yet, show "počítám…".
- **No accidental cancel:** while a batch is running there is no easy-to-hit control that removes or cancels files. Per-file remove/cancel, and any "clear", stay hidden until the batch finishes or a file fails. The existing `useLeaveGuard`/`beforeunload` warning stays. In-app links (e.g. registration) are not shown until the batch finishes.
- **Screen lock / backgrounding:** keep the screen awake with the Screen Wake Lock API while uploading. Re-acquire it on `visibilitychange` back to visible, and release it when done. When the API is missing, degrade silently.
- **Interruption recovery:** when the page comes back to the foreground (or the network returns: `online` event), any file that failed with a network/abort error is retried automatically, with no tap needed. The server's SHA256 dedup (and commit 3a19e7c, which lets a re-upload repair an upload that finished without its client) makes re-sending safe. Show "Spojení přerušeno, pokračuji…" instead of a scary error. Errors that cannot be retried (`not_media`, a dead link) keep their message.
- **Offline:** when `navigator.onLine` turns false, show a clear "Jste offline — počkám na připojení" banner and pause rather than burning through retries.
- **After a reload:** the browser loses the selected files. If a batch was in progress (remember per device the count and the timestamp, see **Browser storage**), say kindly "Nahrávání bylo přerušeno — vyberte fotky znovu, už nahrané se nezdvojí".
- All new texts go through i18n `uploadLink.*` (cs + en).

## Implementation Notes

- Reuse `useUploadQueue`: its `progress` is already byte-weighted. Add the throughput/ETA as a small pure helper with unit tests, not inside the component.
- Put the wake lock and the foreground/online auto-retry in a hook (e.g. `useUploadResilience`) with Vitest tests (fake timers need `shouldAdvanceTime`; stub `navigator.wakeLock`).
- Keep the authenticated `/upload` page's behaviour unchanged unless a shared component change is clearly beneficial to both.
- Update `docs/FRONTEND.md` (the `UploadLinkPage` paragraph, the new hook, the browser storage key) and `README.md` if the feature is user-visible.
- Verify visually on a 360×800 mobile viewport (agent-browser), including the done screen and the offline banner.
