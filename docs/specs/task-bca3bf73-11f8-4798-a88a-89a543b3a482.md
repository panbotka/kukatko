# /users: show waiting accounts by default, make approving on a phone one tap

The admin's usual errand on `/users` (`web/src/pages/UsersPage.tsx`) is letting newly registered people in, mostly from a phone. Today the page opens on the whole roster (`pendingOnly` defaults to `false`), and the phone card layout stacks every action button (approve, edit, change password, reset link, block) under every account, so it is hard to scan and approve.

## Requirements

### Default filter
- The "Jen čekající na schválení" filter is **on by default**. The state lives in a URL query param (project rule "back always works"): no param = waiting only, an explicit param (e.g. `?all=1`) = everyone. Toggling the switch updates the URL, Back restores the previous state, and a reload keeps it.
- When nobody is waiting, the default view does not look broken. It shows a clear empty state ("Nikdo nečeká na schválení") with a button/link that switches to all users.
- The waiting-count reminder keeps counting everybody, as it does now.

### Phone layout (below the breakpoint where cards replace the table)
- A **waiting** account's card is compact: display name/username, e-mail, when they registered, and the upload link they came through (if any, already shown since b32f870). Its primary action is one large, full-width **"Schválit"** button.
- Approving from the card is **one tap**: no confirmation modal. A wrong approval is cheap to undo (block the account), and approving is the action this screen exists for. Show success feedback, and the card leaves the waiting list right away. The approve button is disabled while the request runs, so a double tap cannot fire twice. Errors show inline on that card. Keep the confirmation modal on desktop only if the implementer finds a reason to; otherwise drop it everywhere for consistency, and say which in the commit.
- The secondary actions (edit, change password, reset link, block) are folded behind one "Další akce" control per card (dropdown or expandable). They are not a stack of full-width buttons. The existing disabled-reason hints (`ReasonedButton`, maintainer boundary, self) keep working inside it.
- Cards of already-approved accounts (when showing all) get the same folded secondary actions and a compact field list.
- Tap targets ≥ 44 px, no horizontal scroll at 360 px width.

### Desktop
- The table keeps working. Only the default filter and (if chosen) the dropped approve confirmation change there.

## Tests
- Vitest: filter on by default without a param, `?all=1` shows everybody, toggling writes the URL, empty state + its switch, one-tap approve on the card (no modal; button disabled while pending; card disappears from the waiting list; error stays on the card), secondary actions reachable through the fold with their disabled reasons.
- Visually verify on a phone viewport (e.g. a 390×844 screenshot of a throwaway instance or static harness) and attach it to the commit/notes.
