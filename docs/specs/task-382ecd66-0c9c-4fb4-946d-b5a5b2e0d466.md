# Keyboard-First Navigation and Shortcuts Overlay

The command palette (Cmd-K / "/") exists; complete the story so the whole app can be driven from the keyboard.

## Requirements

- In the photo grid: arrow keys (plus j/k) move a visible focus ring between photos; Enter opens the focused photo; Space toggles its selection; f toggles favorite (respecting role permissions). Focus scrolls into view correctly in the virtualized grid.
- A "?" shortcut opens a shortcuts overlay: a dialog listing all keyboard shortcuts grouped by context (library, photo detail, selection), closable with Esc. Inventory the shortcuts that already exist today (lightbox arrows, palette, …) first, so the overlay is truthful and complete.
- Shortcuts never fire while an input/textarea or the command palette has focus.
- Existing shortcuts keep working; no conflicts introduced.
- cs (default) + en i18n for the overlay.
- Tests for the grid key handling and the overlay.

## Implementation notes

- Known repo gotcha: a shortcut that "only works after a click" is usually waiting on data, not focus — wire handlers so they work as soon as the page has its data.
- Update docs/FRONTEND.md (keep any existing shortcuts inventory there current).
