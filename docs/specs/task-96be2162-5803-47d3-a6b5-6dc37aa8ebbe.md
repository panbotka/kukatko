# Settings, registration and the announcement are per project

## Context

Kukátko is multi-tenant. `instance_settings` and `announcements` are keyed by `project_id` (one row per project) and their stores take `projectUID`, but `settingsapi`/`announcementapi` still pass `project.BootstrapUID` with `TODO multi-tenancy` comments; `POST /projects` already creates a settings row for a new project. Registration creates a membership in the resolved project. Frontend: `/p/:slug` routes, `apiPath`/`instancePath`, `usePublicSettings`, `useAnnouncement`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 4.2. Step 28 of 40.

## Requirements

- `settingsapi`, `announcementapi`: read the project from `auth.ProjectFromContext`; remove the TODOs; the routes live only under the prefix. A project admin edits registration open/closed, the secret and the welcome Markdown of **their** project; the welcome text shown on first sign-in is the project's (`users.welcome_seen_at` stays per user — document it).
- Anonymous reads: new `GET /api/v1/p/{slug}/settings/public` (no auth; `WithProject` must allow anonymous for this one route, returning only `{project_name, registration_enabled}` and 404 for unknown/inactive slugs); the instance-level anonymous settings route keeps only `passkeys_enabled`.
- Registration page moves to `/p/:slug/register` (instance `/register` redirects to it when a `?project=<slug>` param is present, else shows "Registrace probíhá přes pozvánku nebo odkaz projektu"); the form posts the project's secret; the account becomes an unapproved viewer of that project.
- Frontend `/p/:slug/settings` (project admin): registration toggle, secret (show/regenerate), welcome Markdown editor with preview (the `Markdown` component), plus a read-only "Využití a limity" block (photos, originals bytes, the two limits with "neomezeno"; note "limity nastavuje správce systému"). The announcement banner (`useAnnouncement`) is keyed by slug.
- Tests: Go — A's secret does not register into B (same-shape failure as a wrong secret); public settings for an inactive project → 404; announcement set in A invisible in B. Vitest — register page per project, settings page, banner per project.
- Docs: `docs/API.md`, `docs/PACKAGES.md`, `docs/FRONTEND.md`, `README.md`.

## Out of scope

Dropping the transitional `users.*` columns and the user-picture rules (next step), limits enforcement.
