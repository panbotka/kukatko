# Run the quality gate on the build box

`make check` takes roughly 15 minutes on the Pi, and almost all of it is the 217-file
vitest suite on 4 cores. The box (`ssh box`, 24 threads, 62 GB RAM) can run the same
target far faster. Add a way to run the gate there against the **working tree**, including
uncommitted work.

## Requirements

- `scripts/check-on-box.sh` syncs this repo's working tree to the box and runs the gate
  there, streaming the output, and **exits with the remote command's exit code** — a
  remote failure must never surface as a local success.
- New make target `check-box` running that script. `make check` keeps its current meaning
  and stays the binding gate; `check-box` is an accelerator that must run the *same*
  target remotely, never a reduced subset.
- **`.secrets/` is never synced.** The gate needs no credentials (unit tests only), and the
  box has no business holding this instance's database DSNs or API keys. Exclude
  `node_modules`, `.git`, `bin/` and the build output too — sync should be a few MB.
- The box is not always on: the script wakes it (`boxon`), waits for SSH with a bounded
  timeout, and on failure says plainly that it could not be reached and that `make check`
  is the local fallback. It must not hang indefinitely.
- One-time toolchain bootstrap, performed by the script when missing: Go (the version in
  `go.mod`), `golangci-lint` (the version CI pins), and `npm ci` in `web/`. Node v22 is
  already installed. Re-runs must reuse the remote `node_modules` and Go module cache
  rather than reinstalling.
- Two sessions may run this at once (the Pi hosts several Claude sessions): the remote
  working directory must not be shared in a way that lets one run clobber another.
- Integration tests stay out of scope and the script says so: the test database lives on
  the Pi, so `make test-integration` remains a local command.
- Docs: the new target and its limits go in `docs/OPERATIONS.md`, and the local-development
  loop in `docs/DEVELOPMENT.md` gains a line pointing at it.

## Acceptance

- On a clean tree, `make check-box` exits 0 and is materially faster than `make check` on
  the Pi — report both wall-clock times in the commit message.
- With a deliberately introduced lint error, it exits non-zero and the error text is
  visible locally. Prove this, do not assume it.
- With the box unreachable, it fails with a clear message rather than hanging or falsely
  passing.
- `git status --short` is empty afterwards: the sync must not write anything into the repo.

## Implementation notes

- Connect as **`ssh box`** — `~/.ssh/config` sets the user to `panbotka`. The `ssh box@box`
  form in the global CLAUDE.md does not authenticate.
- Verified on 2026-08-10: the box has Node v22.22.2, but **no Go and no golangci-lint**.
- The Pi has 16 GB shared by every stack; the point of this task is to move load off it, so
  the script should not keep heavyweight processes running locally while the box works.
