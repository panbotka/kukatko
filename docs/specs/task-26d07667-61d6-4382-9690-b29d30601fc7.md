# The help page never mentions the query language, and promises something the app does not do

`/help` is a well written page with thirteen chapters (Procházení fotek, Hledání, Alba,
Štítky, Oblíbené a hodnocení, Lidé a obličeje, Duplikáty, Varianty jednoho snímku, Mapa a
místa, Mazání a koš, Import knihovny, Uživatelské role, Váš účet). Two problems:

1. The **"Hledání" chapter does not mention the query language with a single word.** It talks
   about the quick filter and about content search. That the app understands `person:`,
   `year:`, `label:`, `rating:`, `faces:` and ranges is discoverable only through the **?**
   popup on `/search`. Help is the one place where a feature can be found without stumbling
   over it, so a feature missing from it effectively does not exist.
2. The **"Procházení fotek" chapter promises** "Stav prohlížení — filtry, řazení i pozici —
   si aplikace pamatuje v adrese stránky, takže tlačítko Zpět vždy funguje." Filters and
   sorting really are in the URL; the scroll position is not. A false sentence in help is
   worse than no sentence — the user assumes they are doing something wrong.

## Requirements
- Add a short section about `klíč:hodnota` queries to the "Hledání" chapter with three
  worked examples and a pointer to the full table — or embed the existing `SearchQueryHelp`
  component directly, so there is only one source of truth for the syntax.
- Check the second claim against the running app: scroll to the middle of the library, open a
  photo, go back. If the position is restored, keep the sentence. If it is not, reword it so
  it only promises what actually happens (filters and sorting).
- Both changes in Czech and English.

## Where it is
`web/src/pages/HelpPage.tsx`, texts in `web/src/i18n`,
`web/src/components/search/SearchQueryHelp.tsx` (component to reuse).

## Out of scope
No data changes.
