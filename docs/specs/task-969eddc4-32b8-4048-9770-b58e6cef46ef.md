# Choose a new password from a reset link

The API issues one-time password-reset links valid for 7 days. `GET
/auth/password-reset/{token}` says whether a link is still usable, and `POST` to the same
path sets the new password. Neither needs authentication. Give the link a landing page.

## Requirements

- A new route `/password-reset/:token`, reachable without signing in, laid out like the
  existing sign-in screen.
- On open the page checks the link first. While it checks it shows a quiet loading state,
  not an empty form.
- A usable link shows a greeting with the person's display name and two fields: the new
  password and its repeat. They must match before the form submits, and the password must
  meet the same rules the account screen already states.
- An expired, already-used or unknown link shows a plain explanation and a link to
  sign-in. It does not show a form, and it must not reveal whether the account exists.
- On success the page confirms the password was changed, says that any other signed-in
  sessions were ended, and offers a link to sign in. Do **not** sign the person in
  automatically.
- A failure at submission time — the link expired between opening the page and submitting
  it — falls back to the same explanation as an expired link.
- The screen is usable on a phone: one column, inputs large enough to tap, no horizontal
  scrolling.
- All text goes through i18n with Czech and English strings.

## Definition of done

- Component tests cover: a usable link, a successful change, mismatched passwords, an
  expired link on open, and a link that expires between open and submit.
- `docs/FRONTEND.md` describes the new page.
- `make check` passes.
