## Context
Round-2 review of the multi-tenancy programme (2026-10-14, main 672357f6). Reports: `<path>/kukatko/multitenancy-review-2/fixes-review.md` §A1 and `migration-review.md` §2 + S1. Proven twice (round 1 and round 2): release 0.31.0 serving against the new schema → every login 500 (`column "subject_uid" does not exist`) while its `/healthz` stays 200. The deploy order must be stop old → start new.

Findings:
- `cmd/kukatko/migrate.go` (~72-84): subcommands that open the DB (incl. the read-only `maintenance scan`, `maintenance inventory`?, `import dir`, `ctl`-less admin commands) print "applying N pending migration(s)" and then migrate anyway. An operator running one with the new image while 0.31.0 still serves breaks production.
- The new server does not notice a running old instance; the advisory lock only serialises two new binaries.

## Requirements
- Only `kukatko migrate` and `kukatko serve` apply migrations. Every other subcommand that finds pending migrations refuses with a clear message ("database is at schema N, this binary expects M; run `kukatko migrate` after stopping the old server") and exit code ≠ 0. `maintenance inventory` must keep working against an old (unmigrated) schema exactly as today — it is the release-day A snapshot (check its current behaviour first; it must never migrate).
- `serve`/`migrate` with pending migrations: detect other live Kukátko connections on the database (e.g. `pg_stat_activity` with an `application_name` the binary sets — set it now in internal/database so future releases are detectable; for the current 0.31.0, which sets none, detect by any other connection from a different client to the same DB user and warn loudly in the log + refuse in `kukatko migrate` unless `--force`). Keep `serve` starting (compose does stop→start, so normally there is no other connection); document precisely.
- Tests: unit/integration for the refusal and for application_name; CLI help text.
- Docs: OPERATIONS.md (upgrade runbook: which commands may run when), docs/MIGRATION_SAFETY.md note.
