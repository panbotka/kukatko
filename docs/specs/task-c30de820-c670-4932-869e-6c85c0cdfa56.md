# Tasks: selected photos into the discussion

When a human reviews a batch task ("Dávka: rekruti (61 fotek)") the typical objection is "these three are wrong". Today they would have to copy photo identifiers by hand into a comment. Comments are plain text (`internal/comments`, rendered by `CommentsPanel`), and a photo uid (`ph` + 24 lowercase base32 characters) in a comment is just text. This task adds a bulk action on the task page that writes a comment referencing the selected photos, and teaches the comment renderer to show referenced photos as links and thumbnails.

## Posting from a selection

- On `/tasks/{uid}` the existing `BatchActionBar` (`components/organize/BatchActionBar.tsx`, already extended with a remove-from-task action on the task page) gets an action "Do diskuse" / "To the discussion" (a chat icon via the `Icon` component). It opens a small modal showing the selected photos as `tile_100` thumbnails (up to 24, then "+N"), a textarea for the message (may be empty), and Send.
- Sending posts **one** comment on the task whose body is the message, a blank line, then one photo uid per line. Plain text, no Markdown. The selection is cleared and a toast confirms. Failure keeps the modal open with an inline error.
- Available to anybody who can comment on a task (viewers included), not only writers; the bulk selection UI must therefore be reachable for a viewer on the task page even though the other bulk actions are writer-only (hide those for a viewer).
- Comments have a length limit; if the uid list would exceed it, refuse in the modal with the count that fits.

## Rendering references

- In every comment thread (photo threads and task threads alike) each token matching the photo uid pattern becomes a link to `/photos/{uid}`; inside a task thread the link carries `?task={taskUid}` so the viewer's prev/next and Back stay in the task. Below the comment body a strip of `tile_100` thumbnails renders for the referenced uids (max 12, then "+N"), each linking the same way. Uids that are not in the current task's group still link; a thumbnail that fails to load falls back to nothing (no broken image).
- Output must stay safe: the body is still rendered as text (never as HTML or Markdown); only the recognized uid tokens are replaced with anchors.
- The ctl `tasks comment <uid> "…"` with uids in the text needs no change; it just starts rendering nicely in the web.
