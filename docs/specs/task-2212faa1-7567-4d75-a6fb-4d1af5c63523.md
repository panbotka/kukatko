# Every derived object follows its original's layout

## Context

Kukátko is multi-tenant. `projects.storage_prefix` exists: `""` for the bootstrap project `v` (its objects stay at the bucket root until a separate, manually started move), `projects/<uid>/` for every other project; ingest already prefixes the **original** key. Keys today (see `internal/storekeys`): originals `YYYY/MM/<name>`, sidecars `sidecars/<original key>.yml`, thumbnails `thumb/aa/bb/cc/<hash>_<size>.jpg`, HLS `hls/<hash>/<rendition>/…`, `families.yaml` at the root; local cache: `storyboard/…`, `avatar/…`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 5.2. Step 31 of 40.

**The rule:** the layout of a photo's derived objects is the layout of its **own original** — the prefix is taken from `photos.file_path`, never from the project row — so a half-moved project is consistent per photo and reads never fall back or guess.

## Requirements

- `internal/storekeys`: `PrefixOf(originalKey string) string` (`projects/<uid>/` when the key starts with that pattern — validate the uid shape — else `""`), `Strip(key) (prefix, rest string)`, `Join(prefix, rest)`. `Classify(key)` accepts both layouts and returns the `Kind` **and** the project uid (`""` for root layout) — extend the return type or add `ClassifyWithProject`; every existing prefix test gains a prefixed twin. The original-key regex accepts `projects/<uid>/YYYY/MM/<name>`.
- Key builders: thumbnails (`internal/thumb`), HLS (`internal/hls`), sidecars (`internal/sidecarexport` — the sidecar of `projects/<uid>/2024/05/x.jpg` is `projects/<uid>/sidecars/2024/05/x.jpg.yml`, **not** `sidecars/projects/…`), storyboard and avatar caches, and `families.yaml` (uses the project's current `storage_prefix`, already done in the family step — verify) all take the prefix derived from the photo's `file_path`. Each builder gets a table-driven test with a root-layout and a prefixed photo.
- `internal/trash` purge deletes the original, thumbnails and HLS under the photo's own prefix; `internal/storyboardjob`/`avatar` cache paths likewise.
- Guarantee that keys never collide across projects: a test in `internal/project` that `Create` never yields an empty prefix, plus a test in `internal/ingest` that two projects storing identical bytes get different keys.
- Docs: `docs/ARCHITECTURE.md` storage section (the two layouts and the rule, with examples), `docs/PACKAGES.md` (`internal/storekeys`).

## Out of scope

Maintenance scan, backup classification, reset/purge of a prefix, the move itself (next steps).
