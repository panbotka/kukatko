# The welcome dialog asks a question that cannot be answered on a fresh library

On a fresh instance the first sign-in opens a "Vítej v Kukátku" dialog that asks the user
to pick which person in the library they are. It shows a search box, and then states
"V knihovně zatím nikdo pojmenovaný není." The only action that does anything is
"Přeskočit".

This is the first thing a new administrator sees, and it is a dead end: the dialog asks for
a choice from an empty set.

## Requirements

- When the library holds no named subjects, the first-sign-in flow must not present the
  person picker. Show whatever welcome content is worth showing and let the user get on
  with it.
- The picker must still appear for a user signing in for the first time on a library that
  does have named people, since there the question is answerable and useful.
- A user who never got the picker because the library was empty must still be able to link
  their account to a person later, through the account page, without any reset.
- Do not simply hide the dialog entirely — the welcome text itself is configured by an
  administrator and should still be shown.

## Edge cases

- A library that has faces detected but none of them named still counts as "nobody named".
- The state must be evaluated when the dialog would open, not cached from an earlier visit,
  so an instance that gains its first named person behaves correctly for the next new user.

## Testing

Frontend tests for both paths: with zero named subjects the picker is absent and the
welcome content still renders; with at least one named subject the picker is present.
