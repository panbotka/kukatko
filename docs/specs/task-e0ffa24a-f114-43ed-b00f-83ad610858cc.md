# /people has no controls, and each face tile downloads a full-size preview

Two problems on one page.

**No controls.** The page renders 105 people as an alphabetical grid with nothing above it —
the heading "Lidé" is followed straight by 105 links. No search by name, no sort by photo
count, no split between people and animals. On a phone that is two per row, about 53 rows of
scrolling, ordered by first name. "Find grandma" means remembering her name and scanning the
alphabet.

**Wrong preview variant.** A person tile is a 152 × 152 px square into which a face is
cropped from the original photo, but the crop source is the largest preview variant.
Measured on the first screen of `/people`:

```
60 downloaded previews:  28x fit_1920,  21x fit_1280,  11x fit_720
72 loaded images:        125.5 megapixels  ->  rendered into 72 x (152x152) = 1.7 Mpx
median download time:    2.8 s      max: 4.2 s
```

Roughly 75x more pixels than are used. The library grid does this correctly with `tile_500`;
the problem is specific to face crops. In practice the page fills in over about eight
seconds showing empty dark squares. `/people/:uid` behaves the same — three tiles out of
twenty after three seconds.

## Requirements
- Add a name filter above the grid (same behaviour as the "Osoba" filter in the library) and
  a sort switch: alphabetical / most photos.
- Choose the crop source by the **size of the face box**, not by always taking the largest
  variant: for a 152 px square at DPR 2 about 304 px of resulting crop is enough, so pick the
  smallest `fit_*` variant in which the face box still comes out at ~304 px.
- Use only `fit_*` variants as the crop source. `tile_*` is a centre-cropped square, so a
  face box would land in the wrong place in it.
- Show a `Skeleton` in tiles that have not loaded yet, so the page does not look broken while
  filling.
- Apply the same crop-source fix to the person detail page.

## Where it is
`web/src/pages/PeoplePage.tsx`, `web/src/components/people/SubjectTile.tsx` and
`FaceCrop.tsx` (variant selection), `web/src/pages/SubjectPage.tsx`.

## Out of scope
Pre-generating a dedicated face-crop thumbnail variant on the server is a sensible next step
but is **not** part of this task — no new thumbnail variants, no data changes.
