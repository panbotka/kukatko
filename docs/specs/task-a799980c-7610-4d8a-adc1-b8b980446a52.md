# Tasks: the queue tells you where you stand

The task queue (`/tasks`) is where an agent asks a human questions and hands over batches for approval. Today nothing tells the human that something waits on them: the "Úkoly" nav item is a plain link, the "Co je nového" digest counts only newly opened questions, the queue's state chips carry no counts, and the listing shows one page of 50 with no way to see more. On production 34 tasks are open and none has been answered.

## Summary endpoint

- `GET /tasks/summary` (RequireAuth): `{by_state: {question: n, working: n, review: n, done: n, rejected: n}, open: n, waiting_on_me: n, answered: n}`. One cheap query; `waiting_on_me` and `answered` are per caller.
- `waiting_on_me` semantic (the tasks store may already expose a per-task `waiting_on_me` boolean and a `waiting=1` list filter; if it does not, implement them as part of this task): the task is open, the caller is a participant, and the last activity on the task — the newer of the last state change and the newest live comment — was not by the caller. `answered` = open tasks with a live comment by somebody other than the caller after the task's `state_at`.

## Nav badge

- The "Úkoly" nav item (`web/src/components/navItems.ts`, rendered by the layout) shows a count badge when `waiting_on_me > 0`. On phones, where the item lives inside the hamburger menu, the menu toggle itself shows a dot or count so it is visible without opening the menu.
- Fetched once on mount, refreshed at most every 60 s while the app is open, and refreshed immediately after any task write from the web (comment, state change, assignment). Never fetched for an anonymous visitor. A failed fetch hides the badge silently.
- The layout's navbar width is tight around 992–1400 px; the badge must not push the bar past the container (measure, do not guess).

## What's-new

- `internal/whatsnew` currently counts `photo_tasks` opened since the reference point with `state='question'`. Replace that with the caller's `waiting_on_me` count so the digest line reads "3 úkoly čekají na tebe" / "3 tasks wait on you", linking to `/tasks?waiting=1`. Keep the JSON field name `tasks`.

## Queue page

- Chips on `/tasks` show counts from the summary: "Čeká na odpověď (22)", "Ke schválení (9)", …, "S odpovědí (n)", "Na mně (n)". Zero counts are shown as plain labels without a number.
- Paging: the page requests `limit=50` explicitly and shows a "Načíst další" button when `total > offset + shown`, appending rows; the offset is not persisted in the URL (a reload starts from the top). The summary line "34 úkolů" appears above the list.
