# Fourteen equal icons are not a toolbar, they are a puzzle

The photo viewer presents all of its controls as peers. Counted on the live instance: fourteen
icon-only controls sit in one desktop row — five rating stars, three review flags (look later,
pick, reject), favourite, archive, hide, faces, edits and info — with nothing to say which of
them change the library and which only change the view. On a phone the same set splits in two:
three view toggles stay in the top bar and the remaining eleven drop into a two-row dock along
the bottom edge.

## Requirements

- Group the controls by what they do rather than presenting them as one undifferentiated row:
  the view toggles (faces, edits, info), the assessment set (rating and the review flags), and
  the library operations (archive, hide).
- Move the library operations behind an overflow control that shows text labels, so an
  operation that changes what is in the library is read rather than guessed from a glyph.
- The most frequent actions stay reachable in one tap or click: opening the information panel,
  favouriting, and moving to the next or previous photograph.
- Every icon-only control that remains has a tooltip and an accessible name.
- The same grouping applies on a phone, so the bottom dock carries fewer controls and no
  longer needs two rows.
- Existing keyboard shortcuts keep working unchanged, and the shortcuts help stays accurate.

## Edge cases

- A viewer account without write permission, whose bar is already shorter.
- A video, where the edit and faces views do not apply.
- A photograph opened directly by URL, where the bar renders before the photo's row has
  loaded.
