# Nothing ever re-reads a video's technical metadata

Everything a video's file says about itself — duration, dimensions, frame rate, video and audio
codec, whether it has sound, its creation time, its coordinates — is read once, while the file is
being ingested. If that read fails, the failure is swallowed and the photo is stored with empty
video metadata. Nothing repairs it afterwards.

The job that exists to re-derive metadata from an original only ever re-reads still-image fields.
It never probes a video, so it cannot restore a duration, a frame rate or a codec. There is no
video-specific backfill either. A video that arrived during a broken probe, or before a probe
improvement, keeps its empty fields forever.

That matters beyond a blank line in the info panel: a video with no known duration can never get a
scrub preview, because the preview generator refuses without one. The clip is permanently
second-class and nothing in the interface explains why or offers a way out.

## Requirements

- The metadata job re-derives a video's own fields from the original when the item is a video:
  duration, dimensions, frame rate, video and audio codec, whether it has audio. It must remain
  the gap-filler it is for stills — it repairs what is missing or wrong, and it must not undo a
  value a person has edited by hand. Be explicit in the code about which fields are file-derived
  and therefore safe to overwrite, and which are curated and are not.
- Capture time and coordinates are the delicate part: a video carries its own creation time and
  may carry coordinates, but the catalogue records where a date came from and whether a person set
  it. Re-probing must not silently overwrite a corrected date or a hand-set location. Fill a gap,
  never overrule a person.
- Add a backfill that finds videos with missing technical metadata and enqueues the job for them,
  reachable the same way the other backfills are, so an operator can repair the library in one go
  rather than photo by photo.
- A video that regains its duration must become eligible for its scrub preview again — confirm the
  preview is generated on the next playback rather than staying permanently absent.
- A probe that fails must stop being invisible. At ingest the failure is currently swallowed into
  empty metadata; at minimum it must be logged with the file it happened on, so a library-wide
  problem is discoverable instead of silently producing dozens of half-catalogued clips.

## Verification

Take a video, blank its technical fields in the test database, run the job, and show the fields
restored and the values matching a direct probe of the same file. Report the before and after.

## Tests

Integration tests for the repair over the test database, including that an edited capture date
survives a re-probe, that a hand-set location survives, and that a video with complete metadata is
left untouched. Unit tests for the field-by-field decision about what may be overwritten.
