# Keep the upload-link progress bar below 100 % until every file has a server verdict

Found in the v0.30 prerelease walkthrough (staging 54a1504): on `/u/:code` the big bar reaches **100 %** while the line next to it still says "4 z 6 fotek · zbývá necelá minuta". The bar is weighted by bytes (`useUploadQueue.progress`), so once the last byte is sent it is full, but the server is still processing (pHash, thumbnails, jobs) and no file has a verdict yet. For the non-technical people this page is built for, a full bar means "done", and they close the page.

## Reproduction
- iPhone 12 emulation, anonymous, link `ARVpaKVv` on box staging. Pick 6 JPEGs of ~13 MB each.
- After ~3 s: "100 % | 4 z 6 fotek | zbývá necelá minuta" (screenshot `12-u-uploading.png` in the prerelease scratchpad).

## Requirements
- The bar and the percentage never show 100 % while a file has no terminal verdict. Reserve a tail for server processing, e.g. bytes count up to ~90 % and each verdict completes its file's share. Pick and document the weighting.
- The percentage and "X z Y fotek" tell one story: 100 % only appears together with the done screen.
- While all bytes are sent but verdicts are pending, show something like "Zpracovávám…" instead of a falling time estimate. The ETA must not say "zbývá necelá minuta" at a full bar.
- The authenticated `/upload` page uses the same `progress`, so check it and apply the change there too if it shares the problem.
- Unit tests for the weighting (pure helper), plus a Vitest case for "all bytes sent, no verdict → < 100 %".
- Update `docs/FRONTEND.md` (`useUploadQueue`, `UploadLinkPage`).
