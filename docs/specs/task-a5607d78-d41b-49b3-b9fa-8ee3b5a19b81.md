# Respect safe-area insets in the fullscreen review game and duplicate-compare views

The review game and the duplicate-compare view are fullscreen overlays mounted
outside the app shell. On phones with a notch or a home-indicator gesture bar their
top and bottom controls bleed into the safe-area, so the buttons that carry the
whole interaction are partly hidden behind the notch / home bar and are hard or
risky to tap.

## Current behavior (root cause)

- Pages: the review game (`ReviewPage`) and the duplicate-compare page
  (`DupComparePage`) are mounted OUTSIDE the `Layout` shell (see
  `web/src/App.tsx` around lines 64 and 68), so they do not inherit the shell's
  safe-area padding.
- Styles: `web/src/components/review/review.css` (`.review-game`, `.review-game__top`,
  `.review-game__actions`) uses `position: fixed; inset: 0`; and
  `web/src/components/duplicates/compare.css` (`.kk-compare`, `.kk-compare__header`,
  `.kk-compare__footer`) uses `height: 100dvh`. Neither adds any
  `env(safe-area-inset-*)` padding.
- `web/index.html` opts into `viewport-fit=cover`, so the insets are non-zero and
  the content bleeds into them. `web/src/styles/app.css` already handles this
  correctly for the navbar and the floating batch dock (`.kk-batch-dock`).
- Affected controls: the review game's bottom action row (Ano / Ne / Nevím) and its
  top close/undo header; the compare view's Keep-left / Keep-both / Keep-right footer
  and its top header.

## Requirements

- On notched / home-indicator phones, the top header rows and the bottom action
  rows of BOTH the review game and the duplicate-compare view must sit fully inside
  the safe area — no button may be hidden behind the notch or the home-indicator bar.
- Pad the overlays' top and bottom (and left/right where relevant) by the matching
  `env(safe-area-inset-*)`, mirroring what `app.css` already does for the navbar and
  the `.kk-batch-dock`. Add the inset to the existing padding rather than replacing
  it, so spacing on non-notched devices is unchanged.
- Do not change the desktop appearance or the overall fullscreen layout.

## Testing

- Reason through an iPhone-class safe-area (e.g. `env(safe-area-inset-bottom)` ≈
  34px) for both views and confirm the action rows clear it.
- Add a test only where it is meaningful (CSS insets are hard to unit-test; a
  snapshot/class assertion is acceptable).
- `make check` must pass.
