# Close the slug and username oracles

Multi-tenancy promises that a project learns nothing about another one, not even a user's name. Two endpoints answer differently for an existing vs a missing slug or username and so let anyone enumerate every project slug and every account name on the instance.

## Context (verify with rg before starting)
- `internal/auditapi/auditapi.go`: `GET /audit/mine` (instance, `RequireSignedIn`) and `GET /p/{project}/audit/mine` (`RequireAuth`) share `parseRequest` → `resolveProjectFilter` / `resolveActor`. `?project=<slug>` answers `400 project "x" does not exist` vs 200 (deactivated projects included, resolved on purpose in `cmd/kukatko/audit.go`); `?user=<name>` answers `400 … neither an account uid nor a username` vs `403 this listing only serves your own actions`.
- `internal/settingsapi/settingsapi.go`: `GET /p/{slug}/settings/public` returns `project_name` and `registration_enabled` to anyone for any active slug, with no rate limit (`internal/ratelimit` middleware exists and guards `/invite/{code}` and `/u/{code}`).
- `internal/auth/handlers_register.go`: `POST /auth/register` distinguishes "registration closed" from "wrong secret".

## Requirements
- `GET /audit/mine` (both mounts) ignores the `project` and `user` query parameters for non-maintainers: the listing is always the caller's own actions, and in the project mount always the request's project. An unknown or foreign value yields the same 200 (empty or filtered) response as a valid one — never a 400/403 that differs by existence. A maintainer keeps the full filter on the maintainer-only `GET /audit`. Tests: a viewer of project A probing `?project=<B slug>`, `?project=<nonexistent>`, `?user=<B member>`, `?user=<nonexistent>` gets identical status and body shape.
- `GET /p/{slug}/settings/public` is rate-limited per IP with the same limiter class as the invite page, and an unknown slug and a known slug with registration closed answer identically (a known slug reveals its name only when registration is open, which is the registration page's declared purpose). Document the trade-off in `docs/API.md`.
- `POST /auth/register` answers one generic error for "closed" and "wrong secret" (per-IP limited already); update the frontend message if it distinguished them.
- `docs/API.md` and `docs/SECURITY_AUDIT.md` record the change.

## Out of scope
- `/invite/{code}` and `/u/{code}` revealing the project/album name to a code holder (by design).
- The uploaded profile picture served to any signed-in account (`internal/userpic`); note it in SECURITY_AUDIT as accepted.
