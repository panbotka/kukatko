# Scalable Albums Index

The /albums page renders all albums (~440 in production) as one flat pile: no search, no sorting, no grouping, even though the API distinguishes album types. Documented as finding N7 in docs/UX_RESEARCH.md. Make the page navigable at this scale.

## Requirements

- A search input at the top of the page filters albums by title as the user types. Matching is case-insensitive and diacritics-insensitive (Czech titles like "Pouť" must match "pout").
- A sort control with at least: a recency-based default, title A–Z, and photo count — use whatever fields the albums list API already returns; do not invent new backend fields unless trivially available.
- Albums are grouped or filterable by their type (the API already distinguishes types), e.g. tabs or pill filters above the grid. With only one type present the page must look no worse than today.
- The grid is virtualized with react-virtuoso (project convention) so hundreds of album cards don't all mount at once.
- Search text, sort choice, and type filter live in URL query params ("back always works" project rule).
- An empty state when the search matches nothing, with a clear way to reset.
- Czech + English i18n for all new copy.

## Implementation notes

- Frontend-only if the API already returns everything needed; client-side filtering/sorting is acceptable at ~450 items.
- Follow repo testing conventions for virtualized grids (virtuoso must be mocked in jsdom — see existing grid tests).
