# Review game and roll-call: project check before the face read

Two paths read a face or roll-call by a client-supplied photo uid before the project predicate is applied. The write itself is scoped, but the answer leaks one bit per guess about another project's photo.

## Context (verify with rg before starting)
- `internal/review/answer.go` (~lines 133–143): `FacesByKeys(photo_uid, face_index)` is unscoped; the handler answers `resultGone` ("no such face") or `resultAssigned` ("already belongs to subject S") before the scoped `assigner.Apply` runs. A curator of A who guesses a B photo uid learns whether face N exists and whether it is assigned.
- `internal/facematch/people.go` (~44–46): `PhotoPeople` loads by bare uid; safe only because `internal/photoapi/http.go` calls `photoInProject` first.
- `internal/vectors/store.go` (`getEmbeddingSQL`) and `internal/vectors/faces.go` (three statements) are unscoped loaders relied on by `photoapi/similar.go`, `facematch/faces.go`, `mcpapi/tools_search.go`, each preceded by `GetByUIDInProject`.
- `internal/photos/store_extras.go` `FilesForJob` has no callers; `photos.GetByUID` is an unscoped loader whose only live user is `internal/userpic`.

## Requirements
- `review.Answer` resolves the photo with the project predicate (the store's `GetByUIDInProject` or an equivalent scoped face lookup) before any face is read; a foreign or missing photo gets the same `resultGone` answer. Integration test with `internal/projecttest`: a curator of A answering with a B photo uid and a real face index gets exactly the response for a nonexistent photo, and B's face stays unassigned.
- `facematch.PhotoPeople` and the `vectors` loaders take `projectUID` and scope their statements (or are renamed with the `ForJob` suffix and listed in `internal/tenancyguard/allow.txt` with the reason), so correctness no longer depends on caller ordering. Update every caller.
- `FilesForJob` is removed; `photos.GetByUID` is renamed to make its unscoped nature explicit (or `userpic` switches to a scoped read) and the tenancy guard forbids `*api` packages from calling it, the way it does for `GetForJob`.
- `docs/PACKAGES.md` and `docs/SECURITY_AUDIT.md` record the change.

## Out of scope
- Changing the review game's tiers or thresholds.
