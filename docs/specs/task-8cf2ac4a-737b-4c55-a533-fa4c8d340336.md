# Use the accent fill for the chosen option on /leaderboard and /review toggles

Found in the v0.29 prerelease walkthrough (box staging, commit 2a243a7).

Since 2a243a7, a chosen option in a ToggleButtonGroup of quiet buttons (`.btn-check:checked + .btn-outline-secondary`, `.btn-outline-secondary.active`) is filled with the orange accent and carries the base colour — /expand's Album/Label, the family relation-kind picker, /map's base-layer choice. Two toggle groups still mark their chosen option differently because they use other button variants:

- `/leaderboard` period toggle: chosen "Za celou dobu" is beige (`btn-light active` / `btn-outline-light`). Screenshot: `/tmp/claude-1000/-home-pi-projects-kukatko/e1859691-8352-48a1-a30b-9400f72ae1fe/scratchpad/sweep2-leaderboard.png`
- `/review` kind toggle: chosen "Oboje" is teal. Screenshot: `.../scratchpad/sweep2-review.png`

## Requirements
- Both groups use the same quiet-toggle convention as the rest (the variant the bridge rule targets), so the chosen option looks identical across the app; no new colour rules unless a group genuinely cannot use the shared variant.
- `aria-pressed`/checked semantics and keyboard behaviour unchanged; URL state for the chosen option (if any) unchanged.
- Colours only via palette tokens (`colourLiterals.test.ts`); update or add tests asserting the chosen option renders with the shared variant.
- Grep for any other toggle group still using a one-off variant and align it too; list them in the commit.
- Verify desktop + phone.
