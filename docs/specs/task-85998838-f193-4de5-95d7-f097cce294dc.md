# Make a user's e-mail address mandatory

Every account will receive mail — registration, approval, password reset — so
`users.email` must always hold a usable address. Today the column is `NOT NULL` but
defaults to an empty string and nothing validates what goes into it.

## Requirements

- A migration that, in this order:
  1. fills every empty address with a placeholder derived from the username, in the
     reserved `.invalid` domain (for example `<username>@kukatko.invalid`). `.invalid` can
     never be delivered to, so a placeholder can never reach a real mailbox by accident.
     Usernames that would collide must still produce distinct addresses.
  2. drops the empty-string default and adds a constraint that the column is non-empty.
- Creating and updating a user through the admin API requires a syntactically valid
  address. Validation lives next to the other user validation in `internal/auth` and is
  unit-tested with valid and invalid inputs, including an address that is only whitespace.
- The address is normalised on the way in: surrounding whitespace trimmed, domain
  lower-cased.
- Two accounts may share an address. A household mailbox is a real arrangement and
  refusing the second account would be wrong — do **not** add a unique constraint.
- The bootstrap admin created on an empty database gets a placeholder address, so a first
  start still works with no configuration.

## Implementation notes

- Prove the migration against populated rows before trusting it: create a throwaway schema
  in the test database, copy the shape of `users` into it, insert rows with and without
  addresses, run the statements, then roll back.
- Grep the whole repository for writes to `users.email` before changing the column. A
  write in another package will still compile and only fail at runtime.

## Definition of done

- Integration tests against the real test database cover: the migration filling
  placeholders on populated rows, creating a user without an address being rejected, and
  updating a user to an invalid address being rejected.
- `docs/API.md` records that the address is required.
- `make check` passes.
