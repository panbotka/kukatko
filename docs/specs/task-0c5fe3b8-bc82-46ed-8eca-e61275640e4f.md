# Justified Photo Grid

The library grid crops every photo into a square tile. Replace it with a justified layout (Flickr/Immich style): rows of photos at their natural aspect ratios, aligned to a common row height, filling the full row width. This is the single biggest step toward looking like a modern gallery.

## Requirements

- The main photo grid (library, search results — wherever the shared grid component is used) lays photos out in justified rows: natural aspect ratios, consistent target row height, full-width rows, sensible last-row handling (no absurdly stretched singletons).
- Aspect ratios come from the dimensions already stored in the catalog and present (or added) in list payloads; a photo with unknown dimensions falls back to a sane default box without breaking its row.
- If a grid density control exists by the time you implement this, its levels map to target row heights; if it does not, pick one good default per breakpoint.
- Virtualization stays (react-virtuoso, virtualize by row); scrolling performance on a long library must not regress; scroll and URL state restoration keep working.
- Everything tiles show today survives: selection UI, hover states, badges (video duration, favorites…), click targets.
- Works on phone and desktop; portraits and panoramas both look natural.
- Thumbnails map to a rendition size appropriate for the rendered tile so wide tiles don't go soft.

## Implementation notes

- Implement the row layout as a pure, unit-tested function (aspect ratios + container width + target height → rows) rather than pulling a heavy dependency.
- Known repo gotcha: jsdom mounts no virtuoso items — mock it and route through the real List as existing grid tests do; verify visually via a throwaway vite probe if needed.
