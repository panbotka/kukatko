# Invitation links — backend

## Context

Kukátko is multi-tenant; a project admin adds people without seeing other tenants' accounts. Besides exact-match add, the main way is an **invitation link**: a code with a role and an expiry that a signed-in person opens to join, or an anonymous person opens to register straight into the project. Model it on `internal/uploadlink` (short code looked up by hash, code kept readable for its manager, revoke, expiry, per-IP limits via `internal/ratelimit`) — read that package first and reuse its patterns. Registration today (`internal/auth/register.go`) has two gates: the project's registration secret and a live upload-link code (`RegisterWithLink`). Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 4.1, 4.2. Step 26 of 40. The pages are the next step.

## Requirements

- Migration: `project_invites` — `uid` (`iv…`), `project_uid` FK cascade, `code_hash` UNIQUE, readable `code` (same handling as upload links), `role` CHECK viewer/curator/editor/admin, `expires_at` NOT NULL, `max_uses` INT NULL, `uses` INT NOT NULL DEFAULT 0, `revoked_at` NULL, `created_by` FK users, `created_at`. Catalogue-side in `internal/reset/tables.go` (wiped with the project).
- Package `internal/invite`: `Store` (`Create` with defaults 7 days / max 90 days, `List(projectUID)`, `Revoke`, `Resolve(code)` → typed `ErrInvalid` for unknown/expired/revoked/used-up — one error, no distinction leaks), `Accept(ctx, code, userUID)` in one transaction: adds an approved membership with the invite's role, or **raises** an existing lower role (never lowers), increments `uses`, audited (`project.invite.accept`). Create/revoke audited too.
- Package `internal/inviteapi`: under `/api/v1/p/{project}` (`RequireAdmin`): `GET /invites`, `POST /invites` `{role, days?, max_uses?}` → 201 with the full URL (`<base url>/invite/<code>`), `DELETE /invites/{uid}`. **Instance-level** public: `GET /invite/{code}` → `{project_name, role, signed_in: bool}` or 404 (same body for every invalid reason); `POST /invite/{code}/accept` (`RequireAuth` at the instance level — no project in the path) → `{slug}` to navigate to.
- Registration: `POST /auth/register` accepts `invite_code` as a third gate; the new account gets an **approved** membership with the invite's role **capped at `editor`** (an invite cannot mint an admin through registration; an admin invite accepted by an existing signed-in account may grant admin). The invite counts one use.
- Rate limits: new `ratelimit.invite` (per IP, defaults like `upload_link`): `Config`, `setDefaults`, `config.example.yaml`, config tests, `docs/OPERATIONS.md`.
- Tests: Go integration — accept adds membership; accept with a lower existing role raises it, with a higher one leaves it; accept twice is idempotent and counts one use; expired/revoked/used-up → 404 `AssertSameShape`; registration via invite yields an approved editor at most; admin of A cannot list B's invites (404 same shape); rate limit.
- Docs: `docs/API.md`, `docs/PACKAGES.md`, `docs/OPERATIONS.md`, `CLAUDE.md` package map lines, `docs/SECURITY_AUDIT.md` short note on invite abuse considerations.
