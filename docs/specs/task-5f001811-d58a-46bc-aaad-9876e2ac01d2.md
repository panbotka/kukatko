# A page the user has no right to opens the library, with no explanation

Typing `/review` as a viewer lands on `/` without a word of explanation. The same happens for
`/duplicates`, `/people/clusters`, `/outliers`, `/upload` and `/trash`. The API answers those
routes honestly with `403`; nothing of that reaches the user.

It shows worst on the Leaderboard page: its "Začněte třídit" button points at `/review`, a
viewer presses it and ends up in the library. It looks like a broken button.

A family gallery is shared and links get passed around. When somebody sends "look at these
duplicates", a read-only recipient ends up on a different page than the one they clicked and
never learns why. The natural reading is "the app is broken".

## Requirements
- On a route the current role may not enter, render a **403 page** styled like
  `NotFoundPage`: one sentence ("Na tuhle část potřebuješ roli editora — požádejte o ni
  správce.") and a link back to the library. No silent redirect.
- The URL stays on the protected route, so a reload shows the same explanation and the back
  button still works.
- Links and buttons that lead nowhere for the current role are hidden or disabled — starting
  with the "Začněte třídit" button on the Leaderboard.
- Czech and English translations for the new page.

## Where it is
Route guards in `web/src/App.tsx` / `web/src/auth`,
`web/src/pages/LeaderboardPage.tsx` (the button), `web/src/pages/NotFoundPage.tsx` (pattern
to follow).

## Out of scope
No changes to the RBAC rules themselves — the backend already answers 403 correctly. No data
changes.
