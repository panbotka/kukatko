# `kukatko ctl`: read a photo whole, write an evaluation back

Give `ctl` the one loop an AI agent needs per photo — read everything about it
(including who is on it and the image itself), evaluate, write the result back —
so the agent needs one command per step instead of three raw HTTP calls.

## Requirements

### Reading
- `ctl photos get <uid>` also reports **people**: it merges `GET /photos/{uid}/faces`
  into the detail, listing named subjects and the still-unassigned detections with
  their detection score. Today the REST detail carries no people at all and the
  caller must know to make a second request.
- `photos.ocr_text` is stored and searchable (`text:` filter) but served by no
  endpoint. Expose it **read-only** on the photo detail so the agent can read what is
  printed in a photo. State in the commit whether it is always served or behind an
  opt-in query param, and why.
- `ctl photos image <uid>` saves a rendition to a file and prints the path;
  `--size` (default `fit_720`) and `--output`. It streams — a full-size original is
  never held in memory.

### Writing
- New `ctl photos edit <uid>` covering the **whole `PATCH /photos/{uid}` surface**:
  title, description, notes, ai_note; taken_at with its estimate flag and note;
  lat/lng and accepting an estimated location as manual; the IPTC/XMP credits
  (subject, artist, copyright, license, keywords, scan).
- **Only flags the user actually passed are sent.** Resending an unchanged taken_at
  would flip its source from exif to manual, so an untouched field must not appear in
  the request body at all.
- **Clearing is distinct from not passing.** Every nullable field needs an
  unambiguous way to say "make this empty" that cannot be confused with omission.
- The CLI **does not reimplement server rules** — the automatic clearing of
  taken_at_note, the location_source validation and the length caps stay on the
  server; the CLI reports the 400 it gets back.
- Fields the API serves but refuses to edit (software, color_profile, image_codec,
  camera_serial, original_name, projection) get **no flags**.
- `--dry-run` prints the request body it would send and exits without writing. This
  runs against a live family archive; the agent must be able to show its intent first.

### `-o llm`
- A third output format beside `table` and `json`, accepted by `ParseFormat` and
  therefore available to **every** `ctl` command, not just `photos get`.
- It drops what costs tokens and teaches nothing: the raw `exif` blob, empty and
  zero-value fields, file-internal and machine-derived columns, and the long signed
  media URLs (the agent fetches the image with `photos image`).
- It keeps identity, texts, the date trio with its precision, location with its
  origin, people, albums, labels, media type and dimensions — as compact JSON.
- `--fields` narrows the output further to a named allowlist.

### Done means
- `make check` green; unit tests for the flag-to-body mapping (especially omitted vs.
  cleared) and for the `llm` renderer; an integration test for each widened payload.
- `docs/OPERATIONS.md` ctl tables updated, `docs/API.md` for the payload changes,
  `docs/PACKAGES.md` if `internal/ctl` gains a file.

## Implementation Notes

- Follow the shape already there: the Cobra command in `cmd/kukatko/ctl_*.go`, the
  client and renderer in `internal/ctl/*.go`, a `_test.go` next to each.
- The requester asked for a `--llm-output` flag; it is specified as `-o llm` because
  `ParseFormat` already owns output modes and one enum keeps every command consistent.
- **Do not touch the MCP server.** It is disabled in production and stays that way —
  this is deliberately the CLI path.
