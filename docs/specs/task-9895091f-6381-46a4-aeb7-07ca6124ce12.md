## Requirements
- Maintainer: can open and manage a deactivated project in the SPA, with a clear "project deactivated" banner; non-maintainers keep the identical 404.
- Pending member: a "Waiting for approval by the project admin" page (cs + en), only for that state; everyone else unchanged.
- Legacy entity links: add a resolver, e.g. `GET /api/v1/resolve/{kind}/{uid}` (RequireSignedIn) that returns the slug of the project holding the entity **only if the caller can enter it**, and the identical 404 otherwise (no oracle; same body for foreign/missing; rate-limited). The SPA's legacy redirect uses it for entity routes and falls back to the last project only for non-entity routes. Also rewrite stored unprefixed notification links if any are still produced (rg the producers); old rows go through the resolver.
- Unknown/foreign slug and instance pages render neutral chrome (no project banner/nav of another project). A dead invite page says "This invitation is no longer valid — ask whoever sent it for a new one" while staying identical for unknown/used/revoked/expired codes.
- Tests: Go integration for the resolver (foreign = missing), vitest for each SPA state. Verify in a browser on box staging (`<staging host>`, the staging admin account; projects v, r2-b, deactivated r2-c exist).
- Docs: API.md, FRONTEND.md, i18n both locales.
