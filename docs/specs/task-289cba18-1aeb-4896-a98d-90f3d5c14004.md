# Disabled primary buttons look like an alternative brand colour

UI/UX review finding #1 (2026-10-11). Disabled filled primary buttons currently render as a dark-orange button with full-contrast text, right next to the bright-orange enabled primary. They read as a deliberate second style, not as "unavailable".

## Where it shows
- `/faces` (Najít osobu) and `/expand` (Rozšíření sbírky): the `Hledat` button before a person/collection is picked.
- `/maintenance`: `Spustit opravu` before any checkbox is ticked.
- `/people/clusters`: `Pojmenovat skupinu` before a name is typed.
- Any other filled primary button in its disabled state (fix it globally, not per page).

## Requirements
- A disabled filled primary button keeps the primary background hue but is clearly dimmed: reduced opacity (around 0.5) on the whole button including its text, `cursor: not-allowed`, no hover/active colour change.
- The enabled primary button stays exactly as it is; only the disabled state changes.
- The same treatment applies to disabled outline/secondary buttons if they currently differ in style from the filled variant's disabled look (one rule for all disabled buttons).
- Colours come only from the palette tokens in `styles/palette.css`; no new colour literal (the colour-literal and contrast tests must stay green).
- Add or update a test that asserts the disabled button styling rule (e.g. a stylesheet/snapshot test), so it cannot silently regress.

## Scope and verification
- UI only: no change to when buttons are disabled or what they do.
