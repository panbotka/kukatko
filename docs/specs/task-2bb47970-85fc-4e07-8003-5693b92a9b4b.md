# Mail sending (internal/mailer)

Kukátko has no way to send e-mail at all. Add a mailer package so later work
(registration, account approval, password reset) has a single, tested way to send a
message.

This task only creates the package and its configuration. Nothing calls it yet — do not
wire it into any HTTP handler.

## Requirements

- New package `internal/mailer` with a small interface (one method that sends one
  message), so every caller depends on the interface and never on SMTP directly.
- An SMTP implementation using the Go standard library only. The binary is built with
  `CGO_ENABLED=0`; do not add a C-backed dependency.
- Support implicit TLS and STARTTLS, plus an unencrypted mode for a local test relay.
  Authentication is optional — a relay on localhost usually needs none.
- Messages are `text/plain; charset=utf-8`. Subject headers are RFC 2047 encoded so Czech
  diacritics survive. No HTML alternative.
- A no-op implementation used when mail is disabled, and an in-memory fake that records
  sent messages for tests. Tests must never open a socket.
- Four named Czech templates, each with its own typed data struct:
  - **registration received** — tells the person their account was created and is waiting
    for an administrator to approve it
  - **account approved** — tells the person the account is now active, with a link to
    sign in
  - **new registration pending** — tells an administrator somebody registered and is
    waiting, naming the username, display name and e-mail
  - **password reset** — gives the person a link to choose a new password and says how
    long the link stays valid
- Every template renders both subject and body from the same data struct. Rendering is a
  pure function and is unit-tested against expected text.
- Sending to an address in the reserved `.invalid` domain is refused with a typed error,
  never attempted. Placeholder addresses exist in the user table and must never generate
  outbound mail.
- A send that fails returns a typed error the caller can tell apart from a bad address.

## Configuration

Add a `mail` section to `internal/config`:

- `mail.enabled` — default false; when false the no-op sender is used
- `mail.host`, `mail.port` — port default 587
- `mail.username`, `mail.password` — both optional
- `mail.encryption` — one of `starttls` (default), `tls`, `none`
- `mail.from_address`, `mail.from_name` — the visible sender
- `mail.base_url` — the public URL of this instance, used to build links inside mails
- `mail.timeout` — default 15s

`config.Load` must reject an enabled mailer with an empty host, empty from-address or
empty base URL, with an error that names the missing key.

## Definition of done

- The new keys are in the `Config` struct, `setDefaults`, `config.example.yaml`, the
  config tests and `docs/OPERATIONS.md`.
- `docs/PACKAGES.md` describes the package and the package map in `CLAUDE.md` gains one
  line.
- `make check` passes.
