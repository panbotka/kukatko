# Task page: send a comment and hand the task to the agent in one tap

On `/tasks/:uid` (`TaskDetailPage`), moving a task to another state is clumsy: you scroll to the bottom to `TaskControls`, choose from a `<select>` of five states and click Save. In the usual flow (example: https://fotky.kotrzina.cz/tasks/tkg704vl3tdtshqe34brrqh0if) the user writes a comment for the curating agent and wants the move to go back to the agent in the same gesture. Make that one action.

## Requirements

- **The primary action next to the comment box:** for a writer, the thread's comment form (`CommentsPanel` with `taskSubject`) gets a second, primary button, **"Odeslat a předat agentovi"**, next to the plain "Odeslat". It posts the comment and moves the task to `working` (the agent's move — `question`/`review` are the human's moves, see `State.NeedsHuman` and the `waiting` filter). It is shown only when the task is not already `working` and is not closed. A viewer sees only the plain send button, as today.
- **Keyboard shortcut:** Ctrl/Cmd+Enter in the comment box does the plain send. The shortcut for "send and hand over" is left to the implementer, but both buttons must stay visible, without relying on the shortcut.
- **Atomic, or honest about failure:** the comment and the state move go through as one action. Either add an optional `state` to the task comment POST, applied in the same transaction and audited (the state part keeps the write guard: a viewer sending `state` gets 403 and nothing is written), or chain the two calls. If the second call fails, the UI must say plainly "Komentář odeslán, stav se nezměnil" and offer a retry. A comment must never be lost or posted twice. Prefer the single-transaction route.
- **Quick state buttons:** above (or instead of) the `<select>`, show a small row of one-click transitions that fit the current state, e.g. from `review`: "Vrátit agentovi" (→ `working`), "Schválit" (→ `done`); from `working`: "Potřebuji odpověď" (→ `question`). Pick the exact set yourself and document it. Closing states still require a resolution: a closing quick button opens the resolution field inline, already focused, instead of failing. The full `<select>` stays available for the rare cases.
- **Feedback:** after the action, the state badge, the thread and the participants update without a reload (the same `reloadKey` the quick answers use). An empty comment disables "send and hand over". Should a state change with no comment be wanted, it goes through the quick buttons.
- Works on a phone (≥ 48 px tap targets, the two buttons wrap cleanly at 360 px width).
- i18n for all texts (cs + en). `ctl` gets the same option if the API changes (e.g. `kukatko ctl tasks comment --state working`).

## Implementation Notes

- The task comment endpoints live in `internal/phototaskapi`, and comments in `internal/comments`. Any API change → `docs/API.md`. If participants are affected, acting on a task already puts you on it, so keep that behaviour.
- Tests: Go integration for the combined write (success, viewer + state → 403 with nothing written, invalid state → 400 with nothing written). Vitest for the buttons' visibility per role/state, and for the partial-failure message if the calls are chained.
- Update `docs/FRONTEND.md` (the `TaskDetailPage`/`TaskControls` paragraphs).
