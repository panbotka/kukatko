# Frontend: three minor state-correctness bugs

Low-severity but real correctness bugs.

## Issues (verified)

1. **SubjectEditModal never resets — cancelled edits and a stale error reappear on
   reopen.** `web/src/components/people/SubjectEditModal.tsx:34-40`, rendered without a
   `key` at `web/src/pages/SubjectPage.tsx:255-267`. Open edit, type "Foo", Cancel
   (`onHide` just sets `editing=false`); the instance stays mounted so
   `useState(subject.name)` keeps "Foo" and reopening shows the discarded value; a prior
   failed save leaves `error=true`, so the red error shows immediately on reopen.
   - Fix: key the modal by `subject.uid`+`show`, or reinitialize the fields (incl.
     `error`) whenever `show` transitions to true.

2. **FacesPage.rejectFocused records "not this person" on an already-confirmed card.**
   `web/src/pages/FacesPage.tsx:217-225` (`rejectFocused`) vs `confirmFocused` (202-215).
   Under "Vše"/"Hotovo" a `done` card (already assigned to the subject) stays visible;
   focusing it and pressing `n` calls `review.reject` — unlike `confirmFocused`, it skips
   the `isActionable(item)` check — persisting a `rejectFace` for a face just assigned TO
   that person (a contradictory assigned+rejected state), reachable only via keyboard.
   - Fix: add `if (!isActionable(item)) return` to `rejectFocused`.

3. **Library keyboard `f` favorite uses a stale baseline that ignores a tile's own
   heart-click.** `web/src/pages/LibraryPage.tsx:153-167` (`toggleFavorite`,
   `favOverrides`) vs the tile's `useFavorite` in
   `web/src/components/library/FavoriteButton.tsx:83`. Two independent optimistic
   favorite states exist per tile; a heart-click updates neither `favOverrides` nor
   `displayPhotos.is_favorite`, so pressing `f` afterward reads the stale server value
   and re-favorites (no-op) instead of toggling off.
   - Fix: lift favorite state to one owner (feed the override map into the tile, or read
     the tile's state) so both input paths share a baseline.

## Requirements
- Fix all three; no regression to the normal flows.

## Testing
- Component tests: reopening the subject modal shows the current subject + no stale
  error; `n` on a done face is a no-op; keyboard `f` after a heart-click toggles
  correctly. `make check` must pass.
