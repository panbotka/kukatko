# Jobs publish under the current prefix; repair stays out of a running move

Background jobs snapshot `photos.file_path` when they start and publish derived objects under that prefix minutes later. If the storage move commits the photo in between, the row resolves under the new prefix while the fresh objects sit at the root: an HLS rendition row pointing at nothing, post-edit tiles orphaned while pre-edit tiles were moved. Separately, `maintenance repair --delete-orphan-segments` deletes root HLS segments of a video whose row is already committed but whose derived copy has not happened yet.

## Context (verify with rg before starting)
- `internal/hlsjob/hlsjob.go` (~231–253) loads the photo once; `encode.go` (~67–83) publishes under `storekeys.PrefixOf(photo.FilePath)` and saves the rendition row.
- `internal/thumbjob/thumbjob.go` (~240–274) → `internal/thumb` (~441) same shape; `internal/sidecarjob` (~222–234) same shape (heals at Finish).
- `internal/rekey/photos.go` (~180–195) reads renditions at batch time; `internal/rekey/step.go` `moveDerived` reports "no work" on `ErrNotExist`.
- `internal/maintenance/streaming.go` (~156–166, ~442–500) builds the live set from `PrefixOf(rec.FilePath)`; `EncodingHashes` already protects in-flight encodes.
- `storage_rekey_runs` holds the run state (`running`/`paused`).

## Requirements
- `hlsjob`, `thumbjob` and `sidecarjob` re-read the photo's `file_path` immediately before publishing/saving; if the prefix changed since the job started, they publish under the current prefix (re-deriving keys) or `Defer` the job and re-run — pick one per job, never write under the stale prefix. Unit tests with a fake store that changes `file_path` mid-job.
- The rekey's pending batch skips photos with a queued or running `thumbnail`, `hls_transcode` or `sidecar` job (or the job handlers skip photos the move is currently stepping) — one of the two directions, documented in `docs/PACKAGES.md` (rekey).
- `maintenance repair --delete-orphan-segments` (and any other repair that deletes under a prefix) refuses with a clear message while a `storage_rekey` run of that project is `running` or `paused`. Integration test.
- `docs/OPERATIONS.md` storage-rekey runbook notes the refusal.

## Out of scope
- Moving thumbnails from the local cache (staging) — production keeps them in the bucket.
