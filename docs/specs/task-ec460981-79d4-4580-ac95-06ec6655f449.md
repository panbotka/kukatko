# Right-Sized Thumbnails and Aggressive Media Caching

Cut the real bytes the app transfers: every image in the UI should be the smallest rendition that covers its rendered size, and immutable media should be cached hard by the browser.

## Requirements

- Audit where the frontend requests renditions (grid tiles, avatars, album covers, lightbox) and make each pick the smallest sufficient size for the rendered box and devicePixelRatio (srcset/sizes or explicit selection — your choice). A phone must not download desktop-sized thumbnails; retina screens still get sharp tiles.
- Media responses served by the app's own routes get long-lived caching: content-addressed or version-stamped URLs may use `Cache-Control: public, max-age=31536000, immutable`; anything not content-addressed gets a safe shorter policy. Never apply this to authenticated API JSON.
- The signed-URL path (R2/Worker) must keep working: do not break the pinned media URL signature contract, and keep cache lifetimes consistent with signature validity.
- Record evidence in docs/PERF.md: bytes transferred for a representative library page before vs after (a rough measurement is fine).

## Implementation notes

- Renditions and URL stamping live in internal/mediaurl + internal/thumb; the frontend mapping in the shared grid/thumb components. Read docs/PERF.md first — it already tracks this area.
- Update docs/FRONTEND.md / docs/API.md if any contract changes shape.
