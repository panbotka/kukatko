# Resume an interrupted sorting run

The review game (Třídění, `/review`) keeps its whole run in memory: the queue of questions, the
position in the round, the session tallies and the combo. Leaving the page — even to a photo's own
detail page and straight back — throws all of it away and the player starts over. Make a run
survive that round trip.

## Requirements

- While a run is in progress the game keeps a snapshot of it, so returning to `/review` in the same
  browser session resumes that run: the same card on screen, the same round position and size, the
  same session tallies (Ano / Ne / Nevím), the same combo, and the round's "daily" flag.
- The snapshot is scoped to the signed-in user and lives in `sessionStorage`: it must never be
  handed to a different account and must not outlive the browser session.
- Answers already accepted by the server are never re-sent on resume. An answer that failed to save
  is either still retryable after the resume or dropped cleanly — it must never be counted twice,
  and the leaderboard and the daily streak must not move again on resume.
- The snapshot is ignored (and the game starts a fresh round exactly as it does today) when it
  cannot be read, belongs to another user, was taken for a different "Na co se ptát" source, or has
  a shape the current code does not recognise. A stored snapshot is untrusted input: validate it,
  never crash on it.
- A finished round (the summary card) and an ended session (the "Díky za třídění!" card) leave no
  snapshot behind — opening `/review` again starts a new round.
- Explicitly ending the game ("Ukončit hru" / "Ukončit třídění") also clears the snapshot.
- Tests: unit tests for the snapshot's write / read / reject paths (including a foreign user and a
  malformed payload), plus a component test proving that a remount restores the card on screen, the
  round progress and the session tallies.

## Implementation notes

- The run's state lives in `web/src/hooks/useReviewGame.ts`; the page is
  `web/src/pages/ReviewPage.tsx`.
- Keep the snapshot small: the question payloads as they arrive from `GET /review/queue` plus the
  counters. Do not persist animation, drag or DOM state, and do not persist image data.
- Frontend only — no API and no backend change.
