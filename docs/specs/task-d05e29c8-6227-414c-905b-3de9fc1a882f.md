# Heavy-vector rate limit reads as a broken page

The five whole-project scan routes (`GET /duplicates`, `GET /review/queue`, `GET /faces/sweep`, `POST /subjects/{uid}/candidates`, `GET /albums|labels/{uid}/similar`) share one per-user token bucket (`ratelimit.heavy_vector`, default 0.1/s, burst 10) and one per-project bucket. When the bucket is empty the server answers `429` with `Retry-After: 1` and `{"error":"rate limit exceeded"}`. That is intended; the pages do not handle it.

## Reproduced (pre-release walk on the box staging stack, 2026-10-16)
- Signed in as a maintainer, open `/p/<slug>/duplicates` and reload it about ten times within ~100 s (or page through with "load more"). The page then shows the generic "Načtení duplikátů se nezdařilo. Zkusit znovu" — it looks broken, and "Zkusit znovu" fails again for the next ~10 s.
- The bucket is per user across projects: after the burst in one project, the same user's `/duplicates` in another project also answers 429 (by design — keep that).

## Requirements
- On every page that calls one of those five routes (DuplicatesPage incl. "load more", DupComparePage, the review game queue, the recognition sweep, the "find a person" candidates, the expand page), a `429` is told apart from other errors: show a calm, specific message in cs + en ("Moc požadavků najednou — zkusím to znovu za chvíli" or similar) and retry automatically after `Retry-After` (with a small cap and backoff so it never hammers the server), instead of the generic failure state.
- A 429 during "load more" keeps the groups already shown and retries the page; it never clears the list.
- Other errors (5xx, 503 sidecar unavailable) keep their current messages.
- Decide from the code whether 0.1/s with burst 10 is a sane default for a curator paging through duplicates 20 groups at a time; if paging a realistic library (a few hundred groups) predictably trips it, propose and implement a better default (or make "load more" pages of the same scan cheaper/exempt) and document the reasoning in `docs/OPERATIONS.md` next to the `heavy_vector` keys. Do not remove the limiter.
- Vitest coverage: each affected page shows the rate-limit message on a mocked 429 and recovers on the retry; "load more" keeps the list.
- Update `docs/FRONTEND.md` for the changed pages/hooks.
