# Durable mail delivery (internal/mailjob)

Sending mail straight from an HTTP handler loses the message whenever the SMTP server is
briefly unreachable, and it makes the request wait on a remote host. Kukátko already has a
persistent job queue in Postgres with retry and backoff (`internal/jobs`, with worker
handlers such as `thumbnail`, `ocr` and `sidecar`). Deliver mail through it.

The mailer package `internal/mailer` provides the sender interface, its configuration and
the message templates.

## Requirements

- New package `internal/mailjob` with a worker handler for a new job type `mail_send`.
- The job payload names the template to render and carries its data plus the recipient
  address. The payload is JSON and must survive a restart, so it may not contain anything
  that only makes sense inside the originating process.
- An `Enqueue` helper that callers use instead of touching the queue directly. When mail
  is disabled in the configuration the helper records that fact and does not enqueue — an
  instance without SMTP must not grow an ever-failing queue.
- A recipient in the reserved `.invalid` domain is never enqueued. Placeholder addresses
  exist in the user table and must never generate outbound mail.
- The handler renders the template and hands the message to the mailer. A transient
  failure returns an error so the queue's existing retry and backoff apply. An address the
  server rejects as permanently undeliverable must not be retried forever — classify it as
  a terminal failure.
- Register the new job type wherever the queue enumerates its known types, and give it a
  worker pool in the worker runtime. Wire the handler in `cmd/kukatko` next to the other
  handlers.

## Edge cases

- The queue is the only delivery path, so a mail enqueued while the SMTP host is down must
  still arrive once the host returns.
- Enqueueing must be safe to call inside the transaction of the mutation that caused it,
  the way the audit trail is written, so a rolled-back registration sends no mail.

## Definition of done

- Unit tests cover: enqueueing while mail is disabled, an `.invalid` recipient, a
  successful render-and-send against a fake mailer, a retryable failure and a terminal
  failure.
- `docs/PACKAGES.md` describes the package and the package map in `CLAUDE.md` gains one
  line.
- `docs/OPERATIONS.md` mentions the new job type where job types are listed.
- `make check` passes.
