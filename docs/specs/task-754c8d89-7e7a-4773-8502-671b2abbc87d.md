# Metrics: expose the platform the app runs on — backup, disk, encode states, map provider

The Prometheus surface describes the request path, the job runtime and the catalogue's content, but nothing
about the machine underneath it. Every number below is already computed for the admin dashboard and merely
never reaches `/metrics`, so this is plumbing, not new aggregation.

Do the task "Metrics: fix the three series that mislead" first if it is still open; this one builds on the
same package but does not depend on its changes.

## Requirements

- `internal/system`'s memoised aggregations must become readable from a scrape-time collector. `Collect` is
  unusable for that (it does a live DB ping and a sidecar probe), so add one exported accessor on
  `system.Service` that hands over the already-cached dashboard data without any per-request work, and build
  every collector below on it.
- Backup outcome. `backup.Service.Status()` is a cheap in-memory read that already carries `Running`,
  `LastStartedAt`, `LastFinishedAt`, `LastError` and `LastResult`. Export whether a run is in progress,
  whether the last one succeeded, when the last run and the last *successful* run finished, and how many
  originals it uploaded versus skipped. "Did last night's backup run and did it succeed?" must be answerable
  from `/metrics` alone; it is the most important thing this instance currently cannot be alerted on. The
  service is already in scope in `cmd/kukatko/serve.go`.
- Disk. `system.StorageUsage` (originals bytes, cache bytes, free and total bytes of the filesystem holding
  the originals) is memoised for 30 s and shown on the dashboard. Export it, so "will the box run out of
  disk?" becomes an alert instead of a surprise.
- Streaming encode states. The dashboard's video aggregation knows `Streamable`, `EncodeQueued`,
  `EncodeRunning`, `EncodeFailed`, `NotScheduled` and the oldest queued timestamp; only `Missing` is exported
  today (as `library_videos_without_streaming`). Export the rest as one gauge family with a bounded state
  label plus the oldest-queued timestamp. `NotScheduled` matters most: it is the state whose own doc comment
  says it stalls silently, because no queue row anywhere records that a video was never offered for encoding.
- Map provider health. `mapy.Health.Snapshot()` is an in-memory read and the shared `*mapy.Health` is already
  threaded through `serve.go`. Export whether the provider is up and when it was last checked, so a rejected
  API key stops being "the map is grey".
- The backlogs that ride along. The same cached snapshot already holds the curation backlog (unassigned
  faces, clusters, photos without a date, without GPS, without OCR, duplicate markers) and the library's size
  in bytes (live, trash, derived). Export them from that one snapshot as bounded gauge families; they cost
  nothing extra once the accessor exists.
- A failed read of any source must drop only its own families for that scrape, never fail the whole response
  — the library collector's existing behaviour.
- `/metrics` stays unauthenticated: instance-wide aggregates only, no per-user label, nothing naming a photo,
  album, label or person, and no bucket, path or key name as a label value.
- No collector may run unmemoised SQL at scrape time.

## Out of scope

Job queue latency, storage-backend I/O (FS/R2), ingest outcomes and the external-binary shell-outs are a
separate task; do not start them here.

## Implementation notes

- `geocodeBudgetCollector` in `internal/metrics/collectors.go` is the shape to copy for anything read from
  memory; `libraryCollector` is the shape for anything memoised behind a TTL.
- Reuse the library collector's memoisation rather than adding a second cache layer where the source already
  has one.
- Tests: the package's collectors are tested by gathering from a registry built over a fake source; follow it.
- Document every new family in `docs/OPERATIONS.md` under "Prometheus metrics".
- The Grafana dashboard lives in the `rpi` repo and is out of scope; note in the commit which panels these
  new series would deserve.
