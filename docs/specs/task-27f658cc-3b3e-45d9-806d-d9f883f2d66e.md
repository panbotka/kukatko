# Evaluate: push subscription endpoint allows blind SSRF to internal hosts

A source-only security audit (2026-10-06, commit 3792f7c) produced this **unconfirmed lead**. Reproduce it with a unit test, then fix it if confirmed.

## The lead
- When `push.enabled` is true, any signed-in user, viewer included, can POST /api/v1/push/subscriptions (`internal/notificationapi/push.go:165`). The endpoint is any https URL.
- `push.ValidateSubscription` (`internal/push/keys.go:132-139`) checks only length ≤ 2048, scheme == https and a non-empty host. It does no host or IP policy and no DNS resolution, so `https://127.0.0.1:…`, private ranges and 169.254.169.254 are stored.
- Production builds the sender without an HTTPClient (`cmd/kukatko/push.go:76`). `NewVAPID` therefore uses `&http.Client{Timeout: 30s}` (`internal/push/vapid.go:94-97`), which has no CheckRedirect and no restricted dialer.
- webpush-go POSTs through that client, so redirects are followed across hosts and down to plain http. A 301/302/303 becomes a GET; a 307/308 replays the POST.
- The response body is not returned to the user, but the user sees two status signals in GET /push/subscriptions:
  - a 2xx stamps `last_used_at` (`internal/push/store.go:270`, exposed at `notificationapi/push.go:54`)
  - a 404 or 410 removes the subscription (`internal/pushjob/pushjob.go:196`)
- Delivery is triggered by another account tagging the user's linked subject (`internal/tagnotifyjob/service.go:190`) or by the registration-pending notice to approvers.

## Requirements
1. **Reproduce** with a unit test in `internal/push`.
   - Start a TLS `httptest` server A that answers 302 → `http://127.0.0.1:<B>/probe`, where B is a plain recording server.
   - Call `Send` with a valid generated subscription whose endpoint is A, using a client that trusts A's certificate but keeps the default redirect policy.
   - Expect B to record the request.
   - Also assert that `ValidateSubscription` accepts loopback, private and link-local endpoints.
2. **If confirmed, fix:**
   - The sender must not follow redirects. Treat a 3xx as a failed delivery.
   - The sender must refuse loopback, private, link-local, unspecified and multicast destinations at dial time, after DNS resolution (a dialer Control hook), so DNS rebinding is covered too.
   - Optionally also validate at subscribe time. Consider an allowlist of known push-service hosts (FCM, Mozilla autopush, Windows notify, Apple web push), with a config override if one is added. Any new config key follows CLAUDE.md's configuration rules.
   - Tests must still be able to inject a client for httptest servers. Keep the injection seam while making the production default safe.
   - Regression tests: no redirect is followed, loopback is refused, and a normal endpoint still works.
3. **Hardening, while in this code:**
   - The endpoint's response body (up to 512 bytes, `vapid.go:194`) ends up in the job error shown to maintainers. Make sure it is truncated and rendered as plain text.
   - Re-subscribing an endpoint owned by another account moves ownership to the caller (`store.go:111-112`). Decide whether to refuse that and document the decision.
4. Record the outcome as a new SEC entry in `docs/SECURITY_AUDIT.md`.
