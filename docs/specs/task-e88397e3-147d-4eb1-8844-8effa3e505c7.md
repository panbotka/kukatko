# A project admin manages the members of their project — page

## Context

Kukátko is multi-tenant. Backend under `/api/v1/p/{slug}`: `GET /members`, `PATCH /members/{user_uid}` `{role}`, `POST /members/{user_uid}/approve`, `DELETE /members/{user_uid}`, `POST /members` `{identifier, role}` (always 202, no enumeration); errors `self`, `last_admin`. The old instance-wide approve/role endpoints are gone; the `/users` page still points at them. Frontend: `apiPath()`, `useProjectPath()`, `useAuth().isAdmin` (project role), Czech default + English, `Icon` only, palette tokens only. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 4.1; read `docs/FRONTEND.md`. Step 25 of 40.

## Requirements

- Replace the `/users` page by `/p/:slug/members` (project admin only; update `navItems.ts`, `navItems.test`, the drawer test, and every link to `/users`): a table — avatar, display name, username, role as a select (viewer/curator/editor/admin; disabled on the caller's own row with a tooltip), approval state (badge "Čeká na schválení" + button "Schválit"), last login, remove button with confirm ("Uživatel ztratí přístup k projektu; jeho účet zůstane").
- Error mapping: `last_admin` → toast "Projekt musí mít alespoň jednoho administrátora"; `self` → toast.
- "Přidat člena" modal: one text input labelled "Uživatelské jméno nebo e-mail (přesně)", a role select, submit → always the neutral confirmation "Pokud takový účet existuje, byl přidán." (never "not found"), then refresh the list.
- Pending-approval count badge on the navigation entry, as the old `/users` entry had (check `navItems` for the existing badge mechanism; if there was none, skip the badge).
- Service module `web/src/services/members.ts` via `apiPath`.
- Tests (Vitest): table renders roles and pending state; own-row select disabled; add modal shows the neutral text for any response; error toasts; nav/drawer tests updated.
- Docs: `docs/FRONTEND.md`, `README.md` ("Správce projektu" paragraph), `docs/UX_AUDIT.md` entry.

## Out of scope

Invitations UI (next steps), backend changes.
