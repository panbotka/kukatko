# Fix the cluster-card "remove face" button touch target on mobile

On a touch device the red "remove face" (✕) button on each face cluster sample
renders as a tall narrow sliver covering the face the user is meant to judge, and
it is still hard to hit accurately.

## Current behavior (root cause)

- Where: `web/src/components/people/ClusterCard.tsx` (around lines 74-86) — a red ✕
  remove button overlaid on the corner of each 48px sample `FaceThumb`.
- The button carries inline `width: 18px; height: 18px`, but the global
  `@media (pointer: coarse) .btn { min-height: 2.75rem }` rule in
  `web/src/styles/app.css` overrides the height up to ~44px while nothing constrains
  the width. The result on a phone is an ~18px-wide, ~44px-tall red bar running down
  most of the 48px face — it obscures the face and is still only 18px wide, so this
  destructive "detach this face" action is both ugly and easy to mis-tap.

## Requirements

- On coarse-pointer devices the remove control must be a proper, comfortable touch
  target (~44px in BOTH dimensions) that does NOT cover the sample face it belongs
  to. Either give it a real ~44px square hit area positioned so it doesn't obscure
  the thumbnail, or relocate the control out of the thumbnail corner (e.g. to a small
  action row beneath the sample) on narrow/touch screens.
- On fine-pointer (desktop) devices keep the current compact corner ✕ appearance.
- The action stays destructive-styled and clearly a "remove this face from the
  cluster" control; do not change its behavior.

## Testing

- Add/update a Vitest test asserting the remove control renders with an adequate
  touch target (or the relocated layout) under a coarse-pointer condition.
- `make check` must pass.
