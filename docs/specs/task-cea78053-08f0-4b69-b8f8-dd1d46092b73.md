# Duplicates, stacks, bulk and trash are scoped by project

## Context

Kukátko is multi-tenant: `photos.project_id`, denormalised `embeddings.project_id`; `internal/photos` and `internal/organize` are scoped (convention in `docs/PACKAGES.md`: `projectUID` after `ctx`, never defaulted; foreign = 404 same shape); `auth.ProjectUIDFromContext(ctx)`; `internal/projecttest`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4, 2.6, 6. Step 19 of 40.

## Requirements

- `internal/duplicates` (pHash banded LSH + embedding HNSW, union-find) + `duplicatesapi`: groups are built **within** one project — the pHash candidate join and the kNN both filter by project; `internal/dupmerge` verifies every member of the group shares the project before touching anything; `internal/dupmarkers` + `dupmarkersapi` per project.
- `internal/stacks`: detection rules and manual stack/unstack/set-primary operate within a project; a stack can never contain photos of two projects (assert in the store).
- `internal/bulk` + `bulkapi`: the batch must consist of the project's photos — verify with one query (`count(*) … WHERE uid = ANY($1) AND project_id = $2` equals `len(batch)`); otherwise the whole batch is rejected with 404 (body identical to "not found", no hint which uid was foreign).
- `internal/trash`: listing, restore, purge and the scheduled retention per project; the retention sweep iterates active projects; purge deletes the original/thumbnails/HLS under the photo's own `file_path` (the prefix work is a later step — here just make sure keys are derived from the row, not recomputed).
- Isolation tests: duplicates — seed identical pHashes and identical embeddings in A and B, assert the groups of A never contain B's photos; dup merge with a mixed group → refused; stacks; bulk with one foreign uid → 404 and no change; trash listing and purge of a foreign uid → 404.
- Docs: `docs/PACKAGES.md`, `docs/API.md`.

## Out of scope

The system dashboard, places, import, processing (next step), the storage prefix.
