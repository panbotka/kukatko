# Development on the Pi has no object store of its own — give it a local MinIO

## Current state (updated 2026-08-02, read this first)

Until 2026-08-02 the Pi's `.secrets/db.env` held `KUKATKO_STORAGE_BACKEND=r2` against
`KUKATKO_STORAGE_R2_BUCKET=kotrzina-photos` **with production credentials** — the
live library of https://kukatko.kotrzina.cz, in production since 2026-08-01. Any
storage-touching command on this box wrote into the real library, and
`kukatko maintenance reset` would have deleted its `thumb/`, `sidecars/` and `YYYY/`
prefixes outright.

**A stop-gap is already in place.** The operator switched dev to the local-disk
backend and *removed* the R2 credentials rather than repointing them, because an
absent key cannot be reached by accident while a wrong bucket name can:

```
KUKATKO_STORAGE_BACKEND=fs
KUKATKO_STORAGE_ORIGINALS_PATH=/home/pi/projects/kukatko/.devdata/originals
KUKATKO_STORAGE_CACHE_PATH=/home/pi/projects/kukatko/.devdata/cache
KUKATKO_STORAGE_TEMP_PATH=/home/pi/projects/kukatko/.devdata/tmp
```

Verified: `kukatko migrate` loads this config and exits 0; `.devdata/` is gitignored.
The production credentials live in 1Password and in the production container's
environment. **Do not restore them to this box.**

So the danger is contained. What remains is that development no longer exercises the
S3 code path at all — and that is where the last two production defects were found.

## What to build

1. **A durable local MinIO on the Pi.** `--restart unless-stopped`, a *named* volume
   so its contents survive recreation, credentials that are not the production ones.
   `docs/DEVELOPMENT.md:222-263` already documents MinIO on `127.0.0.1:18100` for the
   integration tests — fold into that, do not add a competing section.
   A container `kukatko-minio-test` exists but **exited two weeks ago** and was
   created ad hoc (`--restart=no`, port 19100, anonymous volume). Replace it.
   **Do not use MinIO's default ports 9000/9001** — 9000–9999 is the reserved
   monitoring range on this box.

2. **Point the dev runtime at it:** `storage.backend=r2` against the local endpoint
   and its own bucket (e.g. `kukatko-dev`), replacing the `fs` stop-gap above.

   Leave `storage.r2.media_base_url` **unset** for dev. `newSignerFor` then leaves
   `signer` nil, `URL()` returns the empty string and `internal/mediaurl` falls back
   to the application's own `/api/v1/photos/…` routes, which stream the bytes
   (`r2.go:108-110`, `mediaurl` package doc). No edge Worker has to be reproduced
   locally, at the cost of not exercising the signed-URL path — an accepted gap; say
   so in the docs rather than leaving the next reader to wonder.

3. **Make the same MinIO serve the integration tests**, so `make test-integration`
   stops skipping the R2 suite on the Pi. The suite needs two buckets, derived by
   suffix from `KUKATKO_TEST_S3_BUCKET` (`docs/DEVELOPMENT.md:244`).

4. **Add a guard against pointing dev at production again.** `internal/reset` already
   verifies the database name before it truncates; give it the same treatment for the
   bucket — refuse unless the configured bucket matches what the operator typed.
   Design it so the check cannot be satisfied by accident; if you find a better shape,
   take it, but state the trade-off.

5. **A make target** to bring the local stack up (`make dev-storage` or similar), so
   this is one command and not a paragraph of docker flags in a document.

## What is already fine — do not rebuild it

**The database is already isolated.** Dev uses `kukatko` on the Pi's
`shared-postgres`; production uses `kukatko` on the VPS's `pgvector`. Different
hosts, no shared state. Leave it alone.

## Constraints

- **The Pi has 16 GB of RAM shared with every other stack and every Claude session.**
  MinIO must be modest and must not bring a fleet of new containers with it.
- **Ports:** 5080, 5100–5999, 9000–9999, 12345 and 18789 are reserved. Stay out.
- **Do not touch production** — not its bucket, not its database, not the VPS. This
  task changes the developer's box and the repo.
- Verify for real: prove with a listing that a dev upload lands in the dev bucket.
  Do not assert it from config. You have no production credentials and must not
  obtain any, so verify the dev side only.
- `make check` **and** `make test-integration` must pass.
- **Do not run `make dev`** — it binds the port of the developer's own instance.
