# MCP: čitelné selhání místo HTML místo metadat

Malý předstupeň k tomu, aby šlo Kukátko přidat jako remote MCP konektor v UI Clauda/ChatGPT.
Tohle samo o sobě OAuth nepřináší (to je samostatný task), ale odstraňuje stav, kdy klient
dostane *úspěch* tam, kde má dostat „tady OAuth není".

## Zjištěný stav (změřeno 2026-09-12)

Throwaway instance (`KUKATKO_MCP_ENABLED=true`, testovací DB, `go-sdk v1.6.1`, negociováno
`2025-06-18`):

```
POST /api/v1/mcp   bez auth  ->  401, application/json, {"error":"authentication required"}
                                 ŽÁDNÁ hlavička WWW-Authenticate
GET /.well-known/oauth-protected-resource             -> 200 text/html   (SPA fallback)
GET /.well-known/oauth-protected-resource/api/v1/mcp  -> 200 text/html   (SPA fallback)
GET /.well-known/oauth-authorization-server           -> 200 text/html   (SPA fallback)
GET /.well-known/openid-configuration                 -> 200 text/html   (SPA fallback)
GET /register                                         -> 200 text/html   (SPA fallback)
```

Příčina: `router.NotFound(web.Handler())` v `internal/server/server.go` (SPA catch-all) chytá
úplně všechno, co není namountovaná route.

Proč to vadí: Anthropic dokumentuje, že když na 401 chybí `WWW-Authenticate` s
`resource_metadata`, Claude zkusí odhadnout metadata probem na
`/.well-known/oauth-protected-resource/<cesta>` a pak `/.well-known/oauth-protected-resource`.
Počítá s tím, že tam bude **404**. Kukátko vrátí **200 s HTML**, takže klient dostane úspěšnou
odpověď a parsuje SPA jako JSON — selže to nesrozumitelně místo toho, aby čistě zjistil, že
server OAuth nemá. Stejná past platí pro `POST /api/v1/mcp`, když je `mcp.enabled=false`:
vrátí 200 + index.html, ne 404 (už popsáno v `docs/MCP.md`).

Zdroje: https://claude.com/docs/connectors/building/authentication ·
https://modelcontextprotocol.io/specification/draft/basic/authorization

## Požadavky

- `/.well-known/*` nesmí padat do SPA fallbacku. Neznámá cesta pod tímto prefixem vrací **404**
  (klidně prázdné tělo nebo JSON chybu), ne `index.html`.
  - **Nejdřív ověřit, jestli dnes něco pod `/.well-known/` legitimně obsluhujeme** (ACME řeší
    traefik na VPS, ne aplikace — ale zkontrolovat `apple-app-site-association`,
    `change-password`, PWA manifest a podobně). Co se obsluhuje, musí fungovat dál.
- Neautentizovaná odpověď z `/api/v1` nese `WWW-Authenticate: Bearer` (schéma `Bearer`, ne
  `Basic` — `Basic` by v prohlížeči vyvolal nativní přihlašovací dialog; **ověřit, že se to
  opravdu neděje**, a že se frontend na 401 chová stejně jako dosud, tj. přesměruje na
  přihlášení).
  - Až přijde OAuth (samostatný task), do téhle hlavičky přibude
    `resource_metadata="…"` a `scope="…"`. Teď stačí holé `Bearer`.
- Když je `mcp.enabled=false`, `POST /api/v1/mcp` vrací **404**, ne 200 s SPA. Klient tak pozná
  „server tohle neumí" od „server neodpověděl".
- Doplnit metadata nástrojů — dnes je `tools/list` bez nich:
  - **per-tool `title`** u všech 19 nástrojů. Bez něj klienti renderují syrové `snake_case`
    (`add_photos_to_album`). Titulky přes i18n nejdou (MCP je server-side, jazyk neznáme) —
    anglicky, krátce.
  - **`destructiveHint: false`** u nástrojů, které nic nepřepisují: `create_album`,
    `create_label`. Podle MCP specu je default `true`, a ChatGPT developer mode bere každý
    nástroj bez `readOnlyHint` jako zápis a ptá se na potvrzení — u „založ prázdné album" je to
    zbytečné tření.
  - `create_album`, `create_label` a `bulk_edit_photos` nemají dnes **žádné** anotace; projít je
    a doplnit, co sedí (`idempotentHint` u `bulk_edit_photos` schválně **ne** — není idempotentní).
  - `openWorldHint: false` všude — knihovna je uzavřený svět, nic nesahá ven.
- Opravit `docs/MCP.md` tam, kde je dnes nepřesné:
  - tvrdí „POST only", ale route je registrovaná přes `chi.Handle` (všechny metody; GET vrací
    405 až ze SDK, DELETE se session hlavičkou dokonce 204),
  - tvrdí „no `Mcp-Session-Id`", ale SDK hlavičku na `initialize` **vrací** (ověřeno:
    `Mcp-Session-Id: YN2FLRSQHIBBJ4AYL2XBJMHS5H`) — jen ji pak nevaliduje.

## Co do tohohle tasku NEPATŘÍ

- Vlastní OAuth 2.1 / RFC 9728 / DCR — samostatný task, je to rozhodnutí, ne úklid.
- `web.allowed_origins` je dnes mrtvá konfigurace (deklarovaná, nikým nečtená) a CORS middleware
  není žádný. Nechat být: MCP klienti jsou server-side, prohlížeč se sem nedostane a session
  cookie je `SameSite=Strict; HttpOnly`, takže tady není co opravovat. Jen to nepřidávat jako
  „mimochodem".

## Testy

- Integrační: neautentizovaný `POST /api/v1/mcp` -> 401 **a** hlavička `WWW-Authenticate`
  začíná `Bearer`.
- Integrační: `GET /.well-known/oauth-protected-resource` -> 404, a odpověď **není**
  `text/html` (regrese na SPA fallback).
- Integrační: s `mcp.enabled=false` -> `POST /api/v1/mcp` vrací 404.
- Unit/integrační nad `tools/list`: každý nástroj má neprázdný `title`; žádný write nástroj
  nemá `readOnlyHint`; `create_album`/`create_label` mají `destructiveHint: false`.

## Jak to ověřit naživo

`make dev` **nepoužívat** (živá instance na Pi je tenhle repozitář). Throwaway serve na testovací
DB — recept i s pastmi (port je `KUKATKO_WEB_PORT`, storage cesty se musí přebít, `embedding.url`
nesmí být prázdný) je v paměti `kukatko-throwaway-serve-instead-of-make-dev`. Bootstrap admina
a `POST /api/v1/auth/tokens` dá bearer pod klíčem `secret`, kterým se dá prohnat `initialize`
a `tools/list`. Po sobě uklidit uživatele, jeho `api_tokens`/`sessions`/`audit_log`.

Pozor: SDK 400-uje POST, jehož `Accept` neobsahuje **obojí** `application/json`
i `text/event-stream` — při ručním curlu to posílat.
