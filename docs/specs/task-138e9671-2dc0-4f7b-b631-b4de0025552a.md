## Problem
`.kk-tile__unavailable` (PhotoTile + TrashCard) is a size container whose top/bottom insets reserve the select circle and the heart. At the library's **default density (10 per row at 1440px, tiles ≈117×88 px)** the remaining band is so short that both `.kk-tile__unavailable-icon` and `.kk-tile__unavailable-text` compute to `display: none` — the tile is an empty dark square, indistinguishable from a tile still loading. That is worse than before the fix (the text was at least there). Measured on staging by tile size: 117×88 and 125×92 → nothing; 144×108 → icon only; 164×123 and 187×141 → text only (no icon); 241×181 → icon + text.

Repro: staging library `/`, default tile size, scroll to the end — the tiles for trunc.jpg (phsosatkcb86tulvdrusdn7ak9), f.dng (phn9visnak43pnja0jhiogqitp), broken.jpg (phglhp5uv1qvsaeeiknf0pj0ov) are blank.

## Requirements
- At every tile size the stepper allows (including the default 10-per-row desktop grid and the phone grid), a tile without a preview shows **at least the image glyph**, never nothing — still clear of the select circle and heart (the glyph may sit between them, e.g. centred; it need not sit in a full-width band).
- Text keeps appearing where it fits; the icon should not disappear at sizes where text shows (the 164–187px rung currently drops it).
- `styles/tileUnavailable.test.ts` extended so a tile of ~110×80 px must render the glyph; verify in a static harness across the stepper's sizes as the original fix did.
