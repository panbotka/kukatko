# Fix horizontal overflow on organize & search pages on mobile

Several list rows, page titles, and a help modal overflow the viewport width on a
phone, forcing the whole page (or modal) to scroll sideways. Fix each so nothing
exceeds the viewport width at 320-360px. Also enlarge one tiny touch target.

## Issues to fix (each is an independent, verifiable symptom)

1. **Label & saved-search list rows overflow at 360px.**
   - Where: `web/src/pages/LabelsPage.tsx` (around lines 111-143) and
     `web/src/pages/SavedSearchesPage.tsx` (around lines 106-138).
   - Cause: each row is `d-flex justify-content-between gap-2` with the name link
     `flex-grow-1` but NO `text-truncate` / `min-width:0`, beside two always-visible
     full-text buttons ("Přejmenovat", "Smazat"). The coarse-pointer floor makes each
     button ≥44px, so the two Czech-worded buttons eat ~150px of a ~336px row and a
     long/unbroken name cannot shrink, pushing the row past the viewport → horizontal
     page scroll.
   - Fix: truncate the name (`text-truncate` + `min-width:0` on the flex item) and on
     narrow screens collapse the two actions to icon-only buttons or a single "⋯"
     overflow menu, so the row never has to fit name + two labelled buttons across a
     phone.

2. **Long/unbroken names overflow detail-page headers.**
   - Where: the `h1.kk-page-title` on `web/src/pages/AlbumDetailPage.tsx` (~line 177)
     and `web/src/pages/LabelDetailPage.tsx` (~line 102); the `.kk-page-title` class
     in `web/src/styles/tokens.css` (~line 314) sets no `overflow-wrap`.
   - Cause: `.kk-page-title` has no `overflow-wrap: anywhere` / `word-break`, and the
     flex title container has no `min-width:0`, so a name with no spaces cannot break
     and overflows the header past the viewport edge.
   - Fix: give `.kk-page-title` `overflow-wrap: anywhere` and `min-width:0` on the
     flex title container so any name wraps instead of overflowing. (This is a shared
     class — verify the change is safe on the other pages that use it.)

3. **Query-language help modal overflows horizontally.**
   - Where: `web/src/components/search/SearchQueryHelp.tsx` (around lines 39-92) — a
     `Modal` containing two `Table`s whose columns are `text-nowrap` (multi-key cells
     like `favorite: private: archived:` and an example `camera:"Canon EOS R6"`).
   - Cause: `text-nowrap` on both columns with no `overflow-x:auto` wrapper and no
     small-screen fullscreen; `Modal.Body` only scrolls vertically, so the content
     overflows the modal sideways at 320-360px.
   - Fix: make the modal `fullscreen="sm-down"` and/or wrap the tables in an
     `overflow-x:auto` container (or drop `text-nowrap` on the wide key column) so the
     help scrolls/wraps instead of blowing out the modal width.

4. **Query-help "?" trigger is a tiny touch target.**
   - Where: `web/src/components/search/SearchQueryHelp.tsx` (around lines 26-37) — the
     `variant="link" size="sm" p-0` icon-only button beside the "Dotaz" label on
     `SearchPage`.
   - Cause: icon-only `.btn` with `p-0`; the coarse-pointer floor gives it 44px
     height but its width stays ~the glyph (~18-20px), so it is an awkward, easy-to-miss
     tap target.
   - Fix: give the help trigger a ~44px square hit area on touch (padding or a
     tap-target helper) while keeping the glyph visually small.

## Requirements

- At 320px and 360px viewport width, none of issues 1-3 may cause the page or the
  modal to scroll horizontally; long/unbroken names must wrap or truncate. Issue 4:
  the "?" trigger must be a ≥44px touch target on coarse pointers.
- Preserve desktop appearance; these are narrow-screen guards.
