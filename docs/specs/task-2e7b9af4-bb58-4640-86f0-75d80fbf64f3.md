# `s` hides and unhides a photo in the detail view

Hiding a photo from the library is a finished feature — `photos.hidden_from_library`,
`POST /api/v1/photos/{uid}/hide` and `/unhide`, and an eye / eye-slash toggle button in the
photo detail. But walking a series of photos and hiding the dross still means aiming a mouse at
that button every time. Give it a key.

## Requirements

- In `web/src/pages/PhotoDetailPage.tsx`, bind **`s`** in the existing `useKeyboardShortcuts`
  map to the handler the eye button already calls (`toggleHidden`). Do not duplicate its logic,
  its optimistic state flip or its toast.
- It is a **toggle**, and the detail **stays on the photo**: pressing `s` hides it, the view does
  not navigate anywhere, the button switches to its hidden state, and pressing `s` again brings
  the photo back. That is deliberate — the second press is the undo, since the toast has no
  action button.
- The photo must visibly read as hidden while you are standing on it, so a stray press is
  obvious. If the detail does not already mark a hidden photo beyond the toggle button's own
  state, add a small badge next to the title.
- Gated on write permission exactly like the button: for a viewer the key does nothing at all.
- **Document it.** Add a `ShortcutEntry` for `s` to the `detail` group in
  `web/src/lib/shortcuts.ts` with a new `descriptionKey`, plus the cs/en strings. That registry
  is what the `?` help modal and the mobile nav drawer render, so a shortcut missing from it is
  an undiscoverable one.
- **Tests.** A component test proving `s` calls the hide endpoint and flips the button state,
  that a second press unhides, that it does nothing for a read-only user, and that it is ignored
  while a text field has focus or a modal is open — the hook already guards all three, so assert
  the behaviour rather than re-implementing the guard.

## Implementation notes

- `s` was chosen because it is free across the whole application and matches the Czech "skrýt";
  the default UI language is Czech. Do **not** reach for `h` — that is the grid's vim-style
  "move left" in `useGridKeyboardNavigation`.
- `a` is deliberately left unbound: archive sits next to hide in the same button row and is the
  obvious future claimant for it.
- The rating hotkeys in the same file go through a second, raw `document` listener
  (`lib/ratingHotkeys.ts`) which guards on modifiers and on typing but **not** on an open modal.
  Do not follow that pattern — `s` belongs in the `useKeyboardShortcuts` map, which guards all
  three cases.
- Hiding is not archiving and not deleting: a hidden photo leaves the grid, timeline, map and
  default search but stays in its albums, labels and favourites. The migration header of
  `0049_photos_hidden_from_library.sql` is the design note for that distinction.
- Definition of Done per `CLAUDE.md`: `docs/FRONTEND.md` for the shortcut, `README.md` if it
  lists shortcuts; then `make check`, then commit and push.
