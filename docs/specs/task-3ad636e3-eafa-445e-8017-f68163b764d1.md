# Upload links: anyone with the link can add photos from an event

After an event everyone has a few photos on their phone. A curator creates one short link, posts it
to the group chat, and anyone who opens it — signed in or not — uploads photos straight into the
preset album(s) and labels.

## Requirements

- **Create a link** (RequireCurator or higher; a new page under the albums/upload area plus a
  "Sdílet odkaz pro nahrávání" action on an album): pick one or more albums and one or more labels
  (existing ones, or create inline), an optional title/note shown to uploaders ("Pouť 2026 – fotky
  od vás"), validity in days (default **30**, editable). The creator gets the link and a copy button
  (Web Share where available).
- **Short URL**: `/u/<code>` with a short random code (~8 chars, unambiguous alphabet, unguessable,
  unique). The code is the only credential; store it so a leak of the DB listing cannot be replayed
  carelessly (hash or treat as secret consistently with API tokens).
- **Manage links**: list (creator's own; admin sees all) with title, targets, expiry, upload count,
  last use; extend validity, revoke. Revoked or expired → the page says so clearly, uploads refuse
  (410), nothing else about the library leaks.
- **Public upload page** (no sign-in required, works for signed-in users too): shows the title/note
  and **exactly where the photos go** — album names and label names as chips — plus the expiry date.
  It reveals nothing else (no photos of the album, no other metadata).
- **Multi-upload from a phone library**: file input with `multiple`, accepting images and videos
  (incl. HEIC and common video), so iOS "Photo Library" and Android gallery/picker allow selecting
  many at once; drag & drop on desktop. Per-file progress, retry of failed files, a clear summary
  ("12 nahráno, 1 duplicita, 1 chyba"). Large files streamed; reuse the existing upload pipeline
  (`internal/ingest`) and its SHA256 dedup — a duplicate still gets added to the link's albums/labels.
- **Visibility**: photos uploaded through a link are visible in the target albums immediately (no
  moderation queue); a curator removes unwanted ones by archiving as usual.
- **Uploader identity**: anonymous uploader may enter an optional name ("Od koho?"), remembered on
  the device; it is stored with each photo's provenance (which link, which name). Signed-in user's
  uploads are owned by them as usual.
- **Registration offer**: after an anonymous upload finishes, offer registration ("Chcete vidět
  všechny fotky? Zaregistrujte se"). A valid upload link lets the person register **without the
  shared registration secret**, but the account still waits for admin approval as today. Photos
  uploaded in that browser session before registering are attributed to the new account.
- **Abuse limits**: per-link and per-IP rate limits, configurable max file size and max uploads
  per link (config keys documented), only media types the ingest accepts. Every link create/extend/
  revoke and every upload through a link is audited.
- i18n cs (default) + en; mobile-first layout of the public page.
