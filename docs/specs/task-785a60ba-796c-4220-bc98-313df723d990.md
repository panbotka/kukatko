# Push a submitted library search onto the history so Back restores the previous view

Found in the v0.30 prerelease walkthrough (staging 88963a6). This is pre-existing, not a regression. "Back always works" is a project rule.

## Reproduction
- Open `/` in a fresh tab, type `year:2024` into the library filter box ("Filtrovat v knihovně") and press Enter. The URL becomes `/?q=year%3A2024`.
- Change the sort to "Nejstarší": the URL becomes `/?sort=oldest&q=…`. Back from there correctly returns to `/?q=year%3A2024`.
- Press Back again: the browser leaves the app (to the previous site or `about:blank`) instead of returning to the unfiltered `/`. The query change replaced the history entry rather than pushing one.

## Requirements
- A **submitted** query (Enter, a picked suggestion, a filter chip) pushes a history entry, so Back returns to the previous query or the unfiltered library. Typing that only updates the URL as you type (debounced) may keep using replace, so one keystroke ≠ one entry.
- Same behaviour on `/search` and the other scoped lists that use the shared filter box (album, label, person, task), unless one of them has a documented reason to differ.
- Vitest/RTL test driving the real router: submit a query, go back, and assert the previous URL and the rendered state.
- Update `docs/FRONTEND.md` where the URL-state rule for the filter box is described.
