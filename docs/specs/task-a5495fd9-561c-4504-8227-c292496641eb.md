# The name field on the face groups page is too narrow to use

On `/people/clusters` each card carries a text input and a "Pojmenovat skupinu" button on
one row. The button has a fixed width and the input has no minimum width, so the input
absorbs all of the shrinkage. At the page's **default** tile density the field is too
narrow to read its own placeholder or the text being typed.

## Evidence

Measured in a 1440x900 desktop window at the default density (5 cards per row):

```
rowW 217 · buttonW 168 · inputW 41 · placeholder "Nové nebo existující jméno…"
```

At the widest density (fewest cards per row) the same input measures 442 px and is fine.
So the default view of this page ships with an unusable name field on a normal desktop,
before any phone is involved.

The naming itself works correctly — typing a name and pressing the button creates the
subject and writes its markers. This is purely layout.

## Requirements

- At every tile density the page offers, and at every viewport width from a phone upward,
  the name field must stay wide enough to show its placeholder and the text being typed.
- The input, not the button, should take the free space in the row; the button may shrink,
  wrap, or move below the input on narrow cards.
- Keep the control usable on a phone, where the cards are already narrower.
- Do not solve this by shortening the placeholder text or by removing tile densities.

## Testing

Add a frontend test asserting the input keeps a usable minimum width rather than
collapsing when its container is narrow. The repository already tests CSS this way — see
the existing style tests under `web/src/styles` for the established pattern of asserting
declarations rather than screenshots.
