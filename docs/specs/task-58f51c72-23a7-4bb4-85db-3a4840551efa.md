# Library statistics overview

Expose cheap library-wide counts (photos, embeddings, faces, people, albums, labels) as an
authenticated endpoint and render them both on a new all-users page and as a section of the
maintainer System page. Modelled on photo-sorter's status page, which serves
`{"total_photos":20310,"photos_processed":20092,"photos_with_embeddings":20092,
"photos_with_faces":14567,"total_faces":112806,"total_embeddings":20092}`.

## Requirements

- Add a counts aggregation to `internal/system` (new `Counts`/`Library` struct + store method).
  It must be a set of cheap `COUNT(*)` queries, **not** a `maintenance scan` full-tree walk.
- Counts to report, all instance-wide (not per-user):
  - photos: total, of which videos, archived, and in trash
  - photos with an embedding, photos with at least one face
  - total embedding rows, total face rows
  - subjects (split by kind: person / animal / other), markers assigned vs unassigned
  - albums, labels
- Derive and report coverage gaps explicitly: `photos_without_embedding`,
  `photos_without_faces` — this is what makes the page useful during import verification.
- Memoise the aggregation for ~30s, following the existing memoisation of the `storage`
  block in `internal/system`.
- New endpoint `GET /api/v1/system/stats` guarded by **RequireAuth** (every logged-in user).
  Do not move the existing maintainer-only `GET /system/status` or loosen its guard.
- Frontend: a new page reachable from the user menu for all authenticated users, rendering
  the counts as a readable tile/table layout (thousands separators, no raw JSON). Use the
  existing service pattern in `web/src/services/system.ts`.
- Frontend: `SystemStatusPage` additionally renders the same counts as a "Library" section,
  consuming the same endpoint — no second data source, no duplicated aggregation.
- Failure behaviour: if the aggregation query fails, the endpoint returns an error and the
  pages show an inline error state; they must not render zeros as if they were real counts.
- i18n strings for cs (default) + en. Icons only via the `Icon` component.

## Tests

- Integration test against the real test DB: seed a known fixture, assert every count and
  every derived gap value.
- HTTP test: anonymous request is rejected; a viewer-role token gets `200`.
- Frontend: a Vitest test for the new page (loaded state + error state).

## Implementation Notes

- Reuse `photos.Store.Count` and the existing face count in `internal/vectors/faces.go`
  where they fit; add new queries rather than reimplementing the storage/jobs blocks, which
  already exist in `system.Status`.
- Counts should come from indexed columns; check `EXPLAIN` on the archived/trash predicates
  so the page stays fast on a ~20k-photo library.
- Docs at the end: `docs/API.md` (new endpoint), `docs/FRONTEND.md` (page + service),
  `docs/PACKAGES.md` (`internal/system` change), `README.md` (user-visible feature).
  No `CLAUDE.md` change — no package is added or removed.
