# Two misleading texts

Both verified on the box staging (commit 68e805e, 2026-09-06).

## 1. Literal backticks in the query-language help

The dialog "Vyhledávací jazyk" (opened from the "?" next to the library filter box) renders the `person:` row as "`person:me` je osoba, kterou jsi ty — …" and the `uploader:` row as "`uploader:me` jsi ty, `uploader:none` jsou importované fotky" — the backticks are printed as characters. The strings are `search.help…person` and `…uploader` in `web/src/i18n/locales/cs/common.json` (≈ lines 929–930); check the English locale for the same. Other rows of the same table render examples as real `<code>` elements. Screenshot: `/mnt/nas-botka/kukatko-stage-test/04-query-help.png`.

### Requirements

- The help rows render `person:me`, `uploader:me`, `uploader:none` as inline code like the examples in neighbouring rows, in both locales; no backtick characters anywhere in the dialog.
- Prefer a data shape that separates prose from examples over parsing Markdown in a plain-text cell; the `Markdown` component with `rehype-sanitize` is the only sanctioned Markdown renderer if you go that way.
- Vitest: a test that the rendered dialog contains no "`" character and that the code spans exist.

## 2. Registration promises an e-mail that may never be sent

After self-registration the page says "Potvrzení jsme poslali na váš e-mail." (`register.doneMail`), and a login before approval answers "… Až ho schválí, přijde vám e-mail a budete se moct přihlásit." The admin's approve dialog says "… a přijde mu o tom e-mail". On an instance where mail is off (`mail.enabled: false` in `config.example.yaml` ≈ line 553; the mailer is then the no-op sender) nothing is ever sent, and for a placeholder address (`.invalid`) `internal/mailer` refuses to queue anything at all. Staging has mail off; the promise was false.

### Requirements

- `GET /settings/public` (`internal/settingsapi/settingsapi.go`, ≈ lines 100 and 180) additionally reports `mail_enabled` (true only when the configured sender really sends). Document it in `docs/API.md`.
- The registration success text, the pending-approval login text and the admin approve/password-link dialogs use the e-mail wording only when `mail_enabled` is true; otherwise they say what actually happens ("Správce tě pustí dovnitř a dá ti vědět." / "Uživatel se bude moci přihlásit; nedostane o tom e-mail, mail není zapnutý."). Both locales.
- Tests: settingsapi test for the new field in both configurations; Vitest for both text variants on the register page and the login pending message.
- Docs: `docs/API.md`, `docs/FRONTEND.md` (register/login pages).

## Out of scope

- Do not change what the mailer sends or when.
