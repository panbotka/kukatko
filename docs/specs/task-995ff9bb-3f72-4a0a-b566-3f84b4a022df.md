# Tool pages: form controls sit on different baselines

UI/UX review finding #19 (2026-10-11). The tool pages `/faces` (Najít osobu), `/expand` (Rozšíření sbírky) and `/recognition` (Rozpoznávání) share a form pattern: a picker/slider/limit input and a submit button. On desktop `/recognition` the slider column ("Jistota") starts visibly lower than the "Na osobu" input column; on phones the "Hledat/Prohledat" button floats to the right of the "Limit" input at a different height than the input and above the input's helper text. The empty-state blocks below the forms are consistent and fine.

## Requirements
- Desktop: all controls in a form row align on the same baseline (labels top-aligned, controls bottom-aligned); the slider's label row and its value sit at the same height as the neighbouring inputs' labels.
- Phone (below `md`): controls stack full-width in order (picker, slider, limit, submit button full-width last); helper texts stay directly under their control.
- The three pages use one shared layout/pattern so they cannot drift; do not change which controls exist or what they do.
- Tests: a rendering test per page that the submit button comes after the limit input in DOM order and is full-width on narrow viewports (class assertion is enough).
