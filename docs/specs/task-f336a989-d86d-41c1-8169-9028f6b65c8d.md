# Four small findings from a pre-release walk

Each item is independent. Do all four, with tests where they apply.

## 1. A derived passkey relying party must not crash the server

With passkeys not configured (`auth.passkey.rp_id` and `origins` empty) and `mail.base_url` set to an IP URL (e.g. `http://192.0.2.10:6490`, a LAN or staging deployment), the server refuses to start and restarts in a loop: `building the passkey relying party: … field 'RPID' is not a valid domain string: the value must be a domain and not an IP address` (`cmd/kukatko/auth.go` `buildPasskeys`).

- An **explicitly configured** relying party that the library refuses may still fail startup; that is the documented, deliberate choice.
- A relying party **derived from `mail.base_url`** that is an IP address or `localhost`-like and therefore unusable must only disable passkeys. Log one WARN saying why and how to configure them; `/capabilities` and the endpoints say passkeys are not available. The server must start.
- Tests in config/cmd: IP base URL without passkey config → starts, passkeys off. Explicit invalid rp_id → still fails. Docs: `config.example.yaml` comment + `docs/OPERATIONS.md`.

## 2. /system/projects asks every project for its rekey status

Opening or refreshing the system administrator's project list fires one `GET /api/v1/projects/{uid}/rekey` per project. Every project without a storage move answers **404**, so a list of 15 projects means 15 requests and 14 red 404s in the network log.

- Either include the rekey state (none / running / paused / failed / done) in the `GET /projects` list payload and drop the per-row requests, or make "no run" a `200 {"run": null}` (or 204) instead of 404 and fetch it only where the UI shows it. Prefer the first.
- Update the API docs, the frontend service and the tests.

## 3. Comment deep link on a phone: the "N KOMENTÁŘE" heading hides under the sheet header

On a phone-width viewer (iPhone 12 emulation), opening `/p/<slug>/photos/<uid>?panel=info#comment-<uid>` scrolls the info sheet so that the comments section heading sits half under the sheet's sticky "Informace" header. The comment itself is visible.

- When scrolling the panel to a linked comment, offset by the sticky header's height (or use `scroll-margin-top` on the comment/section), so the section heading and the comment are fully visible, on desktop and phone.
- The viewer itself must keep `scrollTop` 0. That is an existing guarantee, don't regress it. Update the existing deep-link test.

## 4. Migration safety doc is missing the last file

`docs/MIGRATION_SAFETY.md` lists `0120_audit_log_project_backfill` as "not part of this rehearsal". A rehearsal of the full chain 0100–0120 on a fresh copy of a pre-tenancy library measured: **0120: ~400 ms** (an UPDATE, ROW EXCLUSIVE on audit_log, reads continue), 0102 ~233 ms, **total `kukatko migrate` ~0.88 s** on the build box. About 99.8 % of the audit rows got the bootstrap project. The remaining ~0.2 % are instance-level account actions (passkey.login, user.register, user.approve, user.create, api_token.*, password_reset*), which correctly stay NULL. Rollback 0120→0100 took ~2 s and was clean (inventory-diff 0 differences). The new server answered `/healthz` ~0.9 s after start, migrations included.

- Update the timing table, the total and the "Open at the last gate" list with these numbers (generic: no hosts, no deployment names).
- In the Method section, note that throwaway `pgvector/pgvector` containers must be removed with `docker rm -fv`: the image declares a VOLUME, and a plain `rm -f` leaves an anonymous volume holding the copy of the library behind.
