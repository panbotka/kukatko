# ppimport: import non-primary PhotoPrism files (RAW siblings)

Kukátko's PhotoPrism import copies only the primary file of each photo, so a
RAW+JPEG pair loses the RAW. The user requires not losing RAW.

## Verified facts (live)
- The PhotoPrism library (`fotky.kotrzina.cz`) has **12 `type:raw` photos** — each is
  a JPEG primary **plus a non-primary `raw` file** (confirmed via a sample's `Files[]`:
  `{type:jpg, primary:true}` + `{type:raw, primary:false}`). Also **0 live photos**
  and **6 standalone videos** (the video IS the primary → already imported fine).
- Kukátko's `internal/ppimport` uses `detail.PrimaryFile()` throughout
  (`details.go:114`, `people.go:26`, `metadata.go:34-43`) and never iterates the
  photo's other `Files`, so any non-primary file (the RAW) is dropped.

## Requirements
- When a PhotoPrism photo has more than one file, import ALL of them: download each
  non-primary file (the `raw` sibling, and any other non-primary sidecar) in addition
  to the primary, and record it as an extra `photo_files` row grouped with the primary
  via `internal/stacks` (primary = the displayable JPEG). The PhotoPrism client
  already downloads a file by its hash (`/dl/<hash>`) — reuse it per file.
- Single-file photos (the vast majority) are unchanged.
- Keep the import idempotent and incremental; re-import must not duplicate the RAW
  file (dedup on SHA256 as usual).
- Be generic: handle any non-primary file type PhotoPrism reports (raw / a video
  sidecar / an alternative encoding), not just `raw` — even though live=0 today.

## Testing
- Integration test: a PhotoPrism photo with `jpg` (primary) + `raw` imports BOTH files,

  file; a re-run adds no duplicates.
