# Rotation is the commonest edit and today it is an invisible half-feature

Turning a photo upright is the edit people reach for most, and in the edit panel it is one
button whose label cannot be read, only turns one way, is never audited, and leaves the
library grid showing the photo the wrong way up.

## Evidence (read from the code on 2026-08-12)

- `web/src/components/photo/EditPanel.tsx:123-133` — a single `outline-secondary` button
  labelled `photo.edit.rotateRight`. The user reports its text is the same colour as its
  background, so on the live instance the control is effectively invisible.
- `web/src/lib/photoEdit.ts` — only `rotateRight` exists; there is no counter-clockwise helper.
- `internal/photoapi/edit.go:58` — `handlePutEdit` writes the edit and enqueues the sidecar,
  but records **no audit entry**. It is the only write path in `internal/photoapi` that does
  not (compare `update.go:114`, `thumbnail.go:94`, `comments.go:102`).
- Nothing regenerates thumbnails after an edit: `GetEdit` is read only by the media renderer
  (`media_edit.go:49`) and the sidecar job. A rotated photo therefore stays sideways in every
  grid, in search results and in the map popovers.
- `web/src/pages/PhotoDetailPage.tsx:295-301` — because `FaceOverlay` cannot follow the
  preview transform, **any** non-identity edit switches the whole face UI off. Rotating a
  photo silently costs the user their face rectangles.

## Requirements

- The edit panel offers **two** rotation controls, counter-clockwise and clockwise, each a
  rotation-arrow icon from `bootstrap-icons` via the `Icon` component, each with an
  accessible label. They read as buttons against the Superhero dark surface — a contrast
  regression is the bug being fixed, so the styling must be verified as visible, not assumed.
- Each press turns the in-progress edit by one quarter turn in its direction and the preview
  follows immediately, as the existing button already does. Rotation stays 0/90/180/270 and
  the current angle stays readable next to the controls.
- A saved edit writes an audit entry attributed to the acting user, in the same shape as the
  other photo write paths, carrying enough detail to tell what changed (at least the
  rotation). A new action constant belongs in `internal/audit` with a doc comment.
- Saving an edit enqueues the `thumbnail` job for that photo, so the derived thumbnails are
  rebuilt from the edited rendering and the library grid shows the photo the way the user
  turned it. Saving a neutral edit must not be a special case — it too has to leave correct
  thumbnails behind.
- `FaceOverlay` maps its boxes through the edit's rotation, so the rectangles land on the
  faces on a rotated photo, and the face UI is no longer suppressed for a rotation-only edit.
  A crop still suppresses it — the boxes genuinely cannot be placed then.
- Tests: unit tests for the new rotation helper and for the overlay's rotated coordinates, a
  frontend test that both buttons are present, labelled and rotate in the right direction, and
  an integration test that a saved edit lands an audit row and enqueues the thumbnail job.

## Out of scope

- Re-running `face_detect` or `ocr` after a rotation. The detection results stay as they are;
  only their on-screen placement is corrected.
- Any quick-rotate control outside the edit panel, and any change to crop, brightness or
  contrast.
- Rewriting the original file. The edit stays non-destructive.

## Implementation notes

- `bootstrap-icons` has `arrow-counterclockwise` and `arrow-clockwise`; check
  `web/src/components/Icon.tsx` for how a name is passed and keep the icon decorative with the
  label on the button.
- The audit entry has to be written the way the package intends — in the mutation's
  transaction where the store supports it, otherwise following the pattern used by
  `handleRegenerateThumbnail`.
- The thumbnail job type and its enqueue helper already exist for
  `POST /photos/{uid}/regenerate-thumbnail`; reuse that path rather than inventing a second one.
- New UI strings go into both `cs` and `en` translations, Czech being the default.
