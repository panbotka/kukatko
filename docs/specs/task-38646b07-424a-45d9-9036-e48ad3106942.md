# The integrity check does not know videos stream

The library integrity check looks for missing originals, missing thumbnails, missing embeddings,
missing faces, missing perceptual hashes, missing places and missing dates. It knows nothing about
streaming renditions — the word does not appear in the package. So the two ways streaming can rot
are both invisible:

- **A rendition row whose segments are gone.** The catalogue says the clip streams, the player
  asks for its playlist, every segment answers 404, and nothing reports it. This is exactly the
  state a storage migration leaves behind today.
- **Segments with no rendition row.** Orphaned objects in the store that nothing will ever serve
  and nothing will ever clean up — dead weight that grows with every failed or re-run encode.

## Requirements

- The scan gains a finding for a rendition recorded in the catalogue whose segments are not in the
  store. Check cheaply — the presence of the playlist or the initialisation object is enough
  evidence; do not fetch every segment of every video.
- The scan gains a finding for objects under the streaming prefix that belong to no recorded
  rendition.
- Both findings carry enough to act on: which photo, which rendition, and how much storage the
  orphans occupy.
- The repair side does the safe half only. A rendition whose segments are gone is repaired by
  dropping the row so the clip stops claiming it streams and the ordinary encode backfill picks it
  up again — the original is untouched, and the integrity check never deletes originals. Orphan
  segments are **reported, not deleted**, unless deletion is explicitly asked for: an object that
  looks orphaned during a running encode is not orphaned, and deleting it would break a job in
  flight. If a delete path is offered at all it must exclude anything an unfinished encode job
  could still be writing.
- A library with streaming switched off, or with no videos, produces no findings and no extra
  store listings — an instance that does not stream must pay nothing for this check.
- The scan's cost must stay proportionate. Say in the documentation how many store operations the
  new checks add per video.

## Documentation

The new findings and their repairs go into the operations documentation alongside the existing
ones, and the package change into `docs/PACKAGES.md`.

## Tests

Integration tests against the test database and a fake store: a healthy encoded video producing no
finding; a rendition row with its objects removed producing the finding and being repaired by
dropping the row; orphan objects being reported and not deleted; streaming switched off producing
nothing.
