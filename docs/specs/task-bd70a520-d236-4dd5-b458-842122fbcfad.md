# Faces panel: confirm every offered suggestion at once

On a photo where several faces each have a confident identity suggestion, let the user
confirm all of them with one click instead of tapping each face row separately.

Reference case: https://fotky.kotrzina.cz/photos/phkcm39m6vhtpkd9oit3gspvst?panel=faces

## Requirements

- Add a single bulk action to `FacesPanel` (`web/src/components/people/FacesPanel.tsx`),
  placed above the face rows, labelled with the count — cs "Potvrdit vše (N)" / en
  "Confirm all (N)".
- **What counts as actionable:** an unassigned face whose top suggestion falls in the
  *offered* tier, i.e. what `rankSuggestions()` in `web/src/lib/faceSuggestion.ts` already
  returns as `offered` (floor `SUGGESTION_DISPLAY_FLOOR`, today 0.5). Do **not** add a second,
  lower threshold and do not change the floor — the bulk action confirms exactly what the
  panel already offers as a one-tap button, and follows the floor if it ever moves.
- The button is rendered only when `canWrite` and at least **two** faces are actionable
  (with one face the existing per-row button is enough).
- Faces that are not actionable — already assigned, uncertain-only suggestion, no embedding —
  are left completely untouched and stay in the panel afterwards for manual handling.
- **Same subject twice:** if two actionable faces top-suggest the same subject, confirm only
  the higher-confidence one and leave the other untouched. Never create two markers for one
  person on one photo (see `internal/dupmarkers` for why).
- Each confirmation goes through the existing single-face path — `assignFace()` →
  `POST /api/v1/photos/{uid}/faces/assign`, driven from `useFaces`. **No new endpoint, no new
  Go package**; the loop is client-side and sequential.
- While running, the button shows progress and can be cancelled, modelled on
  `confirmAllState` in `web/src/hooks/useCandidateReview.ts`. Cancel stops before the next
  face; faces already confirmed stay confirmed.
- Partial failure: the run continues, and afterwards the panel reports how many faces failed.
  Failed faces stay unassigned. No rollback and no undo — the existing per-face
  reassign/unassign is the correction path.
- When the run finishes, the faces are reloaded and selection advances to the next unnamed
  face exactly as a single confirmation does today.
- i18n keys under `faces.*` in both `cs` and `en`; button is keyboard reachable and marked
  `aria-busy` while running.

## Tests

- `FacesPanel.test.tsx`: button hidden with 0/1 actionable faces, hidden without `canWrite`,
  correct count, confirms every actionable face and no other, the same-subject rule, cancel
  mid-run, partial failure tally.
- Hook-level test for the new batch state in `useFaces`.
