# Drop the person payoff card from the sorting game

After a confirmed face the sorting game (Třídění, `/review`) sometimes interrupts the round with a
card announcing "{jméno} má teď N fotek", the year span of that person's photos and a link into
their gallery. It is noise in the middle of a run and nobody wants it. Remove it end to end,
including the backend that computes it.

## Requirements

- The game never shows that card again: a confirmed face answer goes straight on to the next
  question, with the round's progress, combo and tallies behaving exactly as they do for any other
  answer.
- The "jen pro radost" breather — a favourite or highly rated photo with nothing to decide
  (`review.breather.*`) — stays exactly as it is. Only the person payoff goes.
- The answer endpoint no longer returns the payoff payload, and the review service no longer reads a
  subject's headline stats to build it. The reader interface and the wiring that supplied it are
  removed as well: nothing dead may be left behind (the linter is strict and will not tolerate an
  unused type or parameter).
- The strings that only the removed card used disappear from both locales; no orphaned i18n key and
  no orphaned CSS rule stays behind.
- Tests asserting the card or the payload are removed or rewritten; the frontend game tests and the
  backend answer tests stay green.
- Docs are updated in the same change: `docs/API.md` for the answer response shape,
  `docs/PACKAGES.md` for `internal/review`, and `CLAUDE.md`'s package line for `internal/review`
  only if its one-liner stops being true.

## Implementation notes

- Frontend: `RevealCard` in `web/src/components/review/ReviewBreather.tsx`, the payoff plumbing in
  `web/src/hooks/useReviewGame.ts` and `web/src/pages/ReviewPage.tsx`, the type in
  `web/src/services/review.ts`, the `review-game__reveal-link` rules in
  `web/src/components/review/review.css`, and the `review.reveal.*` keys in both locale files.
- Backend: `revealFor` in `internal/review/answer.go`, the payload type and the subject-stats reader
  interface in `internal/review/review.go`, the response field in the answer API, and the
  constructor wiring in `cmd/kukatko`.
- Removing the reader interface must not touch `internal/people` itself — only the review package's
  use of it.
