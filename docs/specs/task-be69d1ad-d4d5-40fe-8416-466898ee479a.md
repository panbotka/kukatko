# Ingest and jobs know the project

## Context

Kukátko is multi-tenant: `photos (project_id, file_hash)` is the dedup key; `auth.ProjectUIDFromContext(ctx)` gives the project on HTTP; `internal/photos` and the other stores are scoped; `projects.storage_prefix` exists (`""` for `v`, `projects/<uid>/` for new projects). Several earlier steps already added `project_uid` to specific job payloads/dedup keys where they needed it (`face_cluster`, `family_export`, `nameless_*`, `task_digest`) — **reconcile**: this step defines the mechanism once and makes those uses conform. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.5 and 5.2; read `docs/PACKAGES.md` for `internal/ingest`, `internal/jobs`, `internal/worker`. Step 21 of 40.

## Requirements

- `internal/ingest`: the entry point takes the `*project.Project` (not just the uid: it needs the storage prefix and, later, the limits). SHA-256 dedup looks up `(project_id, file_hash)`, so the same bytes in two projects become two photo rows. The object key is `project.StoragePrefix + <today's key>`; because `v` has an empty prefix and every other project a non-empty one, two projects never share a key — add a test for exactly that. The upload endpoint, the public upload-link endpoint and `import dir` pass the project they resolved.
- `internal/jobs`: a documented, typed payload field `ProjectUID` (JSON `project_uid`) on the **library-wide** job types: `face_cluster`, `family_export`, `nameless_detach`, `nameless_restore`, `task_digest`, `notification_purge`, and the future `storage_rekey`. `Enqueue` refuses a library-wide type without it (typed `ErrProjectRequired`). Per-photo types (`thumbnail`, `image_embed`, `face_detect`, `metadata`, `ocr`, `sidecar`, `places`, `storyboard`, `hls_transcode`) are unchanged (the handler reads the project from the photo row via the `ForJob` loader). Instance-wide types (`backup`, `mail_send`, `push_send`, `tag_notify` keyed per user) are listed as such in the package doc.
- Dedup indexes (`internal/jobs/store.go` and their migrations): the partial unique indexes keyed on `type` alone become `(type, payload->>'project_uid')` for the library-wide types; `tag_notify` stays per `user_uid`. One idempotent migration drops and recreates them.
- `internal/worker`: expose `jobs.ProjectUIDOf(job) string`; handlers that need the project read it from there, never from a global.
- Every scheduler-style trigger (daily digest, recluster, family export on change, notification purge, trash retention) enqueues one job per **active** project (`project.Store.List` filtered by `active`).
- `internal/jobsapi` (maintainer): the list shows a `project` column (slug via join on `payload->>'project_uid'`, or via the photo for per-photo jobs) and accepts `?project=<slug>`.
- Tests: ingest dedup per project (same bytes into A and B → two rows, two different keys; A's listing excludes B's); `Enqueue` refusal; dedup index behaviour (two `face_cluster` jobs for different projects coexist, two for the same collapse); jobs list filter.
- Docs: `docs/PACKAGES.md` (ingest, jobs, worker — the three job categories), `docs/API.md` (`/jobs` filter), `docs/ARCHITECTURE.md` jobs section.

## Out of scope

Limits enforcement (own step), the storage move, the prefix for derived files (own step).
