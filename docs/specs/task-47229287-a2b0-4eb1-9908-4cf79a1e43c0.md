# User administration: mandatory e-mail, approval, reset links

The admin user screen (`web/src/pages/UsersPage.tsx`) predates three API changes:

- an account's e-mail address is now required, and accounts that never had one carry a
  placeholder in the reserved `.invalid` domain
- an account can be waiting for an administrator's approval — the listing returns an
  approval timestamp, accepts a filter for the waiting ones, and
  `POST /admin/users/{uid}/approve` approves one
- a password reset can be issued as a one-time link —
  `POST /admin/users/{uid}/password-reset` mails the link and returns it

`UsersPage.tsx` is already large. Put new pieces in their own components beside the page
rather than growing that file further.

## Requirements

- The e-mail field in the create and edit forms is required and marked as such. Submitting
  it empty is refused in the browser before the request goes out, and a rejection from the
  server is shown next to the field.
- An account whose address is a `.invalid` placeholder is shown as having **no real
  address**, with a hint that it should be filled in. It is never shown as a normal
  address the administrator might trust.
- An account waiting for approval carries a clear badge in the list, visually distinct
  from the badge a blocked account carries. The two states must never look the same.
- A row for a waiting account offers an **Approve** action. It confirms first, then
  approves, then updates the row in place without a full reload.
- A filter above the list narrows it to accounts waiting for approval, with the count of
  waiting accounts visible so the administrator notices there is something to do.
- The existing "set password" action gains a sibling: **issue a reset link**. It confirms
  first, then shows the returned link in a field the administrator can select and copy in
  one action, together with a line saying the link was also mailed to the person and stays
  valid for 7 days. Closing the dialog clears the link from the screen.
- Every action reports its outcome the way the page already reports outcomes, and a
  failure leaves the list unchanged.
- All new text goes through i18n with Czech and English strings.

## Definition of done

- Component tests cover: the required address, the placeholder address rendering, the
  waiting badge, approving a row, the waiting-only filter, and issuing and copying a reset
  link.
- `docs/FRONTEND.md` describes the new components.
- `make check` passes.
