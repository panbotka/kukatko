# Project chooser as a profile picker

`/projects` (`web/src/pages/ProjectsPage.tsx`) is where an account with more than one project picks which library to enter. Owner feedback (2026-10-16): the page looks bad. Today it is a dense three-column grid of plain Bootstrap cards sorted alphabetically, with deactivated projects (dashed, "Nedostupné") mixed in between the active ones, a small role badge on every card, and three outline buttons top-right. The owner wants it to feel like Netflix's profile picker: you choose what you want to step into.

## Requirements
- **Concept:** a calm, centred "Kam se chcete podívat?" (en: "Which library do you want to open?") screen. Each project is one large, square-ish tile with a picture and the project name under it; picking a tile enters the project (`/p/<slug>`). The whole tile is the link, with a clear hover/focus state (keyboard reachable, visible focus ring).
- **Picture per project:** an automatic cover — the cover of the project's first featured ("Doporučujeme") album if it has one, otherwise its most recently added photo, otherwise a generated placeholder (initial letter on a palette colour, like the avatar initials elsewhere). Add whatever API field is needed (e.g. a `cover_thumb_url` on the memberships the chooser already loads), only for projects the caller may enter, through the existing signed/own media routes; never reveal a photo of a project the caller is not a member of. Respect `internal/tenancyguard` (every statement scoped by project).
- **Order:** active projects first, the one visited most recently first (the membership already tracks the last visit), then the rest by name. Deactivated projects (only a system administrator sees them) go into a separate, quieter "Vypnuté projekty" section below, collapsed by default.
- Keep: the unread-notification count per project (as a small badge on the tile), the role only as a subtle secondary line (or tooltip) rather than a badge on every tile, the project description as an optional one-line subtitle.
- The account actions (Účet, Odhlásit se) and the maintainer's "Správa projektů" move into a small, unobtrusive header/footer row — not three equal buttons competing with the tiles.
- A single enterable project still enters it directly (keep current behaviour); no projects at all keeps a clear empty state.
- Responsive: 2 tiles per row on a phone (390 px), growing to 4–5 on desktop; no horizontal overflow; tiles stay legible with long names (ellipsis, full name in title).
- Colours only via the palette tokens (`styles/palette.css`, contrast test), icons via `Icon`, all texts in cs + en.
- Use the frontend-design skill for the visual direction.
- Tests: vitest for ordering (recent first, inactive section), the cover fallback chain, the badge, keyboard activation; an API/integration test for the cover field and that it never leaks a non-member project's photo.
- Verify visually at 1440 px and 390 px (screenshots against a throwaway instance or the box staging stack), update `docs/FRONTEND.md` (and `docs/API.md` for the new field).
