# Flaky fresh-schema migration test

CI's `integration` job failed once on main (commit db93d173, run 38885413843) and passed on a plain re-run, with no code change:

```
--- FAIL: TestMigrate_freshDatabaseHasOnlyTheBootstrapProject (0.09s)
    projects_migration_integration_test.go:87: a fresh schema applied no migrations — the search_path did not isolate it
```

The test (`internal/database/projects_migration_integration_test.go`, helper `freshSchemaDB`) connects with `search_path=<fresh schema>,public`, creates the schema after the pool exists, then calls `db.Migrate`. It expects every migration to apply into the fresh schema. Once, Migrate saw everything as already applied. Most likely it found `public.schema_migrations` because a pooled connection resolved the name before the fresh schema existed, or because the migrator's existence check is not schema-qualified the way the test assumes. A parallel test in the same package touching the migration lock or `public` is another candidate.

## Requirements

- Find the root cause and fix it, in the test helper or in the migrator if the migrator resolves `schema_migrations` in a way that could also bite a real deployment with a non-default search_path. Say which in the commit.
- Prove it: run the test in a loop (e.g. `-count=200`, plus `-race` and with the package's other tests in parallel) against the test DB with zero failures. Put the command and the result in the commit message.
- Apply the same fix to any other test using the fresh-schema pattern (grep for `search_path` in `_test.go` files).
