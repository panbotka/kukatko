# The long tail is scoped by project

## Context

Kukátko is multi-tenant: `import_runs.project_id` exists; `internal/photos` and most catalogue packages are scoped (convention in `docs/PACKAGES.md`: `projectUID` after `ctx`, never defaulted; foreign = 404 same shape); `auth.ProjectUIDFromContext(ctx)`; `internal/projecttest`; each project has `storage_prefix`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4, 2.6, 6. Step 20 of 40.

## Requirements

- `internal/system` + `systemapi` (`GET /system/status`, maintainer, instance-level): catalogue numbers become a per-project breakdown (`projects: [{slug, photos, originals_bytes, faces, subjects, queue…}]`) plus instance totals; the frontend `/system` page shows the breakdown as a table.
- `internal/places` + `placesapi` (countries → cities with counts) and `internal/placesjob`, `internal/geoestimate`: per project (the `photo_places` side table is keyed by photo, so it follows through the join); the geo estimate only looks at neighbours of the same project.
- `internal/importer` + `importapi`: runs and failures are per project; `GET /p/{slug}/import/runs` lists only that project's runs.
- `internal/dirimport` (`kukatko import dir`): a required `--project <slug>` flag; ingest into that project; the sidecar rebuild mode reads sidecars only under the project's storage prefix — for the bootstrap project with an empty prefix that is the root `sidecars/` tree **excluding** any `projects/…` subtree; a sidecar whose embedded project (if present in the format) does not match → skipped with a warning.
- `internal/processing` + `processapi` (backfills: embeddings, faces, clusters, places, metadata, OCR, sidecars…): per project under the prefix; the maintainer's instance-level trigger (if one remains) iterates active projects.
- Isolation tests: import runs list; places tree for A excludes B's cities; geo estimate ignores B's neighbours; `import dir --project b` lands in B; processing backfill for A enqueues only A's photos.
- Docs: `docs/PACKAGES.md`, `docs/OPERATIONS.md` (`import dir --project`), `docs/API.md`.
