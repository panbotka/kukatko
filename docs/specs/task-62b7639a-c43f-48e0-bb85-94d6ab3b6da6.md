## What is wrong

On `/search`, a query that matches nothing — a typo, or outright gibberish — still returns a full
page of photos under the heading **„Nejlepší shody: 192"**. The default search mode is `hybrid`, and
its semantic half is a nearest-neighbour ranking with no relevance floor, so *every* string gets
results. A user who mistypes a word gets 192 irrelevant photos and no hint that nothing actually
matched.

Found during the v0.24.0 pre-release walkthrough on box staging. **Pre-existing — not introduced by
the v0.23.0..e1b50f5 range** (that range's search commit `e1b50f5` changed accent folding in the
filter arms, not the semantic path). Severity: NIT — the UI does expose the mode and explains it, so
this is a polish question, not breakage.

## Evidence (measured on box staging, 396 photos)

```
/api/v1/search?q=qwertzuiop-nesmysl-xyzzy-42&mode=fulltext  -> total 0     (correct empty)
/api/v1/search?q=qwertzuiop-nesmysl-xyzzy-42&mode=hybrid    -> total 192   (the default)
/api/v1/search?q=qwertzuiop-nesmysl-xyzzy-42&mode=semantic  -> total 396   (everything)
```

So hybrid already discards roughly half the library, but on no threshold that means anything for a
query with no real match.

## Reproduce

1. `/search`, leave the mode at the default **„Chytré (doporučeno)"**.
2. Search `qwertzuiop-nesmysl-xyzzy-42`.
3. Observed: „Nejlepší shody: 192" and a full grid. Expected: something that tells the user nothing
   really matched.

## What to do

Decide the behaviour first — this is a judgement call, so weigh it rather than jumping to code:

- **Option A — a relevance floor.** Drop semantic hits beyond a cosine distance cutoff. Honest, but
  it needs a measured threshold, and `docs/THRESHOLDS.md` requires the measurement that produced any
  value to be recorded alongside it. Do not invent a number.
- **Option B — say what the results are.** Keep every hit but make the heading tell the truth when
  the fulltext half matched nothing: e.g. „Nic přesně neodpovídá — tohle jsou vizuálně nejbližší
  fotky", with the exact-match count when it is zero. Cheaper, no threshold to defend, and it keeps
  the genuinely useful "I can't spell it but I know what it looked like" case working.

**Option B is the better default** — semantic search returning neighbours is the feature, not the
bug; the defect is only that the label overstates them. Take A only if measurement shows a clean
cutoff.

Either way, check the same wording on the library FilterBar, which uses the list path
(`q=` free text → `params.Search`) and *does* already return an honest 0.

## Done when

- A query with no real match no longer presents as confident matches.
- The existing modes („Podle textu" → exact 0, „Podle obsahu fotky" → neighbours) are unchanged.
- If a threshold was introduced, `docs/THRESHOLDS.md` carries it **with the measurement**.
- Tests cover the zero-exact-match case; `make check` passes; `docs/API.md` updated if the response
  shape or the mode semantics changed.
