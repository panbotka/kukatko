# What's new, the digest and upload links are scoped by project

## Context

Kukátko is multi-tenant: `project_members` carries the per-project `last_seen_at`, `visit_reference_at`, `task_digest_at`, `subject_uid` (the same columns still exist on `users` as a transition; a later step drops them); `upload_links.project_id` exists; `internal/phototask`, `internal/notification`, `internal/photos` are scoped; library-wide jobs carry `project_uid` in payload and dedup key. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.2, 2.5, 4.2, 6. Step 18 of 40.

## Requirements

- `internal/whatsnew` + `whatsnewapi`: the visit bookkeeping (two timestamps, the 6 h gap) reads **and writes** `project_members`, not `users`; the digest counts only the project's photos/albums/comments. Leave the `users` columns untouched (do not drop; do not write them either — grep for any remaining writer and move it).
- `internal/personme` (`person:me`/`family:me`): resolves the caller's `project_members.subject_uid` of the current project.
- `internal/taskdigestjob`: the watermark is `project_members.task_digest_at`; the daily scheduler enqueues one `task_digest` job per (user, project) with open tasks (payload `project_uid` + `user_uid`, dedup on both); the mail lists tasks under a heading with the project name and links to `/p/<slug>/tasks/<uid>`.
- `internal/uploadlink` + `uploadlinkapi`: the management routes are per project (under the prefix); the **public** `GET /u/{code}` and `POST /u/{code}/upload` stay instance-level and resolve the project from the link row (`upload_links.project_id`), then run the ingest into that project with that project's storage prefix and limits; `RegistrationGate`/`AdmitRegistration` creates the membership in the link's project (viewer, unapproved, as today's account approval flow); claiming a session's photos at registration verifies the project.
- Isolation tests: what's-new in A does not count B's uploads; `person:me` in B uses B's subject; digest for a user in both projects produces two jobs and two sections; a public upload through B's link lands in B (listing in A excludes it); registration through B's link yields a membership in B only.
- Docs: `docs/PACKAGES.md`, `docs/API.md` (public routes resolve their project), `docs/ARCHITECTURE.md`.

## Out of scope

Dropping the `users.*` columns, mail wording beyond the links, limits enforcement (own step).
