# New Review Game Question Types

Extend the sorting game (`/review`) beyond face/label candidates with three new question types, all backed by data that already exists in the app.

## Requirements
- **Place check:** photos whose location came from the estimator (results marked `estimate` by the geo-estimation logic) can appear as "Byla tahle fotka pořízena v {place}?" Yes → keep the location and clear the estimate mark; No → remove the estimated location. Both through existing write paths, audited.
- **Duplicate check:** pairs from the near-duplicate groups appear side by side: "Je to stejná fotka?" Yes → record the confirmation so the duplicates page can rank that group as human-confirmed; No → record "not duplicates" feedback via the existing feedback package so the pair stops reappearing. NEVER auto-merge from the game.
- **Outlier check:** faces flagged by per-person outlier detection appear as "Je na téhle fotce opravdu {name}?" with the face crop shown. No → detach/invalidate the marker via the existing assignment write paths; Yes → record the confirmation so that face stops surfacing as an outlier.
- The queue mixes the new types with the existing ones; no type may dominate a session (cap or weighted mix). Every question stays answerable with the existing one-tap/one-key game controls, and skipping keeps working.
- Answers are audited like existing review answers and count toward the leaderboard automatically.
- Editor role required (unchanged). i18n cs/en for all new question texts.
- Integration tests per type: each answer triggers exactly the right write-path side effect and nothing else. Frontend tests for rendering each new question layout — the duplicate check needs a two-image layout; the outlier check shows a face crop (crop bboxes from fit_* thumbnails, never from tile_* — tiles are centre-cropped and the bbox lands wrong).
