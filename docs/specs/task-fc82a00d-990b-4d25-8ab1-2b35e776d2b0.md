# Greyed-out buttons with no stated reason

As a viewer you see a series of controls that are present but `disabled`, with no explanation
anywhere:

- the name rows in the faces panel (`button … [disabled]`),
- the "Zjistit místo" button under the mini-map in the Informace panel,
- "Uložit pohled" in the library and search headers.

At the same time some writes **do** go through for a viewer — the favourite heart works, and
correctly so, because favourites are personal. From the user's point of view the state is
"some buttons work, others don't, and I can't tell which is which".

A greyed-out button with no reason reads as a malfunction, not as a permission — especially
next to a working button on the same toolbar.

## Requirements
- Pick one consistent rule for controls that are disabled because of the user's role and
  apply it everywhere: either always render them disabled **with a tooltip** carrying one
  sentence ("Na tohle potřebuješ roli editora."), or never render them for that role. Today
  the app does both.
- Whichever rule you pick, a control that is disabled for another reason (nothing selected,
  data missing) must say that instead, so the two cases are distinguishable.
- The tooltip must be reachable without a mouse (title/aria-describedby, or a tap target on
  touch devices).
- Czech and English translations.
