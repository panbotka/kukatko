# Service worker push handlers and the browser-side subscribe module

Kukátko is an installable PWA with a real service worker, but it handles no push at all. This task adds the two worker events a push needs, the Android badge icon, and the browser module that subscribes to push in the first place. It builds **no UI** — the permission modal and the settings section are separate tasks.

## Context that matters

`web/build/service-worker.js` is the worker **template**: plain JS, not bundled, so it cannot import anything from `web/src`. `web/build/pwa.ts` (`pwaPlugin`, `apply: 'build'`) substitutes its placeholders at `generateBundle` and emits it as `/sw.js`, unhashed, at the output root. It currently listens for `install`, `activate`, `message` and `fetch`; the fetch handler is a strict **whitelist** that calls `respondWith` for nothing but the precached shell, precached asset paths and the share-target POST.

`web/build/pwa.test.ts` runs the **real rendered worker** in a `node:vm` scope with fake caches — that is how the worker is tested here. `web/src/pwa/shareContract.ts` is the precedent for sharing a contract between the worker and the app: deliberately **DOM-free**, so the un-bundled worker's test can import it and drive the real worker against it, which is what keeps the two halves from drifting.

`web/src/pwa/register.ts` registers the worker and drives the update handshake.

Backend context: an endpoint under `/api/v1` returns the VAPID public key and whether push is enabled instance-wide; another accepts a subscription (endpoint URL, the `p256dh` and `auth` client keys, a user-agent) and removes one by endpoint. The payload the server sends is JSON carrying a title, a body, a deeplink path, a kind and a collapse tag.

## Requirements

- A contract module shared by both halves, in the same spirit as `shareContract.ts` and equally **DOM-free**, holding the payload field names, the notification tag shape and the deeplink handling — so `build/pwa.test.ts` can import it and drive the real worker against it.
- A `push` handler in the worker template: parse the payload and show a notification carrying the title, the body, the app icon, a **monochrome badge icon**, the deeplink in its data, and the payload's collapse tag so a later notification of the same kind **replaces** the earlier one instead of stacking. Without the tag, a weekend of tagging leaves ten near-identical entries in the shade.
- A `notificationclick` handler: close the notification and open the deeplink. If a Kukátko window is already open, **focus it and navigate it** rather than opening a second one — an installed PWA has no tabs, and a duplicate window leaves the person with no way back. This repo has already hit that exact problem once with the review game.
- A malformed or empty payload must still show something rather than throwing inside the worker. A generic "Kukátko" notification beats a silently swallowed event.
- The `fetch` handler's whitelist must **not** change. A push has nothing to do with fetching, and that whitelist is load-bearing.
- **Android needs a monochrome badge icon.** Android draws the small status-bar glyph from the notification's `badge`, and with none Chrome shows a generic dot. Add a 96×96 monochrome (white on transparent) badge raster. Every raster in this project is **generated and committed** by `scripts/icons.sh` (headless Chromium render, then a crop; ImageMagick only for the crop and the `.ico`) from the master SVG in `web/public/icons/` — extend that script and commit the generated file. Do not hand-draw a one-off that the next regeneration would not reproduce.
- A browser-side module `web/src/pwa/push.ts` covering: the current permission state, whether the browser supports push at all, requesting permission, subscribing with the server's VAPID public key, registering the subscription with the server, unsubscribing in both the browser and the server, and reporting the current subscription. It must **never throw at its caller**: an unsupported browser, a denied permission, a missing worker registration and a failing request all resolve to a reported state.
- **`requestPermission()` only works from a user gesture**, so this module must not call it on its own — it exposes it for a click handler to call later.

## Platform notes

- **Android needs nothing beyond VAPID.** Chrome for Android has supported the Push API since version 50 and Firefox for Android since 48. The old `gcm_sender_id` manifest field and an FCM project were replaced by VAPID and must **not** be added. Push works on Android in a plain browser tab, with no install to the home screen.
- **iOS delivers push only to an installed PWA** (Safari 16.4 and up, added to the home screen). In mobile Safari without installing, subscribing simply fails — the module must report that as an ordinary unsupported state, not an error, so the UI built later can explain it instead of showing a broken button.

## Verification

Extend `web/build/pwa.test.ts` to drive the **real rendered worker** in its `node:vm` scope: a well-formed payload shows a notification with the expected title, body, badge, tag and data; a malformed payload still shows something; a click with an existing client focuses and navigates it; a click with no client opens a window; the fetch whitelist is unchanged. Unit-test `push.ts` across every branch — unsupported, denied, granted, subscribe failure, unsubscribe. Vitest, strict ESLint and Prettier must all pass.
