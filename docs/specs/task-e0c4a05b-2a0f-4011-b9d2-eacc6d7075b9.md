# People, faces and vectors are scoped by project

## Context

Kukátko is multi-tenant: `subjects.project_id`, and the **denormalised** `faces.project_id` / `embeddings.project_id` exist (kept in sync by the writers); `auth.ProjectUIDFromContext(ctx)` gives the project; `internal/photos` is scoped (convention in `docs/PACKAGES.md`: `projectUID` after `ctx`, never defaulted, foreign = 404 same shape); `internal/projecttest` is the harness. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4 and 6. Step 13 of 40. Do **not** change any cosine threshold (`docs/THRESHOLDS.md`).

## Requirements

- `internal/people` (subjects of all kinds, markers, the `faces` cache, slugs, nicknames, the subject gallery, the roll-call): every method takes `projectUID`; subject slug uniqueness is per project (the `(project_id, slug)` UNIQUE exists); `GET /subjects/{uid}` and the gallery for a foreign uid → 404 same shape; creating a marker verifies the photo's project; the tag observer used by `tagnotifyjob` receives the project uid in its callback.
- `internal/vectors`: every kNN query (similar photos, face identity suggestions, unassigned-face neighbours, exemplar search) filters `project_id = $n` **inside** the HNSW query using the denormalised column. Verify with `EXPLAIN (ANALYZE, BUFFERS)` on the test DB (seed ≥ 2 000 rows in one project, 10 in another) that the plan uses the HNSW index with the filter; record the plan in `docs/PERF.md` and add the note that pgvector's iterative scan (`SET LOCAL hnsw.iterative_scan = relaxed_order` on pgvector ≥ 0.8) protects recall for small projects — set it per query when the installed version supports it (check at startup once, cache the result).
- `internal/facematch` (face↔marker IoU, suggestions, roll-call, assignment state machine) and `internal/avatar` + `internal/avatarapi` (subject avatars, cache-only renditions): project everywhere; an avatar of a foreign subject → 404.
- `internal/feedback` face rejections/confirmations: scoped through the face's project; `internal/feedbackapi` face routes pass the project.
- `internal/peopleapi` and `internal/avatarapi` pass the project from context.
- Isolation tests: store — subjects list, markers by photo, faces kNN (seed one face in each project with an **identical** embedding and assert the neighbour from the other project never appears), suggestions; HTTP — subject detail, gallery, avatar, create marker on a foreign photo, assign a foreign face.
- Docs: `docs/PACKAGES.md` for each touched package, `docs/PERF.md` (filtered HNSW).
