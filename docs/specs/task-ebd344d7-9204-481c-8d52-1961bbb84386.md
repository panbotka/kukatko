## Problem (reported by the user)
On the homepage, the "Doporučujeme" strip (featured albums) shows a different picture than the same album's tile on the albums page. The albums page draws a **2 × 2 collage of four photos**; the strip draws **one photo**. The user expects the featured card to look like the album tile, with the same four photos in the grid.

## Cause (found while looking at the code)
- `web/src/components/library/FeaturedAlbumsStrip.tsx` (`FeaturedCard`) renders a single `album.thumb_url` / `cover_uid`.
- `web/src/components/organize/AlbumTile.tsx` renders `albumCover(album)` from `web/src/lib/albumCovers.ts`. That gives a 2×2 collage built from the server's `cover_uids` list (newest first). It falls back to a single photo for a hand-picked cover or for an album with fewer than 4 photos.
- The featured payload (`internal/organize/featured.go`, `FeaturedAlbum`, served by `internal/organizeapi/featured.go`) carries only `cover_uid` + `cover_blurhash` (+ `thumb_url`). It has no `cover_uids` candidate list, so the strip has nothing to build a collage from.

## What to do
1. Backend: give `FeaturedAlbum` the same `cover_uids` candidate list the album listing returns. Reuse the album listing's query/logic (`albumCoversSQL` & co. in `internal/organize`); don't write a second copy. Keep the performance rule from docs/PERF.md: no correlated `ORDER BY … LIMIT 1`, and scan only the featured albums' membership. Keep the visibility rules the strip already applies (`coverVisible`). Update the integration tests.
2. Frontend: have `FeaturedCard` draw its cover with the same logic as `AlbumTile`: `albumCover()` → single / collage / none, with the same thumb sizes (`COLLAGE_THUMB_SIZE` for cells). Ideally extract the shared cover-media rendering out of `AlbumTile` into one component and use it in both places, so they cannot drift apart again. Keep the blurhash placeholder for the single-photo case.
3. Note: the albums grid plans covers across all tiles (`taken` set) so neighbouring tiles don't repeat a photo. A tile there can therefore differ slightly from the album's plain `albumCover(album)`. For the strip, plan the album on its own (no `taken` from the albums page). Say in the task note whether exact parity with the albums page holds or not.
4. Tests: vitest for the strip (collage with ≥4 photos, single photo for a hand-picked cover and for <4 photos, empty state). Go tests for `cover_uids` in the featured payload.
5. Docs: `docs/API.md` (featured endpoint payload), `docs/FRONTEND.md` (strip/tile cover component).
