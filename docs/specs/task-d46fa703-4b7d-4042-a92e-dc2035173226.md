# Two react-bootstrap defaults stay English in the Czech interface

`<html lang="cs">` is set correctly, but two accessible names come from react-bootstrap's
built-in defaults and were never routed through i18next:

| String | Where | Reach |
| --- | --- | --- |
| `Toggle navigation` | the navbar hamburger's `aria-label` | every page |
| `Close` | the modal close button | every dialog, e.g. "Nové album" |

Scanned `/`, `/albums`, `/people/clusters`, `/system`, `/account`, `/upload` and `/search` —
one `Toggle navigation` hit on each.

Nothing is visibly wrong; these strings surface only to screen readers and voice control. But
on a Czech instance a screen-reader user hears English for the primary mobile navigation
control, which is the one control they most need named correctly.

## Requirements

- The navbar toggle and the modal close button must take their accessible names from the
  translation catalogues, in both Czech and English.
- Apply it to every modal in the application, not only the album dialog — if the codebase
  wraps react-bootstrap's modal anywhere, fix it at that wrapper so future dialogs inherit
  the translated name rather than repeating the prop at each call site.
- Do not change any visible text or layout; only the accessible names change.

## Testing

Add a frontend test asserting the accessible name of the navbar toggle and of a modal's
close button comes from the catalogue rather than the library default.
