# Evaluate: an expiring API token can mint a non-expiring token and register a passkey

A source-only security audit (2026-10-06, commit 3792f7c) produced this **unconfirmed lead**. It hinges on a policy decision, so this task **evaluates and documents. It does not change behaviour.**

## The lead
- `authenticateRequest` (`internal/auth/middleware.go:139-144`) turns a Bearer token into a principal with the user's full standing. The principal records neither the token id nor its expiry; only an empty session distinguishes it.
- The credential-management routes sit behind RequireAuth only: POST /auth/tokens (`internal/auth/routes.go:82-83`) and /auth/passkeys/register/begin|finish (`routes.go:76-77`).
- `handleCreateAPIToken` (`internal/auth/handlers_apitoken.go:75`) and `Service.CreateAPIToken` (`internal/auth/service_apitoken.go:41,54`) accept a nil expiry ("never") from any principal.
- So token A with expires_at = now+1h can mint token B that never expires, or register a software passkey, and passkey login then yields a full browser session.
- Expiring or revoking A does not remove B or the passkey. The role does not increase. What is lost is the bounded lifetime and the single revocation of the presenting credential.

## Requirements
1. Write integration tests that demonstrate current behaviour, and keep them as documentation:
   - with Bearer A (1 h), mint B with no expiry
   - after A expires (fixed clock) or is revoked, B still authenticates
   - optionally, Bearer A can complete passkey registration with the virtual-authenticator pattern
2. Do not change behaviour in this task.
3. Write a new SEC entry in `docs/SECURITY_AUDIT.md` with:
   - the confirmed behaviour and its realistic threat, such as a leaked agent token, the MCP/ctl token use, or a non-interactive client
   - options with trade-offs: refuse credential management for token principals (session only); cap a child token's expiry at the parent token's expiry; let the token creator opt in
   - the impact on `kukatko ctl` and any documented token workflows (check `docs/API.md`, `docs/OPERATIONS.md` and `internal/ctl`)
   - a recommendation
