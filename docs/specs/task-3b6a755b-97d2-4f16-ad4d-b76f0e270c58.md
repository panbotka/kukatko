## Bug (reported by the user, reproduced on box staging)
1. Open a photo with the faces panel open, e.g. on staging `http://100.127.79.1:6490/photos/phv30k8jer6jj8aibmm7e8rdun?panel=faces`.
2. Press → : the viewer moves to the next photo (OK).
3. Press → again: **nothing happens.** The keyboard focus is now in the name input (`AddAutocomplete`) for the first unassigned face, so the arrow key moves the text caret instead of navigating.

Expected: → / ← keep moving between photos while the faces panel is open. The user is just browsing; they haven't started typing a name.

## Likely cause (from a quick look; verify it)
`web/src/components/people/FaceAssignPanel.tsx` (~line 212) renders `<AddAutocomplete … autoFocus>`. `FacesPanel.tsx` (~line 351) apparently opens the assign panel for the first unassigned face whenever the photo changes, so every navigation lands focus in the input. The viewer's arrow-key shortcut is then ignored because the event target is an editable field. That ignore rule is correct and must stay.

## Fix direction
- Don't steal focus on **navigation**. Focus the name input only when the user explicitly picks a face: a click/tap on a face box or on a face row, or a keyboard shortcut meant for it. A face the panel auto-selects just because the photo changed must **not** focus the input.
- Keep the face-naming flow fast for keyboard users. If there is (or should be) a shortcut to jump into the name field (e.g. `N` or Enter on the selected face), make sure it exists and is listed in the shortcut help. Check `docs/UX_AUDIT.md` for any recorded decision about this autofocus before removing it, and record the new decision there.
- Escape inside the input should return focus to the viewer, so arrows work again without a mouse click (check whether it already does).
- Check the other `autoFocus` in `components/review/ReviewFacePair.tsx` for the same trap only if it lives in a navigable view. The review game is one question at a time, so it is probably fine; say so in the task note.
- Memory hint: "works only after a click" bugs in this app are often a shortcut waiting on focus (`kukatko-shortcut-dead-window-not-focus`). Confirm which of the two this is.

- Plus: explicitly clicking a face still focuses the name input.
