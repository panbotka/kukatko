# Controls too small or too quiet for the decision they carry

Icon-only buttons are about 16px wide on a phone, and several permanent or destructive actions are
drawn as text links.

## Background

The app-wide coarse-pointer floor (`web/src/styles/app.css:1118`) sets `min-height: 2.75rem` on
`.btn`, `.form-control`, `.nav-link` and friends, but `min-width: 2.75rem` only on
`.navbar-toggler`, `.btn-close`, `.form-check-input` and the opt-in `.kukatko-tap-target-touch`
(`app.css:1219`). An icon-only `variant="link"` with `p-0` therefore ends up roughly 16–20px wide and
44px tall. The helper class exists and is used correctly in eight places; it is missing here:

- `components/people/FacesPanel.tsx:180` — the close ✕ of the viewer's faces bottom sheet, the
  primary way to shut it on a phone.
- `components/photo/MetadataPanel.tsx:1009` — the edit-location pencil, the entry point to a write.
- `components/organize/LabelChip.tsx:108` — the label kebab, which holds rename, a review toggle and
  **delete**, at about 32px (`app.css:2006`).
- `components/photo/EditPanel.tsx:101` — its header close is a bare `p-0` link while its rotate
  buttons already carry the helper (`:137`, `:149`). Confirm before changing; fix only what is
  actually missing.

Separately, actions drawn as links where the weight of the decision calls for a button:

- `components/people/DuplicateMarkerGroupCard.tsx:278` — "this really is them twice" is the card's
  only permanent, unconfirmed decision, yet it is a thin `variant="link"` while the reversible
  per-crop verdicts above it get real outline buttons. Verbatim the complaint that produced `587dc14`.
- `pages/task/TaskParticipants.tsx:103` — removing a person from a task is a server write with no
  confirm and no undo, drawn as an icon-only link held at `opacity: 0.6` until `:hover` or
  `:focus-visible` (`app.css:3199-3212`). Hover never fires on a phone, so a destructive control sits
  permanently dimmed at roughly 24px wide.
- `components/photo/MetadataPanel.tsx:325` — restoring a crossed-out date writes immediately
  (`:611-624`) but reads as a footnote inside grey explanatory text.
- `components/pwa/PwaStatus.tsx:52` — a `variant="link"` with `text-body-secondary` inside a filled
  `Alert variant="info"`: grey on a saturated Superhero fill, effectively invisible. The repo already
  documents the workaround at `components/library/WhatsNewPanel.tsx:182-186` and
  `components/search/UnknownFiltersAlert.tsx:94-96`.
- `components/search/QueryNoticesAlert.tsx:37` — a bare `Link` inside a filled alert, and the only
  affordance that fixes an unsatisfiable `person:me` query.
- `components/photo/CommentItem.tsx:171` — delete is a caption-size, padding-free control 8px from
  Edit, told apart only by colour. It does route through a confirm, so it ranks last.

## Requirements

- Every icon-only control listed above clears a ~44px square on a coarse pointer, through the
  existing helper rather than a new convention per component.
- The task-participant remove control is fully visible on a coarse pointer (never hover-gated), clears
  44px, and its write becomes undoable — an undo toast, or a confirm. A no-confirm, no-undo
  destructive control is not acceptable.
- `DuplicateMarkerGroupCard`'s permanent verdict looks like the verdict buttons beside it.
- `MetadataPanel`'s date-restore leaves the explanatory sentence and becomes its own small button.
- The two filled-alert controls get the workaround the repo already uses, so they are legible on the
  Superhero fill.
- `CommentItem`'s two row actions become separable by touch: give delete a box, or move both into the
  kebab pattern `components/organize/LabelChip.tsx:138` already uses.
- Out of scope, deliberately: draft-only and disclosure controls — the "later" dismissals, filter
  clears, details toggles, wizard back buttons and form fields are correct as links.

## Testing

- A CSS assertion that the coarse-pointer floor gives a width, not only a height, to the controls
  named here.
- Component tests for the undo path on task-participant removal, and that every changed control keeps
  its accessible name.
- Measuring a tap target needs a real coarse pointer, which agent-browser's device emulation does not
  provide — the touch branch wins in a plain headless harness. Force the hover/pointer media features
  in a standalone harness and report the measured rects.
