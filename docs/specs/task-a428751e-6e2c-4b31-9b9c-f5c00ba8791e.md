# Set a Photo's Location on a Map

A family archive is full of scanned photos with no GPS. Let an editor set a photo's location by picking a point on a map — faster and more precise than the existing time-based estimation.

## Requirements

- From the photo detail's edit surface, an editor opens a map picker: search for a place (the backend already has geocode/place-search endpoints) or click/drag a pin on the map; confirming saves the coordinates to the photo.
- A photo with an existing location shows it as a draggable pin; a photo without one starts the map somewhere sensible (e.g. the last location picked this session, or the library's common area — your judgment, anything but 0,0 in the ocean).
- Clearing is possible too: an explicit "remove location" action empties the coordinates.
- A manually picked location is authoritative: it replaces an estimated one and is not flagged as an estimate (internal/geoestimate marks its results `estimate`; a manual pick must not be).
- Saving behaves like any other metadata edit: audited, and the follow-up derived work (reverse geocoding via the places job, sidecar rewrite) gets enqueued so country/city browsing and sidecars stay consistent — verify this actually happens.
- Backend: if the photo edit API does not accept coordinates yet, extend it (validate lat −90..90, lng −180..180; audited like other edits).
- Map tiles go through the existing backend tile proxy (the mapy.com key stays server-side).
- Mobile-friendly: the picker works full-screen on a phone.
- cs (default) + en i18n; unit + integration tests for the edit path, component test for the picker (mock leaflet in jsdom).

## Implementation notes

- Leaflet + the tile proxy are already in the app (map view) — reuse, don't add a second map stack. Build the picker as a reusable component; a bulk variant will want it later.
- Update docs/API.md if the edit contract changes, and docs/FRONTEND.md.
