# Review Game Mixer v2 — Varied Rounds (Backend)

The review game's queue currently returns questions in whatever order the sources produce them, so sessions get repetitive fast: many consecutive questions about the same person, clusters of near-identical photos, long runs of all-confident questions. Players quit early (the live instance has 1 player and ~38 answers). Rebuild queue composition so every batch is varied.

## Requirements
- The queue serves questions composed into **rounds** of a configurable size (default 10). A round is a playlist built with variety rules:
  - Never more than 2 consecutive questions about the same subject or label; cap questions per single entity within one round (default max 3).
  - Rotate across ALL question types available in the codebase (at least face and label questions; if other types exist — e.g. place/duplicate/outlier checks — include them in the same rotation). Interleave types rather than clustering them.
  - Spread photos: avoid consecutive questions whose photos come from the same album or nearly identical timestamps; interleave eras when the pool allows.
  - Interleave confident-tier and uncertainty-band questions instead of clustering them — the existing SureShare ratio still holds over the whole round; change the ordering, not the mix.
  - All rules degrade gracefully: with a small or one-sided pool, serve what exists; never return an empty round while any question exists.
- Round metadata: the response tells the client where a round begins/ends (or one request = one round) plus the counts the client needs for a between-rounds summary.
- **Breather cards (data):** the queue can weave in (or a sibling endpoint supplies) non-question "breather" cards — a high-rated or favorited photo with title/year, era-varied. Read-only, clearly typed so the client can render them differently.
- **Reveal payload:** when a face answer confirms an assignment, the answer response may include a small reveal (the subject's current photo count, oldest/newest photo year) — cheap indexed queries only.
- **Leaderboard streak:** extend the leaderboard response with each player's current day-streak (consecutive days with at least one review answer), derived from existing audited answers — no new tracking table if the data suffices.
- The mixer must be deterministic given its inputs (question pool, config, seed) so tests can assert the variety rules.
- Config keys for round size and per-entity caps under the existing review.* namespace — add to the Config struct, setDefaults, config.example.yaml, tests, and docs/OPERATIONS.md together.
- Keep the API backward-compatible or update reviewapi and its tests consistently. RequireWrite unchanged (editors only); leaderboard stays RequireAuth.
- Tests: no 3-in-a-row same entity, per-entity cap, type rotation when multiple types exist, interleaved tiers, small-pool degradation, round boundaries, breather typing, reveal correctness, streak computation (incl. timezone/day-boundary edge).
- Update docs/PACKAGES.md and docs/API.md.
