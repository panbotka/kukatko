# Fix: MultiSelect suggestion menu paints under the upload queue

On `/upload` the open album/label suggestion list is covered by the upload queue's sticky
progress header, so the user cannot see or click the options.

## Reproduce

1. Open `/upload` on a desktop-width viewport, signed in as a user who may write.
2. Drag in a few photos — the queue and its sticky progress header appear.
3. Click the album field and start typing.
4. The suggestion list opens but is painted **behind** the progress header / queue box.

Before any file is dropped the picker behaves correctly — the sticky header only exists once
the queue has items, which is why the bug looks intermittent.

## Cause

`web/src/components/MultiSelect.tsx` renders the desktop suggestion list as a `position: fixed`
overlay carrying the Bootstrap `.dropdown-menu` class and **no explicit z-index**, so it takes
`--bs-dropdown-zindex: 1000`. `UploadProgressHeader` uses `.kukatko-sticky-toolbar`
(`web/src/styles/app.css`), which is `position: sticky; z-index: 1019`. 1019 beats 1000.

## Requirements

- An open `MultiSelect` suggestion list paints above every in-page sticky toolbar and above the
  upload queue, on every page that uses the component.
- Layering stays correct where `MultiSelect` already lives inside a scrollable modal
  (`BulkEditModal` and the bulk pickers): the menu must not jump above the modal backdrop nor
  visually escape the modal.
- The layering values become documented tokens rather than magic numbers spread across
  components. Extend the existing scale in `app.css` coherently (sticky toolbar 1019, navbar
  1020, 1025, floating dock 1030) and explain the ordering in the comment.
- Regression test (Vitest): with a `.kukatko-sticky-toolbar` rendered on the page, the open
  `role="listbox"` carries the layering that puts it above that toolbar. Assert the applied
  class/style token, not a screenshot.
- Verify for real in a browser at desktop **and** phone width. The phone branch renders the list
  in flow (`position-static`) inside the modal scroll and must keep working above the on-screen
  keyboard — do not regress it while fixing the desktop overlay.

## Out of scope

- Any redesign of the upload page — that is a separate task.
