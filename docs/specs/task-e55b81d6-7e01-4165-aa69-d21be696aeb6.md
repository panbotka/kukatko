## Goal
A new notification kind, `task_assigned`. When someone asks me on a Kukátko task (`/tasks`), I get "<who> tě přidal(a) k úkolu: <task title>", linking to `/tasks/<uid>`. Channels are in-app / push / e-mail per my preferences, off by default.

## Current state
- `internal/phototask`: `photo_task_participants(task_uid, user_uid, joined_at, added_by)`. `added_by` null = the person joined by acting; set = they were asked by that user.
- A person is asked through `Store.Assign` (`participants.go`, `POST /tasks/{uid}/participants`, audited `ActionTaskAssign`) and through `participants` at task creation (`store_write.go`, `askParticipants`).
- The only signal today is the daily `task_digest` mail (`internal/taskdigestjob`). It stays as it is: it is a separate digest with its own config, not this kind.

## What to build
1. Add the kind to the registry (all defaults off), i18n for the preferences grid (cs + en), and a Czech mail template.
2. Notify in the **same transaction** as the assignment, both for `Assign` and for `askParticipants` at creation, through `notification.Deliver`. Better still, use an observer like the people store's TagObserver, so `phototask` doesn't import notification directly. Follow whichever pattern the codebase prefers.
3. Rules:
   - never notify the person who asked themselves (self-assign);
   - joining by acting (`added_by` null) is not an assignment → no notification;
   - re-asking someone already on the task → no duplicate;
   - a disabled account → none.
4. Tests:
   - unit tests for the rules;
   - integration test: create with participants → each asked person (minus the creator) gets one; `Assign` → one; self → none; repeat → none.
5. Docs: `docs/PACKAGES.md`, `README.md`.
