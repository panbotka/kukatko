# Reflow the Import-history and Maintenance-result tables into stacked cards on mobile

The import run-history table and the maintenance scan-result table are multi-column and
only horizontal-scroll on a phone. Reflow them to stacked cards on small screens.

## Current behavior

- `web/src/pages/ImportPage.tsx` (~line 196): the `RunHistoryTable` of past import runs.
- `web/src/pages/MaintenancePage.tsx` (~line 112): the `ScanResult` table.
- Both are `<Table responsive>` (`.table-responsive`, `overflow-x:auto`) — no page-level
  overflow, but a many-column table is awkward to read on a phone (later columns
  off-screen, must scroll sideways).

## Requirements

- Below a small breakpoint (phones), render each run-history row and each scan-result
  row as a stacked "label: value" card (one record = one card) instead of a wide
  scrolling table; keep the full table for tablet/desktop.
- Preserve all existing behavior and any per-row status/detail — presentation reflow
  only.
- If a reusable "responsive table → cards" helper already exists in the codebase, use
  it; otherwise implement a small typed one (no `any`) consistent with the app's
  component conventions.

## Testing

- Add/update Vitest tests asserting the mobile card layout and the desktop table both
  render.
- `make check` must pass. Update `docs/FRONTEND.md` if a shared component is added.
