# Release binaries must stop being stamped +dirty

Every published release binary claims it was built from a modified working tree, which destroys the only provenance signal the binary carries.

## Evidence (verified 2026-08-12 against the published artifact)

Downloading `kukatko_0.8.0_linux_amd64.tar.gz` from the v0.8.0 release and inspecting it:

```
go version -m ./kukatko
  ./kukatko: go1.26.5
  mod  github.com/panbotka/kukatko  v0.8.0+dirty
```

The cause chain is confirmed:

1. `.goreleaser.yaml:10` runs `sh -c "cd web && npm ci && npm run build"` as a before-hook.
2. The vite build empties `internal/web/static/dist/`, which includes `.gitkeep` — and that file **is tracked** (`git ls-files internal/web/static/dist/` returns it).
3. Go's VCS stamping sees a deleted tracked file and stamps the module version `+dirty`.

Why it matters: `+dirty` is how a binary says "I do not correspond exactly to that tag". When every release carries it, it stops distinguishing anything, and a genuinely dirty build becomes indistinguishable from a clean one.

## Requirements

- A release built from a clean checkout of a tag produces a binary whose module version has no `+dirty` suffix.
- A release genuinely built from a modified tree still gets `+dirty` — the fix must not simply disable VCS stamping.
- `go build ./...` still works on a fresh clone with no frontend build run (this is why `.gitkeep` is tracked — `go:embed` needs the directory to exist).
- The chosen approach is written down where the next person will look: a comment at the point of the fix, plus `docs/OPERATIONS.md` if it changes how a release is cut.

## Implementation Notes

Options worth weighing: restore the file after the frontend build inside the hook; configure vite so the output directory is not emptied wholesale; or stop tracking `.gitkeep` and have the build create the directory (only if the `go:embed` requirement above stays satisfied).

## Constraints

- **No mutable operations against production data.** This task does not touch the running instance at all.
- Do not cut an actual release as part of this task. Prove the fix by inspecting a locally built binary with `go version -m`.
- `make check` must pass. `make check-box` runs the same gate on the build box and is much faster.
