# Photo writes and media are scoped by project

## Context

Kukátko is multi-tenant. The read side of `internal/photos`/`photoapi` is already scoped (store methods take `projectUID` after `ctx`, typed `photos.ErrNoProject`, foreign uid = 404 same shape as missing; the convention is documented in `docs/PACKAGES.md` under `internal/photos`). `auth.ProjectUIDFromContext(ctx)` gives the project; `internal/projecttest` is the isolation harness. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4, 3.1, 6. Step 12 of 40.

## Requirements

- `internal/photos.Store` write methods take `projectUID` and verify the target photo belongs to it (an `UPDATE … WHERE uid = $1 AND project_id = $2` that affects 0 rows → `ErrNotFound`): edit metadata (title, description, taken_at, location, orientation…), rating, favourite, archive/restore, visibility (private/hidden), photo edits (crop/rotate…), comments create/delete on a photo, stack/unstack (if in this package), set primary, the `photo_files` writers used by ingest. Child-table writes verify the parent photo's project in the same statement or transaction.
- Media bytes in `internal/photoapi`: thumbnail, download, rendition/HLS playlist and segment routes, face crop (`GET /photos/{uid}/face`), storyboard — each looks the photo up **with the project** before serving a byte or minting a signed URL. `RequireAuthOrDownloadToken` routes included.
- `internal/mediaurl`: `thumb_url`/`download_url` are built with the API base of the current request (`auth.APIBase(ctx)` from the prefix step) or the signed CDN URL; signed URLs are only ever minted for photos of the current project (the caller passes rows it already filtered — add a defensive check that the row's `project_id` equals the context project and a test for it).
- Worker loaders: background job handlers (`thumbjob`, `embedjob`, `facejob`, `metajob`, `ocrjob`, `sidecarjob`, `placesjob`, `storyboardjob`, `hlsjob`, `tagnotifyjob`) load photos by uid without a request context. Give `internal/photos` explicit, clearly named unscoped loaders `GetForJob(ctx, uid)` / `FilesForJob(ctx, uid)` (returning the row **including** `project_id`) and switch the handlers to them. Enforce with a unit test that walks every `internal/*api` package source and fails if `ForJob(` appears there.
- Isolation tests: HTTP — edit, rate, favourite, archive, comment, thumbnail, download, face crop on a foreign photo → 404 same shape; store — a write on a foreign uid returns `ErrNotFound` and changes nothing (assert the row is unchanged).
- Docs: `docs/PACKAGES.md` (`internal/photos` ForJob loaders, `internal/mediaurl`), `docs/API.md`.

## Out of scope

Ingest (its own step), albums/labels/people packages, trash/purge, stacks detection.
