# Navigation on top or on the left — the user's choice

Today the desktop navigation is a horizontal navbar at the top (`web/src/components/Layout.tsx`, items from `navItems`), shown from 992 px up; phones use the bottom tab bar plus the offcanvas drawer (`MobileNavDrawer.tsx`). Owner request (2026-10-16): support **both** a top bar and a left sidebar, let each person pick, keep the top bar as the default.

## Requirements
- **Preference:** a setting "Umístění menu: nahoře / vlevo" (en: "Menu position: top / left") on the account page (`/account`), applied immediately without a reload. Default = top. Store it the same way the UI language is stored (`web/src/i18n/accountLanguage.ts`): per account in the browser, keyed by the account uid, not cleared at sign-out, every storage access wrapped so a blocked/empty storage simply falls back to the default. No server change.
- **Left sidebar (desktop, ≥ 992 px):** a fixed-width vertical sidebar holding the same destinations, groups and order as the top bar and its dropdowns (main items, Procházet, Nástroje, admin/maintainer items, the account menu, notifications bell, search, keyboard-shortcuts button, current project identity and the project switch entry). Groups can be section headings or collapsible groups rather than dropdowns. Active route highlighted, keyboard navigable, badges (tasks waiting, unread notifications, unread in other projects) shown just like in the top bar. Optionally collapsible to an icon-only rail (remember that per account too) — nice to have, not required.
- **One source of truth:** both layouts render from the same `navItems` definitions and the same role/visibility rules; no destination may exist in one layout and not the other (extend `navItems.test` to prove parity).
- **Content area:** with the sidebar, the page content shifts right and keeps its own container; nothing may slide under the sidebar — sticky toolbars, the photo viewer (full-screen, must cover the sidebar), modals/offcanvas, the upload rail, the batch dock, toasts and the announcement banner all keep working. Respect the existing z-index ladder documented in `docs/FRONTEND.md`.
- **Phones and narrow screens (< 992 px):** unchanged — bottom tab bar + drawer regardless of the preference.
- Colours only via palette tokens (`styles/palette.css`, contrast test), icons only via `Icon`, all texts cs + en.
- Use the frontend-design skill for the sidebar's visual design so it matches the existing Superhero-based look.
- Tests (vitest): default is top; switching to left renders the sidebar and persists per account (two accounts in one browser keep separate choices); storage failure falls back to top; nav parity between layouts; the mobile layout ignores the preference.
- Verify visually at 1440 px and 1024 px in both layouts (library, photo viewer, a modal, an admin page) and at 390 px; update `docs/FRONTEND.md` and the user-visible feature list in `README.md`.
