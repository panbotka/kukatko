# Moving a project's objects under its prefix — the model

## Context

Kukátko is multi-tenant. The bootstrap project `v` still has `storage_prefix = ''` and ~21k originals (78 GB on Cloudflare R2 in production) at the bucket root; new projects use `projects/<uid>/`. Every reader derives a photo's derived-object layout from the photo's own `file_path`, so the move can be done **one photo at a time while the app runs**. `internal/storagemigrate` already implements a similar move (fs → r2: copy, verify, commit the row, only then delete) — study it and reuse its helpers. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 5.3. Step 33 of 40; the worker job, CLI and API are the next step, the UI the one after.

**Owner's hard rule: copy first, verify, commit the row, and only then delete the old object. Never delete the only copy.**

## Requirements

- `internal/storage`: add `Copy(ctx, from, to string) error` to the storage interface with an fs implementation (hard link or copy) and an r2 implementation (server-side `CopyObject`; objects over 5 GB use multipart copy — implement or return a typed `ErrTooLargeToCopy` that the service records as an error for that photo); `Stat(ctx, key) (size, etag)` if not present. Fakes for tests.
- Migration: table `storage_rekey_runs` — `uid`, `project_uid` FK, `state` CHECK (`running`,`paused`,`done`,`failed`), `total_photos`, `done_photos`, `total_bytes`, `done_bytes`, `last_key`, `errors` JSONB (ring of the last 50 `{key, message, at}`), `error_count`, `started_at`, `updated_at`, `finished_at`. Preserved in `internal/reset/tables.go`.
- Package `internal/rekey`:
  - pure `Plan(photo PhotoFiles, newPrefix string) []Move{From, To string; Kind storekeys.Kind}` listing the original, every thumbnail size from the thumb config, the HLS files of every recorded rendition, and the sidecar — the new key is `storekeys.Join(newPrefix, storekeys.Strip(old))`.
  - `Service` with `Start(ctx, projectUID)` (refuses when the project already has a non-empty prefix and no run exists, or a run is `running`/`paused`; sets `projects.storage_prefix = 'projects/<uid>/'` so **new uploads land in the new layout at once**; inserts the run with totals = count and `sum(file_size)` of photos whose `file_path` lacks the prefix; returns the run), `Pause`, `Resume`, `Retry` (`failed` → `running`), `Status(ctx, projectUID)`, and `Step(ctx, run, batchSize) (processed int, done bool, err)` — the unit of work the job calls.
  - `Step` processes photos whose `file_path` lacks the prefix, ordered by `file_path`, and for each: (1) if the destination original does not exist, `Copy`; (2) **verify** the destination: `Stat` size equals `photos.file_size` and the ETag equals the MD5 of the source when single-part, else stream the destination and compare SHA-256 with `file_hash`; (3) in one transaction update `photos.file_path` and `photo_files`; (4) copy the derived objects from the plan that exist (skip missing silently); (5) delete the old original and old derived objects **only now**; (6) update the run counters and `last_key`. Any failure on one photo is appended to `errors`, the photo is skipped, the run continues; `error_count > 100` flips the run to `failed`.
  - Idempotent and resumable: a crash between any two steps leaves either both copies or the new one; a re-run re-verifies before deleting; a photo whose row already points at the prefixed key but whose old object still exists just deletes the old object after verifying the new one.
  - `Finish(ctx, run)` when no unprefixed photo remains: enqueue `family_export` for the project and `sidecar` jobs (force) for every photo of the project; delete the root `families.yaml` and the root `sidecars/` tree **only after** listing shows their prefixed replacements exist; mark `done`.
- Tests (integration with the fake storage): a full run; crash after copy before commit (re-run completes, no loss); crash after commit before delete; verification failure (old kept, error recorded, run continues); `error_count` threshold; pause/resume; Start refusals; and an invariant checker run after **every** step: every `photos.file_path` points at an existing object with the right size.
- Docs: `docs/PACKAGES.md` (`internal/rekey`, storage `Copy`), `docs/ARCHITECTURE.md` (the move), `CLAUDE.md` package map line.

## Out of scope

The worker job type, CLI, HTTP API, UI (next steps). Do not start a move anywhere.
