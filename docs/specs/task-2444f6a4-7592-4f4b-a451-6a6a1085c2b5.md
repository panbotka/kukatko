# Curator role 2/5 — people and faces

Move the 28 endpoints of the people-and-faces curation surface from `RequireWrite` to the
`RequireCurator` gate added in step 1.

Read `docs/superpowers/specs/2026-09-26-curator-role-design.md` section 3 before starting.
Requires step 1 (`RoleCurator`, `CanCurate`, `RequireCurator`) to be merged.

## Requirements

- Move to `RequireCurator`, and nothing else in these packages:
  - `internal/photoapi`: `POST /photos/{uid}/faces/assign`, `POST /photos/{uid}/people`,
    `DELETE /photos/{uid}/people/{subjectUID}` — the other 11 write routes stay.
  - `internal/peopleapi`: all four writes, including `DELETE /subjects/{uid}` and
    `POST /subjects/{uid}/merge`.
  - `internal/familyapi`: all three.
  - `internal/clusterapi`: all three.
  - `internal/reviewapi`: `GET /review/queue` and `POST /review/answer`.
  - `internal/sweepapi`, `internal/candidatesapi`, `internal/outlierapi`: one each.
  - `internal/dupmarkersapi`: `keep` and `invalid`.
  - `internal/feedbackapi`: `POST` and `DELETE` of `face-rejections`,
    `face-confirmations`, `label-rejections` and `duplicate-marker-dismissals` — eight
    routes. The four `duplicate-dismissals` / `duplicate-confirmations` routes stay on
    `RequireWrite`, because they are about near-duplicate photos, not faces.
- Each package takes the new guard as an injected `func(http.Handler) http.Handler` config
  field, wired in `cmd/kukatko`, exactly as its existing guards are.
- A viewer must still get 403 on every one of these routes.
- Tests: add a curator case to the role-boundary test each touched package already has.
  It must assert that a curator reaches the moved routes and is refused on at least one
  route of that package that did not move (where the package has one). This is the only
  thing that proves the wiring rather than the intent.
- Docs: the guard column of every moved route in `docs/API.md`.

## Implementation notes

- The `GET`s here (`/faces/clusters`, `/review/queue`, `/faces/sweep`,
  `/subjects/{uid}/outliers`) are gated because they lead into a write flow, not because
  they mutate. They move with the flow they belong to.
- Known pre-existing failure: `web/src/pages/ReviewPage.test.tsx`, case "leaves no
  snapshot behind a finished round", fails on main under the full vitest suite and passes
  in isolation. If `make check` is red only there, it is not this task's regression.
