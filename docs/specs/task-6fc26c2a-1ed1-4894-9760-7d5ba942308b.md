# The outlier faces section should read as a question, not a fault report

At the bottom of a person's page the outlier faces (the ones furthest from that person's
centroid) are presented as a wall. Measured on the live instance: about thirty tiles were
visible at once out of roughly 290 in the section, each captioned with a raw cosine distance
such as 0.288 or 0.317, under a hedge of red "Není to tato osoba" buttons; many tiles never
loaded their image and stayed as empty grey squares. The section looks broken and invites
mis-clicks, and the numbers mean nothing to anyone who is not the developer.

The instance is live and holds real family photographs; opening the section must not change
any assignment on its own.

## Requirements

- Present the outliers a few at a time — a small batch with an explicit way to see more —
  instead of one long wall.
- Replace the raw distance numbers in the interface with plain language (for example
  "least like the others" ordering). If the number is still useful for diagnosis, keep it in a
  tooltip rather than as the tile's caption.
- Every tile shows the face it is asking about. No empty placeholders: images load lazily as
  the reader reaches them, and a face that cannot be rendered is not offered as a question.
- Each face tile must request an image of roughly the size it is displayed at. Today the tile
  downloads the entire photograph (measured: a 1280 x 960 rendition scaled to about
  2271 x 1703 and then clipped to a 96 x 96 window), which is what leaves the grey squares
  behind. If the API offers a small server-side face crop, use it; if it does not, request the
  smallest rendition that still yields a sharp crop, and never a `tile_*` rendition — those are
  centre-cropped squares, so a face's bounding box lands on the wrong part of the picture.
- Rejecting a face can be undone immediately afterwards, from the same place.
- The rejection control must not dominate the section. The reader is being asked a question
  ("is this still the same person?"), and the section should look like one; today's row of red
  buttons reads as an error state.
- The section stays read-only until the reader acts.

## Edge cases

- A person with fewer outliers than one batch.
- A person with none at all — show nothing rather than an empty frame.
- A rejection that leaves the person with no photographs in the section.
