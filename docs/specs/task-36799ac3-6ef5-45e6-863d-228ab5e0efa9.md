# Upload-link page: hide zero-count status chips and show one offline banner

Found in the v0.30 prerelease walkthrough (staging 54a1504, iPhone 12 emulation, anonymous). The `/u/:code` page is meant to be foolproof for people who have never seen the app, but two things add noise:

1. **Zero-count chips.** Next to "Podrobnosti" the page always shows "0 nahráno | 0 duplikát | 0 selhalo": a green, a yellow and a **red** chip, during the upload and on the done screen too. A red "0 selhalo" reads as an error at a glance. Screenshots: `13-u-done.png` and `12-u-uploading.png`.
2. **Two offline banners.** With the network off, the page shows its own "Jste offline — počkám na připojení." (formal "vy") **and** the app-wide banner "Jsi offline. Kukátko se otevře, ale fotky a knihovna potřebují připojení." (informal "ty", and about the library, which an anonymous uploader cannot even open). Screenshot `14-u-offline.png`.

## Requirements
- On `/u/:code`, a status chip with count 0 is not rendered. When everything is 0, there are no chips at all. The "duplikát" chip appears only when there is a duplicate, and the red one only when something actually failed. Check that `/upload` stays as it is, unless the same rule clearly fits there too.
- On `/u/:code`, only the page's own offline banner shows, and the app-wide offline banner is suppressed on this public route. Decide where that belongs (e.g. the global banner skips routes outside `Layout`) and document it.
- The done screen with all files duplicate ("Hotovo, nahráno 8 fotek" + "0 nahráno, 8 duplicit") reads consistently. E.g. "Hotovo — všech 8 fotek už v knihovně bylo". Pick the wording.
- Vitest for the chip visibility and the single banner. i18n cs + en. Update `docs/FRONTEND.md`.
