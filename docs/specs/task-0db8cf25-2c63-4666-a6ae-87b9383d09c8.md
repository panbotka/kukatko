## Routes

    GET    /subjects/{uid}/relations           RequireAuth
    POST   /subjects/{uid}/relations           RequireWrite
    DELETE /subjects/{uid}/relations/{uid2}    RequireWrite
    GET    /subjects/{uid}/tree                RequireAuth
    PATCH  /families/{uid}                     RequireWrite

`GET /subjects/{uid}/tree` takes `?direction=descendants|ancestors` and `&generations=N`.

Flat chi patterns, no `chi.Mount` — peopleapi is deliberately flat so that outlierapi can
hang `GET /subjects/{uid}/outliers` off the same prefix. Copy peopleapi's shape: guards
injected as `func(http.Handler) http.Handler` from Config, stores behind interfaces so the
tests keep working with fakes.

`GET /subjects/{uid}/relations` returns the four derived lists (parents, siblings, partners,
children), each entry carrying the subject plus its cover and photo count, so the strip in
task 3 renders from one response.

## The POST body

Takes either an existing `subject_uid` OR an inline `new_subject`, and creates the subject
and the relation in ONE audited transaction:

    {"role": "parent", "new_subject": {"name": "Marie Nečasová", "birth_year": 1921}}

This is the affordance that makes filling the tree bearable (design section 10). It is not
optional and it must be atomic: a failed relation must leave no orphan subject behind.

## Wiring

`buildServices` in cmd/kukatko sits at the funlen limit, so a fresh `server.WithAPI(...)`
line fails lint. Mount these routes through the existing peopleapi options helper instead.

## Audit

New actions in internal/audit: `subject.relation.add`, `subject.relation.remove`,
`family.update`. Follow peopleapi's pattern — `a.auditEntry(r, action, targetUID, details)`,
plus a ChangeSet diff via `.StampInto(details)` for the PATCH.

## Tests

Integration over the real test DB for every route, including: RBAC refusals (a viewer gets
403 on every write), the inline `new_subject` path being atomic, 404 for an unknown subject,
and the cycle refusal surfacing as a 409 rather than a 500. Integration tests need `-p 1`,
and run `go vet -tags integration ./...` before the gate.
