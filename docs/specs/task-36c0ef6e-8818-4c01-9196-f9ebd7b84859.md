# Two competing date filters, and the visible one cannot express a decade

The library's primary control row has a **Rok** dropdown — a native `<select>` with **109
entries** (2026 down to 1905, with gaps: 1964 is missing, so is 1992). Exactly one year can
be selected. One click deeper, in the **Filtry** panel, sits a second pair of fields,
**Pořízeno od / Pořízeno do**, which does support a range.

For the task "find grandma's photos from the sixties" the visible control is not enough — a
decade cannot be assembled from it — and the control that is enough is hidden. The fastest
route turned out to be typing `year:1960-1969` into the search field.

The filters also do not synchronise: with `year:1960-1969` in the query, **Rok** still reads
"Libovolný rok".

This library reaches back to 1905. For this collection the time range is the main axis of
search, and the primary control on that axis cannot express what people want (a decade,
"before 1950", "summer 2019").

## Requirements
- Replace **Rok** with a period filter: a list of decades (`1960–1969`) expandable to
  individual years, or a "from year / to year" pair. Only years present in the library are
  offered, as today.
- Unify it with **Pořízeno od / do** so there are not two filters for the same thing. One
  control, reachable from the primary row.
- Derive the control's displayed state from the query, so a `year:` token in the search field
  and the control can never contradict each other.
- The state stays in the URL, as with the other filters.
- `web/src/components/library/timelineRail.ts` already computes labelled ranges for the
  timeline; reuse its range logic where it fits rather than duplicating it.

## Where it is
`web/src/components/library/FilterBar.tsx`, `web/src/hooks/useLibraryFacets.ts`,
`web/src/components/library/timelineRail.ts`.

## Out of scope
No query-language changes, no data changes.
