# 438 albums in one undifferentiated pile, although the API already distinguishes them

`/albums` renders one flat, unsorted, unfilterable grid of cards. On the live instance
`GET /api/v1/albums?limit=1000` returns 438 albums that already carry a `type` field:

| `type` | count | what it is |
| --- | ---: | --- |
| `folder` | 246 | machine-made albums by month and by import |
| `album` | 166 | albums somebody actually created |
| `moment` | 23 | machine-made "moments" |
| `state` | 3 | regions |

239 of them are named in English in the shape `January 2026`, `May 2026`. Six are empty and
also English (`Pets`, `Nature & Landscape`, `Bays, Capes & Beaches` — leftovers from
PhotoPrism categories). Another 34 hold fewer than three photos.

Albums are the second menu item. Somebody opens them to find "Dovolená 2019" and gets 438
tiles of which 55 % are English machine groups, with no search, no sorting and no paging
(the virtualized grid scrolls 16 232 px). The distinction is already in the data — the UI
just ignores it.

## Requirements
- Split the page into sections or tabs by `type`: **Moje alba** (`album`, the default view)
  · **Podle měsíce** (`folder`) · **Momenty** (`moment`) · **Místa** (`state`). The default
  view then shows 166 albums instead of 438.
- Add a search field over album names and a sort selector (name / photo count / date).
- Hide albums with `photo_count = 0` in the default view (a toggle to show them is fine).
- Render machine-made names in Czech **at display time only**: map a leading English month
  name to its Czech equivalent and known country names likewise, falling back to the raw
  name whenever the pattern does not match exactly. Never touch stored names.
- Keep the grid virtualized and the view state in the URL, as elsewhere in the app.

## Where it is
`web/src/pages/AlbumsPage.tsx` (does not use `type` from the API response today),
`web/src/i18n` for the month/country display names.

## Out of scope — important
**No data changes at all.** No migration renaming albums in the database, no recomputation
of month albums from `taken_at`, no deletion of empty albums. Display only.
