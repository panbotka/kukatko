# View Transitions Between Grid and Photo Detail

Opening a photo should feel like the tile grows into the detail view, not like a page swap.

## Requirements

- Navigating grid → photo detail (and back) animates via the native View Transitions API: the clicked thumbnail morphs into the detail image, and back again on close/back.
- Progressive enhancement: browsers without the API get exactly today's instant navigation; no polyfill.
- `prefers-reduced-motion` disables the morph.
- Back/forward navigation, URL state, and scroll restoration keep working exactly as today ("back always works" is a hard project rule — verify it explicitly).
- The morph must not delay interactivity: navigation stays as fast as before; the animation is short (~200–300 ms).
- Optionally apply the same pattern to album card → album detail, but only if it is nearly free once the plumbing exists.

## Implementation notes

- The router integration is the tricky part (wrapping navigation in startViewTransition with the app's router); keep it in one place so future routes opt in with just a `view-transition-name`.
- jsdom cannot test the animation: test the fallback path in vitest, and verify the morph via a real browser probe (agent-browser) with evidence.
