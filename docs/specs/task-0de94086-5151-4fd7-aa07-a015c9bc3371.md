# Unified review-tool UX — phases B, C and D

Give every review tool the same three things: a photo you can enlarge, a grid density
stepper, and one way out to the photo's own page. Phase A (the shared primitives) is
already on `main`; this task is the rollout.

**Read first:** `docs/superpowers/specs/2026-08-10-review-tools-shared-ux-design.md` (the
design and the reasoning) and `docs/superpowers/plans/2026-08-10-review-tools-shared-ux.md`
(the task breakdown, file by file). They are the source of truth; this spec is the summary.

## What already exists on `main` (do not rebuild)

- `components/review/ReviewStage.tsx` — the photo stage shared with the review game:
  measured frame, padded face rectangle, corner anchor out to the photo's page.
- `components/review/ReviewLightbox.tsx` — the overlay around it; `Esc` closes, `←`/`→`
  step, `o` opens the photo in a new tab, the caller's decision buttons go in the footer.
- `hooks/useLightbox.ts` — which item of a list is enlarged; stops at both ends, returns
  focus to the card it was opened from.
- `REVIEW_GRID_SCOPE` in `lib/gridDensity.ts` — one stored column count for every review tool.

## Requirements

- **Phase B — `/faces`, `/recognition`, `/expand`.** All three drop their hard-coded
  `minmax(16rem, 1fr)` / `minmax(14rem, 1fr)` grids for `gridTemplateColumns(density)` off
  `REVIEW_GRID_SCOPE`, and each shows `GridDensityControl` with that scope in its results
  header. Clicking a card's photo opens the lightbox on that item; the lightbox's footer
  carries the same confirm/reject buttons the card has and calls the same handlers.
- **Phase C — `/outliers`.** Same two changes. The card's small „Otevřít fotku" text link
  is removed: the lightbox's corner anchor is now the one way out, as on every other tool.
- **Phase D — `/people/clusters`, `/duplicates`, `/duplicate-markers`.** Lightbox on every
  photo. The stage always requests a `fit_*` size, never the card's square `tile_224` —
  a centre-cropped square is exactly what cannot be judged. Density controls the cluster
  grid on `/people/clusters` and the member grid inside a group card on the two duplicate
  pages; verify in a browser that this reads well before committing, it is the one
  judgement in the design made without seeing it.
- While the lightbox is open the page's own grid shortcuts must not fire — pass
  `enabled: !lightbox.isOpen` to `useKeyboardShortcuts`, as the pages already do for a
  running „confirm all".
- Every new string is in both `cs` and `en`. No page loses an existing capability
  (selection bars, batch confirm, keyboard flow, filter tabs all keep working).
- Each phase is its own commit with `make check` green; `make dev` before the last one.
- Docs updated per `CLAUDE.md`: `docs/FRONTEND.md` for every touched component/page.

## Acceptance

- On each of the seven tools: the stepper changes the number of columns and the choice
  survives a reload; clicking a photo enlarges it; `Esc` returns to the grid with the
  focus back on the card; deciding from inside the lightbox writes exactly what the card
  writes.
- Verified in a real browser signed in as the maintainer account (`panbotka`, item
  „Kukatko" in the 1Password vault „Pan Botka"), driving this tree's frontend against the
  production API through a throwaway Vite proxy — the technique in the plan's last section.
  These pages are editor-gated, so the read-only `ux-research` account cannot see them.
