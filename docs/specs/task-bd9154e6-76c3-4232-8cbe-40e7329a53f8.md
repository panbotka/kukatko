## The defect

`GET /import/verify` reports, on a catalogue holding 280 photos against a source of 20 670:

    "vectors": {
      "source_photos_with_embeddings": 20092,
      "catalog_embeddings": 50,
      "missing_embeddings_count": 0,      <-- reads as "embeddings are done"
      "missing_faces_count": 0
    }

The counters are computed over photos ALREADY in the catalogue, which is defensible — a
vector cannot attach to a photo that was never imported — but the field name says
"missing embeddings: 0" while 20 042 photos of the source have embeddings that Kukatko does
not. Only the top-level `complete: false` contradicts it.

## Why it matters

This is read by a human at the point of no return, and by `kukatko import verify` output. A
reviewer skimming the report sees zeros next to the vector section and concludes the vector
migration is finished.

## Fix direction

Rename or re-scope so the semantics are unmistakable, e.g. `missing_for_imported_photos` plus
a separate `source_coverage` (catalog_embeddings / source_photos_with_embeddings). Keep the
existing defensible computation; the problem is naming and presentation, not arithmetic.
Update docs/API.md and the CLI output together.

## Verification (mandatory)

- A test on a catalogue that is a strict subset of the source, asserting the report cannot be
  read as complete coverage (the coverage figure is < 1 while the per-photo gap is 0).
- `make check` green.
- docs/API.md updated for the changed response shape.
