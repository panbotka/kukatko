# Search History and Query Suggestions

Make repeated searching faster: remember what a user searched and suggest values for query-language keys.

## Requirements
- **Recent searches:** when the search input on the Search page or in the global command palette is focused and empty, show the user's recent searches (most recent first, deduplicated, max 20). Clicking one runs it. A "clear history" affordance exists.
- History is stored server-side per user so it works across devices. A search is recorded when it is actually executed (not on every keystroke). Strictly per-user: nobody can read another user's history.
- **Value suggestions:** while typing a `key:` token (`person:`, `label:`, `album:`), suggest matching values from the existing facet/list data — prefix match, diacritics-insensitive, keyboard-navigable, and inserting the properly quoted value into the query.
- Suggestions are debounced (no request per keystroke) and never block typing; no suggestions must not feel broken (graceful empty dropdown).
- Works in both Czech and English UI.
- Integration tests for the history endpoints (record, dedup, cap at 20, clear, per-user isolation); component tests for both dropdown behaviors (history on empty focus, values while typing, keyboard navigation).
