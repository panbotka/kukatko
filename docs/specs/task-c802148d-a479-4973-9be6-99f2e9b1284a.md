# De-duplicate the passkey-off WARN

The relying party may be derived from `mail.base_url`. When that URL is an IP address or a single-label host, the server now logs one WARN at startup and turns passkeys off, which is correct behaviour. The WARN's `error` attribute, however, repeats the same wrapping prefix twice. Seen on box staging in pre-release walk VI:

`"error":"building the passkey relying party: auth: building the passkey relying party: error occurred validating the configuration: field 'RPID' is not a valid domain string: …"`

## Requirements

- The error chain names the step once. Either the caller in `cmd/kukatko/auth.go` stops re-wrapping with the same words, or the `internal/auth` constructor stops. Keep the package prefix convention used elsewhere in the code base.
- Any other error that passes through the same two wrappers (an explicitly configured but invalid `auth.passkey.rp_id`, which still fails startup) must not repeat the phrase either.
- The WARN message itself and its `rp_id` attribute stay as they are.
- Add or adjust a test in `cmd/kukatko/auth_test.go` (or `internal/auth`) asserting that the phrase "building the passkey relying party" occurs exactly once in the error text.
- `make check` must pass.
