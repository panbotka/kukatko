# Make unchecked switches and checkboxes visible on the new palette

Found in the v0.29 prerelease walkthrough (box staging, commit c2f7eb7).

Since the navy/teal/cream/orange/rust palette (d8fe125), an **unchecked** `.form-switch` / `.form-check-input` is nearly invisible: the track/box takes the dark input background (computed `color(srgb 0 0.049 0.085)`) on a dark card panel (`color(srgb 0.015 0.136 0.193)`), and the off-knob is Bootstrap's `rgba(255,255,255,.25)` circle. Superhero used to paint inputs light, so this was not an issue before the palette swap.

## Reproduce
- `/settings` → "Povolit vlastní registraci" (off) — screenshot `/tmp/claude-1000/-home-pi-projects-kukatko/e1859691-8352-48a1-a30b-9400f72ae1fe/scratchpad/30-crop.png`
- `/users?all=1` → "Jen čekající na schválení" switched off (desktop and phone)
- `/maintenance` → the unchecked checkboxes under "Co opravit" (`sweep-maintenance.png` in the same scratchpad)

## Requirements
- An unchecked switch and checkbox must be clearly visible on every surface they appear on (body, card, modal, offcanvas): border/track and knob meet **WCAG ≥ 3:1** against the surface (non-text UI component), in the default and the disabled-but-readable state; focus ring unchanged.
- Colours only via `styles/palette.css` tokens / `var()` / `color-mix()` — no literals (`colourLiterals.test.ts`); the knob SVG `--bs-form-switch-bg` must derive from a token too.
- Extend `styles/contrast.test.ts` with the unchecked-control pairs so a future palette swap cannot regress it.
- Verify visually on the screens above, desktop and phone; checked state stays as it is (orange).
