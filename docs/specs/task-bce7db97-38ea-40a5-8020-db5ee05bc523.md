# Human Search Language

Three related fixes to the main search flow:

1. The search-mode names "Hybrid / Full-text / Semantic" are the last raw technical terms in the app's main flow (docs/UX_AUDIT.md backlog item about search-mode naming).
2. The FilterBar suggests the query language is unsupported and stays silent on typos (finding N2 in docs/UX_RESEARCH.md).
3. An empty search result says just a bare zero photo count (finding N25 in docs/UX_RESEARCH.md).

## Requirements

- Rename the search modes to words a non-technical family member understands (Czech first) and/or tuck the mode switch behind an unobtrusive "advanced" affordance; hybrid stays the default. Read the audit item first and respect its intent.
- When a query contains an unknown `key:value` token, show gentle inline feedback near the search box suggesting the closest valid key (e.g. "person:" for "persn:"), while keeping the existing graceful degradation to free text. Never block or fail the search because of a typo.
- Replace the bare zero-count empty state with a friendly one offering concrete next steps: clear filters, check spelling, try describing the photo instead (semantic search).
- All copy via i18n (cs default + en).

- The query language keys are already known to the frontend (autocomplete); reuse that list for the typo suggestion — no backend change expected.
