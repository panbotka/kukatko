# Two statistics charts are permanently empty for a library filled by one import

Two panels on `/stats` render correctly and are useless, because this library's arrival history is a single point. One of them looks like a rendering failure.

## Evidence (observed on production, 2026-08-12)

- **"Rust knihovny"** ("Kolik knihovna zabirala na konci kazdeho roku") draws as one solid blue rectangle filling the whole card, labelled `2026`. `storage_by_year` has exactly one row, because every photo arrived in one migration.
- **"Prirustky knihovny"** ("poslednich dvanact mesicu") is eleven zero-height months and one full-height bar: `added_by_month` is eleven `{photos: 0}` entries followed by `{2026-08: 20890}`. Sitting beside the ten-row "Nejcastejsi fotoaparaty" card, it stretches and leaves roughly 470 px of dead space under the axis labels.

Both are faithful renderings of the data. The point is that a library filled by one import will always produce this shape, so these two panels are permanently uninformative — and the first one reads as broken software rather than as an honest chart.

Source: `web/src/components/stats/LibraryChartsPanel.tsx`, series from `GET /system/stats/charts`.

## Requirements

- A growth series with a single data point is not drawn as a chart; it is stated as a sentence instead.
- An arrivals series where only one month is non-zero is either reshaped into something that carries information, or omitted, rather than drawn as eleven zeros.
- Neither panel leaves a large empty region when its neighbour in the row is tall.
- The behaviour is driven by the shape of the data, not by hard-coded knowledge of this instance — a library that really did grow over five years still gets its chart.
- Tests cover the degenerate shapes: one point, all-but-one zero, and the ordinary multi-point case.

## Constraints

- **No mutable operations against production data.** Read-only reads of the stats endpoints are fine; writes are not.
- `make check` must pass. `make check-box` runs the same gate on the build box and is much faster.
