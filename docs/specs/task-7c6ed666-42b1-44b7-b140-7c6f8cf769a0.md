# Tasks: a review ledger

A batch task in state `review` ("Dávka: rekruti (61 fotek)") asks a human to approve what an agent changed on a frozen group of photos. The task page shows the group as a thumbnail grid and nothing else. The agent's convention is: every changed photo carries a comment explaining what was done and why, and the change itself is the photo's `taken_at` (with `taken_at_precision`, `taken_at_source`, `taken_at_estimated`). To review 61 photos the human currently opens 61 details. This task adds a list view of the group that shows, per photo, what the reviewer needs on one line.

## Backend

- When the photo listing is scoped to a task (`GET /photos?task={uid}`, `ListParams.TaskUIDs` in `internal/photos`), every item additionally carries `last_comment`: `{uid, body, author_uid, author_name, created_at}` of the newest live comment on that photo, or `null`. Fetch it in one query for the page (a LATERAL join or one grouped query), never per row. Outside a task scope the field is absent, so the ordinary library listing stays as cheap as it is.
- The items already carry `taken_at`, `taken_at_precision`, `taken_at_source`, `taken_at_estimated`, `title`, `file_name`; keep them.
- `kukatko ctl tasks ledger <uid>` prints the same rows as a table: `UID`, `TAKEN` (rendered with precision: `1974-06-14`, `1974-06`, `1974`, `1970s`), `SOURCE`, `LAST COMMENT` (first line, truncated to the terminal-friendly width) and `BY`. It pages through the whole group (the group is capped at 1000). `-o llm` gives the compact rows. The agent uses it as its own final check before moving a batch to `review`.

## Web

- `/tasks/{uid}` gets a view toggle next to the density control: grid (default) and list ("Přehled" / "List"), persisted in the URL as `view=list` like the other view state.
- The list is virtualized with `react-virtuoso`. Each row: thumbnail (`tile_100`), title or file name, the date rendered with its precision (cs: `14. 6. 1974`, `červen 1974`, `1974`, `70. léta`; en equivalents) with a small badge for the source (`manual`, `exif`, `estimate`…) and the estimated flag, then the last comment excerpt (first 200 characters, single line) with author and relative time. No date = "bez data" in muted text.
- Clicking a row opens the viewer for that photo with the same task context the grid tiles use (`?task=` in the detail query), so prev/next and Back stay inside the task.
- Selection works in list mode too (a checkbox at the row start, plus the existing keyboard/hover selection where practical) so the `BatchActionBar` actions, including remove-from-task, apply from the list.
- Phone: the row stacks (thumb + title on the first line, date and comment below). No horizontal scrolling.
- Sorting from the `FilterBar` applies to the list as it does to the grid.
