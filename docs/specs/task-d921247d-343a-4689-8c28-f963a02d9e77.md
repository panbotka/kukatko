# An album spanning 116 years is browsed with fewer tools than the library

An album with **781 photos** ranging from **1910 to 2026** renders as a heading, a Slideshow
and a Download ZIP button, a filter field and a grid. It has **no timeline** (the library has
one) and **no sort switch**. The `description` field exists in the API response but is never
rendered — neither on the album detail nor on the albums overview, where only the year range
and the photo count appear under the name.

So a 116-year album is as hard to move through as the whole library, minus the tool the
library has for exactly that. And the album description — often the only place saying what the
album actually is — is never shown to anyone.

## Requirements
- Render `description` under the album heading (and, if it fits, on the album card in the
  overview).
- Reuse the library's `TimelineScrubber` on the album detail when the album spans more than
  about two years.
- Add a sort switch (oldest / newest first), with the state in the URL like elsewhere.

## Where it is
`web/src/pages/AlbumDetailPage.tsx`, `web/src/components/library/TimelineScrubber.tsx`.

## Out of scope
No editing of album descriptions, no data changes.
