# Remove private data from the current tree (task specs stay in the repo)

The repository `panbotka/kukatko` is PUBLIC. CLAUDE.md says: nothing private goes in — no secrets and no production specifics (hosts/IPs, SSH targets, container/bucket/vault names, private paths, live URLs or uids, real people's names or data). Owner decision (2026-10-16): the Botka task specs in `docs/specs/task-<uuid>.md` (~730 files) **stay tracked in the repo** — they are the record of what each piece of work was meant to do — but they must contain **no private data**: no IP addresses, no names of real people, no postal/e-mail addresses or phone numbers, no hosts, paths, bucket/vault/item names, live URLs or production uids. Do NOT untrack, gitignore or delete `docs/specs/`; redact inside the files. History is handled separately.

## Inputs
- The private pattern list is the gitignored file `.secrets/privacy-patterns.txt` (one extended regex per line, `#` = comment; its header names the private backup directory). It is deliberately NOT in the repo — never copy its patterns or their matches into any tracked file, test, commit message or Botka note. If the file is missing, stop and finish as needs_review.
- The list is a seed, not exhaustive. Also find by reading what a regex cannot catch: names of real people (library subjects, family members, account holders, people named as examples — the public author identity of the repo, as used in LICENSE and git authorship, is fine), postal addresses, e-mail addresses and phone numbers of real people, real photo/task/subject/album uids taken from production (e.g. `ph…`/`tk…` in example URLs), production counts or sizes, hostnames of the user's other services, local machine paths.
- Extend `.secrets/privacy-patterns.txt` with every new private pattern you find (it is gitignored), so the guard and the history rewrite catch them too.

## Requirements
1. Inventory: `git grep -nIE -f <the pattern list without comment lines>` over all tracked files, plus a careful read of `docs/specs/` (all of them — delegate batches to subagents if needed, each reporting file:line + category, never quoting the value into anything tracked), `docs/superpowers/`, `docs/*.md`, `README.md`, `scripts/`, `.github/`, `config.example.yaml`, test fixtures and testdata.
2. Before changing anything, save every passage you remove or rewrite verbatim (file, line, old text) into a new file in the private backup directory named in the pattern list's header (`removed-<YYYY-MM-DD>.md`). If that directory is not writable, stop and finish as needs_review — nothing may be lost.
3. Replace private values with neutral placeholders (`<instance>`, `<host>`, `<bucket>`, `<project uid>`, `https://photos.example.org`, invented names like "Jana Nováková", obviously fake uids). Keep each spec readable and its meaning intact — redact the value, not the requirement.
4. Judgement calls, documented in the commit message by category (never by quoting the value):
   - The package maintainer e-mail in `.goreleaser.yaml` is personal contact data: replace it with the repo owner's GitHub noreply address (`gh api user` → `<id>+<login>@users.noreply.github.com`).
   - Clearly synthetic test values (documentation IP ranges, `example.org`, made-up `/src/p/x.go` parser paths, an SSRF-refusal table of private ranges) are fine; the real production address is not, anywhere.
5. Re-run the pattern grep: it must report nothing except documented, intentionally kept synthetic cases.
6. Stage only your own hunks (other sessions share the tree); never `git add -A`.

## Done when
- The pattern grep over `git ls-files` is clean apart from documented synthetic cases, every spec in `docs/specs/` is still tracked, the backup file exists, `make check` passes, committed and pushed. The commit message and any Botka note describe what was removed by category and file only.
