# Tasks, threads and notifications are scoped by project

## Context

Kukátko is multi-tenant: `photo_tasks.project_id` and `notifications.project_id` exist; `internal/photos`, `internal/people`, `internal/organize` are scoped (convention in `docs/PACKAGES.md`: `projectUID` after `ctx`, never defaulted; foreign = 404 same shape); `auth.ProjectUIDFromContext(ctx)`; `internal/projecttest`; the SPA lives under `/p/<slug>/`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.4, 2.5, 6. Step 17 of 40.

## Requirements

- `internal/phototask` + `phototaskapi`: tasks, their frozen photo sets, participants, the remembered query and the thread are per project; a task may only freeze photos of its project (verify in one statement; a foreign uid → `ErrNotFound`, nothing created); listing, filters, the summary counts (the navbar badge) and `GET /photos?task=` are per project.
- `internal/comments`: a comment on a photo or task verifies the parent's project; listing joins the parent's project.
- `internal/notification` + the inbox routes in `notificationapi`: notifications are created with `project_id`; inbox listing, unread count and mark-read are per project (`GET /p/{slug}/notifications/*`); `notification_photos` keeps its visibility filter. `notification_prefs` and push subscriptions stay **per user, instance-wide** — document it.
- `internal/tagnotifyjob`: `tag_notices` are recorded with the photo's project; the `tag_notify` job (keyed per user) groups notices **by project** and emits one notification per (user, project), each with the project's slug in its deep link (`/p/<slug>/n/<uid>`); the pure grouping function gets table-driven tests.
- Deep links everywhere in these packages (`notifydeliver`, mail/push payloads built here) use `/p/<slug>/…`; the slug is loaded with the project (`project.Store.Get`), never hard-coded.
- Isolation tests: store — tasks list, inbox, unread count; HTTP — task detail foreign → 404 same shape; comment on a foreign task → 404; `GET /photos?task=<foreign>` → 404; a tag in B creates no notice visible in A's inbox.
- Docs: `docs/PACKAGES.md`, `docs/API.md`.
