# Tasks: quick answers

Most questions an agent opens in the task queue are a choice: "Je na nápisu rok 1936, nebo 1938?", "Domy čp. 36 a 37: platí 1950, nebo 1955?". Batches waiting in `review` need a yes/no. Today the human has to scroll past the filter bar and the photo grid to the discussion card at the bottom and type a sentence, on a phone. The agent then has to interpret free text. This task gives a question a small set of answer options that render as buttons directly under the question, and gives every `review` task a built-in approve/return pair.

## Data and API

- `photo_tasks` gets `options` (a list of up to 5 strings, each 1–60 characters after trimming, non-empty, distinct; store as `text[]` or `jsonb`, your choice, with a CHECK on the count). Empty = no options.
- `POST /tasks` and `PATCH /tasks/{uid}` accept `options` (array of strings; on PATCH absent = leave alone, empty array = clear). Validation errors are 400 with a clear message (too many, too long, duplicate).
- Every task read (listing and detail) carries `options` (always present, possibly empty).
- Answering is **not a new endpoint**: choosing an option posts an ordinary comment on the task whose body is exactly the option text. This keeps the thread as the single record and lets the agent read the answer with `tasks comments` as today, matching it against the options verbatim.
- `review` tasks with no options of their own get two **built-in** answers whose posted text is fixed regardless of UI language, so an agent can match them: `Schvaluji.` and `Vrátit k přepracování.` Document both strings in `docs/API.md` under the task endpoints; the agent relies on them.
- Audit: the task update already audits a field diff; include `options` in it.

## ctl

- `kukatko ctl tasks create --option "1936" --option "1938" --option "nevím"` (repeatable flag). `tasks update --option …` replaces the whole set; `--clear-options` empties it (the two are mutually exclusive).
- `tasks show` prints an `Options` line when set. The `-o llm` output includes `options`.

## Web

- On `/tasks/{uid}` (`web/src/pages/TaskDetailPage.tsx`, `pages/task/TaskQuestion.tsx`) the options render as a row of large buttons (minimum 44 px tall, wrapping on phones) **immediately below the question card and above the participants row**, for every authenticated user, viewers included (they may comment). Tapping posts the comment and refreshes the thread; the button is disabled while the request is in flight so a double tap cannot post twice. The option equal to the caller's most recent comment on the task is shown as chosen (filled variant); the others outlined. Tapping again with the same text does nothing. An error shows an inline alert, the page stays usable.
- A `review` task with no own options shows the built-in pair with localized labels (cs "Schvaluji" / "Vrátit k přepracování", en "Approve" / "Send back") but posts the fixed Czech strings above.
- The create dialog (`components/tasks/NewTaskModal.tsx`, new-task mode) gets an "Možnosti odpovědi" field: up to 5 short entries, added one at a time (Enter or a plus button), removable chips. The task page's in-place edit for writers (pencil in `TaskQuestion`) can edit them too.
- Small groups: when the frozen group has at most 12 photos, hide the `FilterBar` (search field, sort, density) and the Filters button on the task page — a two-photo question does not need a search box. The photo count line and the grid stay; the bulk selection keeps working.
- i18n in both locales. Icons only via the `Icon` component (bootstrap-icons).
