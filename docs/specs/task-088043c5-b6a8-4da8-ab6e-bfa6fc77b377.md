# Hide the timeline scrubber for now

The timeline rail on the right side of the library grid (`components/library/TimelineScrubber.tsx`, fed by `hooks/useTimeline.ts`) fails more often than it works. The user wants it **hidden until it gets reworked later**. This task is a switch-off, not a deletion and not a fix.

## Requirements

- The scrubber no longer renders on `LibraryPage` (`showScrubber`, ~line 173). It also no longer renders on `AlbumDetailPage` (`showScrubber`, ~line 290), which uses the same component and has the same problems. Keep the two consistent.
- With the rail hidden, the grid does not reserve its lane: the `kukatko-grid-timeline-lane` class/gutter is not applied, so the grid uses the full width on desktop and on mobile.
- With the rail hidden, the timeline data is **not fetched**: no request for the timeline/histogram the hook loads. Nothing else is lost: the anchor/jump logic that other features use (e.g. a `?date`/anchor deep link, if one exists) keeps working without the rail. Check what `jumpTo`/`anchor` serve besides the scrubber before cutting anything.
- Hide it with **one obvious switch** (a single exported constant such as `TIMELINE_SCRUBBER_ENABLED = false` next to the component, with a comment saying why and that it is temporary). Re-enabling must be a one-line change.
- Keep `TimelineScrubber`, `useTimeline` and their tests in the tree and passing. Keep the backend endpoint as is. Do not delete code.
- Update tests that assert the rail is on the library/album page: they now assert it is absent and the timeline is not fetched. Keep the component's own unit tests.

## Docs
- `docs/FRONTEND.md`: mark the scrubber as temporarily disabled, give the reason (unreliable, to be reworked) and say where the switch is.
- `README.md`: if it advertises the timeline as a feature, adjust it.
