# Running the storage move

## Context

Kukátko is multi-tenant. `internal/rekey` provides the move: `Service.Start/Pause/Resume/Retry/Status`, `Step(ctx, run, batchSize)` (copy → verify → commit row → delete, resumable) and `Finish`; the `storage_rekey_runs` table records progress. Library-wide jobs carry `project_uid` in payload and dedup key (`internal/jobs`); the worker has per-type pools and `Defer`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 5.3. Step 34 of 40. The owner starts the move **by hand** (UI or CLI); nothing starts it automatically.

## Requirements

- `internal/rekeyjob`: job type `storage_rekey` (payload `project_uid`, dedup per project, **one worker slot**). The handler loads the run; `paused` → `Defer` (re-check in 60 s); `running` → calls `Step` with a batch size derived from the new config key `storage.rekey.per_second` (default 10; add to `Config`, `setDefaults`, `config.example.yaml`, config tests, `docs/OPERATIONS.md`) for about one second of work, then re-enqueues itself (`Defer` with no delay) until `done`/`failed`; it never holds the slot for longer than a few seconds so a restart loses almost nothing.
- `Start`/`Resume`/`Retry` enqueue the job (idempotent through dedup).
- CLI in `cmd/kukatko`: `kukatko storage rekey <slug>` (start), `--dry-run` (prints counts, bytes and the first 20 planned moves), `--status`, `--pause`, `--resume`, `--retry`; reports on **stderr**; exit code 0 unless the run is `failed`.
- `internal/rekeyapi` (instance-level, `RequireMaintainer`, audited): `GET /projects/{uid}/rekey` → the run (or 404 when none), `POST /projects/{uid}/rekey` (start; 409 `already_running`/`already_prefixed`), `POST …/rekey/pause`, `…/resume`, `…/retry`.
- `kukatko ctl projects rekey <slug> [--status|--pause|--resume|--retry]` in `internal/ctl`.
- Tests: job handler with the fake storage (progress advances across several invocations; paused defers; done stops re-enqueuing); CLI dry run and status output; API integration (403 for non-maintainer, 409 cases, the state transitions); ctl.
- Docs: `docs/OPERATIONS.md` — the **runbook**: when to start (after the multi-tenant release is live and verified), how to watch, what "done" means, what to do with `failed`; `docs/API.md`, `docs/PACKAGES.md`, `CLAUDE.md` package map lines.
