# Passkey Frontend

The API provides WebAuthn passkey endpoints (documented in docs/API.md): begin/finish registration for the signed-in user, begin/finish anonymous login, list own passkeys, delete one; GET /capabilities says whether passkeys are enabled. Build the UI on top of them. If those endpoints are missing from docs/API.md, stop and end the task as blocked instead of building against a guess.

## Requirements

- Login page: a "Sign in with a passkey" secondary action under the password form. It uses the browser WebAuthn API and is hidden when the capability is off or the browser lacks support. Errors (user cancelled, no matching passkey) surface as human messages, never raw exception text.
- Account page: a "Passkeys" section — list existing passkeys (name, created, last used), add a new one (prompting for a friendly name, e.g. "Tomášův telefon"), remove one behind a confirmation. The empty state explains in one sentence what a passkey is and why it's convenient.
- cs (default) + en i18n for all copy.
- Tests: mock navigator.credentials; cover login success and cancel, and the add/remove flows.
