# Rework the /upload page flow and file list

Make `/upload` read as three obvious steps — **pick files → organise the batch → start** — and
turn the queue from a list of filenames into something the user can actually look at.

## Requirements

- The page presents the three stages in a visible order, and the layout makes clear that the
  album/label choice applies to the **whole batch**, not to one photo.
- The album/label picker stays reachable with 50+ files queued; today a long queue pushes it
  out of view.
- Every queued file shows a **local thumbnail preview** of the picked file (today `UploadItem`
  renders name and size only), plus its state — queued / uploading / done / failed — legible at
  a glance. Revoke object URLs when a row unmounts or the queue is cleared.
- Keep the virtualization: `UploadList` already uses `react-virtuoso` with window scroll and
  bottom-padding row gaps so heights measure correctly. A batch of 100+ files must stay
  responsive on a phone.
- Preserve existing behaviour: retry of failed files, the "errors only" filter, batch assignment
  of albums/labels after the upload finishes, and the share-target notices.
- Mobile: the same flow works at phone width, touch targets keep the project's minimum
  (`kukatko-tap-target`).
- Tests: update `UploadPage`/`UploadList` coverage and add cases for thumbnail rendering and the
  stage ordering.
- Docs: update `docs/FRONTEND.md` for changed or added components.

## Implementation notes

- The queue's sticky progress header (`UploadProgressHeader`, `.kukatko-sticky-toolbar`) is what
  currently collides with the picker's dropdown; the layering fix is a separate task, so do not
  re-fix it here — just do not make the collision worse.
- Local previews come from the `File` objects already held in `useUploadQueue`; no server round
  trip is needed before upload.

## Out of scope

- Changes to the upload API or the ingest pipeline.
