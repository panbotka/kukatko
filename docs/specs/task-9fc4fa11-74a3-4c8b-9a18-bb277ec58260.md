## Requirements
- A withheld member row must not expose the real account uid to the project (an opaque per-membership id instead, or no uid), and nothing keyed by that row may leak name, picture, standing or existence.
- Withheld memberships are not "in standing": `MemberSQL` (and `InStanding`/`Checker`) exclude them; notifications are neither recorded nor delivered to them.
- Former-member / actor-name / leaderboard resolution treat a withheld membership like no membership.
- Rate-limit POST /p/{project}/members per caller.
- Tests that FAIL on the current code: internal/projecttest-style integration tests (two projects; existing vs non-existing address must produce byte-identical members listings, avatar, notifications count) and notifystanding unit/integration tests.
