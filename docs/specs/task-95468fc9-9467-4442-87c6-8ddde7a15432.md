# Frontend: resilience to partial and paginated failures

Three related bugs where a mid-operation or "load more" failure tears down or
mismanages already-loaded state.

## Issues (verified)

1. **TrashPage: a partial bulk failure leaves a stale grid and stale selection.**
   `web/src/pages/TrashPage.tsx:116-130` (`run`, and `confirmDelete`). In a bulk
   restore/purge, if the 3rd `op(uid)` throws mid-batch, the loop breaks, `catch` sets
   `actionError`, and the `selection.clear()` + `reload()` (only on the success path
   after the loop) are skipped. Photos 1-2 were already mutated server-side but still
   render as archived, and the selection still holds all items → a retry acts on
   already-gone photos.
   - Fix: always `reload()` and clear the selection once the batch settles (in a
     `finally`), so the grid reflects whatever partial work happened.

2. **DuplicatesPage: a failed "Load more" wipes the whole loaded list.**
   `web/src/pages/DuplicatesPage.tsx:68-98` (`load`/`loadMore`). A page-2 failure sets
   the single shared `status='error'` regardless of offset; the list renders only when
   `status==='ready'`, so all already-loaded groups vanish behind a full-page error.
   - Fix: for `offset > 0` failures keep `status='ready'` + the existing groups and show
     an inline "couldn't load more" + retry (as `usePaginatedPhotos`/TrashPage do with
     `moreError`).

3. **DuplicatesPage: a second group's merge can clobber the first during the dry-run
   window.** `web/src/pages/DuplicatesPage.tsx:107-122` (`beginResolve`). During group
   A's in-flight dry-run, `busyGroupId==='A'` but `pending` is still null (no
   modal/backdrop yet), so B's buttons stay enabled; clicking B overwrites `busyGroupId`
   and discards A's merge.
   - Fix: disable all merge/dismiss actions whenever any dry-run is in flight (a
     page-level "busy" lock), not only once the backdrop appears.

## Requirements
- Fix all three; preserve existing success behavior.

## Testing
- Component tests: a mid-batch failure still refreshes the list and clears selection; a
  failed load-more keeps prior groups + shows inline retry; a second merge is blocked
  while a dry-run is in flight. `make check` must pass.
