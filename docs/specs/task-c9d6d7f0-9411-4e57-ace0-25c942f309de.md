# Uploading is open to every signed-in role

Today only curators and above may upload photos. The owner wants anybody who is signed in, viewers included, to be able to add photos to the library. Filing photos into albums and labels stays curation and keeps its current guards.

## Current state (verified 2026-10-11 on main 7b97933)
- Backend: `POST /api/v1/upload` is mounted in `internal/ingest/http.go` (`RegisterRoutes`) behind the guard passed to `ingest.NewAPI`, and `cmd/kukatko/ingest.go` passes `authAPI.RequireCurator`. The field/param is named `requireCurator`.
- Tests that pin the curator guard: `internal/ingest/guards_test.go` (`TestGuards_curatorUploads`) and `internal/ingest/http_integration_test.go` (setup uses `authAPI.RequireCurator`, `TestHTTPUpload_viewerForbidden` expects 403, `TestHTTPUpload_curatorCreatesPhotos` comment mentions RequireCurator).
- Frontend gates the upload on `canCurate`:
  - `web/src/App.tsx`: `/upload` sits inside `<RequireRole role="curator">` (together with `/upload-links`, `/people/clusters`, `/faces`, `/expand`, … which must STAY curator-only).
  - `web/src/components/Layout.tsx`: `{canCurate && renderLink(UPLOAD_ITEM, { cta: true })}`.
  - `web/src/components/MobileNavDrawer.tsx`: `...(canCurate ? [REVIEW_ITEM, UPLOAD_ITEM] : [])`.
  - `web/src/components/MobileTabBar.tsx`: the upload tab has `curateOnly: true`.
  - `web/src/pages/LibraryPage.tsx`: the empty-catalogue state shows the upload CTA only for `canCurate` (viewer gets `library.emptyCatalog.hintViewer`).
  - `web/src/pages/ShareTargetPage.tsx`: the phone share sheet target forwards to /upload only for `canCurate`, otherwise discards the share and shows `share.forbidden.*`.
  - `web/src/pages/UploadPage.tsx`: after upload the page offers an album/label picker (`UploadOrganize`, in `UploadStageUploading` and `UploadStageDone`) that assigns via `POST /photos/bulk` (RequireCurator) and asks `POST /photos/bulk/membership-summary` (RequireCurator) through `useBatchMembership`.
