# Password reset by link

An administrator must be able to start a password reset for somebody. Kukátko can already
set a password directly, but that means the administrator learns the password. Instead,
issue a one-time link the person uses to choose their own — mailed to them, and **also**
returned so the administrator can copy it and send it by hand.

Mail is sent by enqueueing it on the job queue.

## Requirements

- A migration adds a table of reset tokens: the account it belongs to, a **hash** of the
  token, when it was created, when it expires, when it was used, and which account issued
  it. Only the hash is stored — a leak of the table must not hand anybody a working link.
  Deleting an account removes its tokens.
- `POST /admin/users/{uid}/password-reset` — admin only. Issues a token valid for **7
  days**, enqueues a mail to the account's address containing the link, and returns the
  full link in the response so the administrator can copy it.
- Issuing a new reset invalidates any earlier unused token for that account. Only the most
  recent link works.
- `GET /auth/password-reset/{token}` — no authentication. Reports whether the link is
  still usable, so the page can say "this link has expired" instead of showing a form that
  will fail. It returns nothing about the account beyond the display name needed to greet
  the person.
- `POST /auth/password-reset/{token}` — no authentication. Sets the new password. The
  token is consumed, so a second use fails. **All** of that account's sessions are
  invalidated, including any signed in right now. The new password goes through the same
  strength rules and hashing as any other password change.
- Both public endpoints are rate-limited per client address using the existing rate-limit
  middleware.
- A token for a blocked account is refused.
- Issuing and consuming are both written to the audit trail, each in the same transaction
  as its mutation.
- Expired and consumed tokens are removed by the existing periodic cleanup that already
  prunes expired sessions.

## Implementation notes

- The new table must be classified in `internal/reset/tables.go` as **preserved**, not
  wiped: it belongs to the accounts, not to the library — the same reasoning that keeps
  `users` and `sessions`. Without the classification the integration tests in
  `internal/reset` fail late in the run.

## Definition of done

- Integration tests against the real test database cover: issuing a link, the mail being
  enqueued, consuming it, a second use failing, an expired link, a superseded link, a
  blocked account, and sessions being invalidated.
- `docs/API.md` documents all three endpoints.
- `make check` passes.
