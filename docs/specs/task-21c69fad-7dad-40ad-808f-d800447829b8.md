# Serving HLS and backfilling it

The player's side of the contract: three endpoints, plus the ability to (re)generate renditions
for photos that already exist.

Depends on the HLS groundwork, encoder-plan and transcode-job tasks.

## Contract

- `GET /api/v1/photos/{uid}/hls/master.m3u8` — the master playlist
- `GET /api/v1/photos/{uid}/hls/{rendition}/index.m3u8` — the media playlist
- `GET /api/v1/photos/{uid}/hls/{rendition}/{segment}` — a redirect to the object store

Segment URLs in the playlist point at **the backend, not the CDN**. This is deliberate and is the
whole reason the design works: the backend authorises each segment and signs it fresh, so a
signature can never expire mid-playback and no long-lived tokens are ever handed out.

## Requirements

- All three endpoints sit behind the same guard as the existing video endpoint. A photo with no
  rendition answers 404 on all three, and an unknown rendition name answers 404.
- The playlist endpoints return `application/vnd.apple.mpegurl` and are built from the rendition
  rows through the pure functions from the encoder-plan task — no playlist text is assembled here.
- The segment endpoint validates the segment name with the layout validator from the groundwork
  task, then answers 302 to a freshly signed object URL, with a cache directive that forbids
  storing the redirect. When the storage backend publishes no URLs, it streams the object instead.
- The photo payload gains a field telling the client whether HLS is available for that photo, so
  the player never has to probe.
- `/process/hls` backfills and re-runs the job following the existing backfill endpoints, and HLS
  becomes a regular per-photo processing step so its state is visible alongside the others.
- Tests: HTTP integration tests for all three endpoints covering the 404 cases, the shape of the
  redirect target, and the rejection of a malformed segment name.

## Implementation notes

- Mount the routes inside the existing photo API options helper. Adding another top-level API to
  the server wiring trips the function-length lint.
- A cached redirect would eventually send a client to a 403 — the existing video endpoint already
  handles this correctly, so follow that pattern rather than inventing a second one.
- Docs: `docs/API.md` for the three endpoints and the new payload field, `docs/OPERATIONS.md` for
  the backfill step.
