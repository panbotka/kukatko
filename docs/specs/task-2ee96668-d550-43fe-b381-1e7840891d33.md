# Administrator screen for instance settings

The API exposes three instance-wide settings an administrator may read and change at
`GET`/`PUT /settings`: whether self-service registration is open, the shared secret
registration asks for, and the Markdown text shown to a person the first time they sign
in. Nothing in the interface edits them yet.

Do **not** add this to `UsersPage.tsx` — that file is already large. Give it its own page.

## Requirements

- A new admin-only route, linked from wherever the other admin screens are reached.
- A switch for registration. Turning it on while the secret is empty is refused in the
  browser with an explanation, matching what the API refuses.
- A field for the shared secret, shown in readable text with a way to hide it. The
  administrator has to read it back to tell people what it is, so a write-only password
  field would be wrong. A short line explains that the word is what keeps strangers out
  and that everybody in the community is expected to know it.
- A Markdown editor for the welcome text with a live preview beside it — or below it on a
  narrow screen. The preview renders exactly what the welcome itself will render.
- Render Markdown with `react-markdown` together with `rehype-sanitize`; add both
  dependencies. The sanitising step is not optional even though an administrator writes
  the text.
- Links inside the rendered Markdown open in a new tab and carry the usual protections.
- Nothing is saved until the administrator saves. Leaving with unsaved changes warns
  first. Saving reports success, or the server's rejection.
- All text goes through i18n with Czech and English strings.

## Definition of done

- Component tests cover: loading the current settings, the preview rendering Markdown,
  enabling registration with an empty secret being refused, revealing the secret, and a
  successful save.
- `docs/FRONTEND.md` describes the new page and `README.md` mentions the setting.
- `make check` passes.
