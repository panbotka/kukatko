# Last-admin guard counts only approved, enabled admins

A project admin can demote or remove the only working admin as long as a pending or disabled "admin" row exists, leaving the project with no one but the maintainer.

## Context (verify with rg before starting)
- `internal/project/member_store.go` `ensureAnotherAdmin` (~line 393) counts `project_members WHERE project_uid=$1 AND role='admin'` with no `approved_at IS NOT NULL` and no join on `users.disabled`.

## Requirements
- `ensureAnotherAdmin` counts only memberships that are approved and whose account is not disabled. Demoting, removing, or (if exposed) un-approving the last such admin fails with the existing last-admin error.
- Disabling an account (maintainer action) that is the last working admin of a project is either refused with the same error or allowed and audited with a warning — pick one, document it in `docs/API.md`, and test it.
- Integration tests: (a) one approved admin plus one pending admin → demoting the approved one fails; (b) one approved admin plus one disabled admin → removing the approved one fails; (c) two approved admins → demoting one succeeds.
- `docs/PACKAGES.md` (project) and `docs/API.md` (members) updated.

## Out of scope
- The maintainer's implicit admin role (unchanged).
