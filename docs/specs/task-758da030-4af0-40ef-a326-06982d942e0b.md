# Scalable People Index

/people lists ~105 subjects with no search or sorting, and downloads roughly 125 megapixels of imagery to paint small avatar squares (finding N8 in docs/UX_RESEARCH.md). Make it scale.

## Requirements

- A search input filters subjects by name as the user types; case- and diacritics-insensitive (Czech names).
- A sort control: photo count descending (default), name A–Z, recently added — use fields the subjects list API already returns.
- Avatar tiles must load an appropriately small rendition for their rendered size instead of large images; the total transferred for the page must drop by an order of magnitude.
- The grid is virtualized with react-virtuoso.
- Search/sort state lives in URL query params ("back always works").
- Empty state for no matches; cs + en i18n for all new copy.

## Implementation notes

- Known repo gotcha: a face bounding box may only be cropped from `fit_*` renditions — `tile_*` sizes are centre-cropped squares, so a bbox crop lands wrong. Keep avatar crops correct.
- Keep the information the tiles show today (name, counts, birth/death years where present).
