# API Token Management on the Account Page

Surface the existing API-token backend in the UI — today tokens are curl-only.

## Requirements
- The backend already provides personal API tokens (`kkt_…` Bearer tokens; create/list/revoke endpoints under the auth API — see docs/API.md). Build an "API tokens" section on the Account page on top of them; do not change the backend contract.
- **List** existing tokens with name, creation date, and whatever metadata the API returns (prefix, last used if available). Empty state explains in one sentence what API tokens are for, with a link to a short new help-page entry.
- **Create:** name input → on success show the full secret ONCE in a copy-to-clipboard field with an i18n warning that it will never be shown again; the list refreshes.
- **Revoke:** per-token button with a confirmation dialog naming the token; revoked tokens disappear immediately.
- Respect backend RBAC: if the API rejects token creation for the user's role, show a read-only explanation instead of broken buttons.
- i18n cs/en.
- Component tests: list render, create flow with the secret-shown-once behavior, revoke confirmation, error states.
- Update docs/FRONTEND.md (and the help page).
