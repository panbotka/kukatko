# Add a mobile bottom tab bar for the primary destinations

On a phone the whole primary navigation is hidden behind the hamburger: the top row
is just `[hamburger] [search]`, so reaching the everyday destinations always costs a
menu open-then-tap. Add a persistent bottom tab bar on mobile for the core loop.

## Current behavior

- `web/src/components/Layout.tsx` renders the primary nav items plus Upload / Review
  / Leaderboard inside `Navbar.Collapse`, which is collapsed behind the hamburger
  below the `md` breakpoint (`expand="md"`). There is no always-visible quick access
  to the main destinations on a phone.

## Requirements

- On mobile (below the navbar's expand breakpoint) show a fixed bottom tab bar with
  the 3-5 most-used destinations. Suggested set: Knihovna (library), Alba, Štítky,
  Nahrát (upload) — pick the everyday core; keep it to at most 5 tabs.
- Each tab: a `bootstrap-icons` icon via the `Icon` component + a short label, an
  active-state highlight bound to the current route, and a ≥44px touch target.
- The bar is fixed to the bottom and must respect `env(safe-area-inset-bottom)`
  (mirror how `.kk-batch-dock` in `web/src/styles/app.css` already does it) so it
  clears the home-indicator.
- It must not collide with the floating bulk-action bar (`BatchActionBar`): when a
  photo selection is active and that bar is shown, the tab bar should hide or the two
  must stack without overlapping. Reserve bottom scroll clearance on pages so content
  isn't hidden behind the tab bar.
- Show the tab bar ONLY on mobile; on `md`+ the existing top navbar remains the sole
  navigation (no bottom bar on desktop).
- Keep everything else (Tools/Provoz/Správa/user menu) in the existing menu — the tab
  bar is only the primary loop, not a full nav replacement.

## Testing

- Add a Vitest test asserting the tab bar renders its destinations with active-state
  wiring on a mobile viewport and is absent on desktop.
- `make check` must pass. Update `docs/FRONTEND.md` with the new component.
