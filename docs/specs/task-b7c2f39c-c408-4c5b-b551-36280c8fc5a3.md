# Show album, label and person previews in the command palette

In the Cmd+K search (`web/src/components/search/SearchCommand.tsx`) albums, labels and people
render with a generic icon. `GET /search/global` returns no cover for any of them — albums have
one in the model (`GET /albums` returns `cover_uid` and `cover_uids`), labels and people have no
cover concept at all. Give all three the same small thumbnail the albums page uses.

## Backend

- `GET /search/global` returns, for album, label and person hits, the cover photo uid **and** a
  `thumb_url` stamped the same way photo hits already get theirs (`internal/mediaurl`).
- An album uses its existing cover. **A label and a person get a derived cover**: the newest
  photo carrying that label / showing that person (`taken_at` descending, falling back to
  `created_at`), excluding archived and hidden photos. An entity with no photos simply has no
  cover and the field is omitted.
- `GET /labels` returns the same derived cover so the Labels page can render previews too.
- The derivation runs as **one query over the whole batch** (lateral join or equivalent), never
  one query per entity — the endpoint must not fall into an N+1.

## Frontend

- Album, label and person rows in the palette show a **small square thumbnail** in place of the
  generic icon. Row height stays stable.
- When there is no cover, or the image fails to load, the row **falls back to today's icon** —
  never an empty gap.
- The Labels page shows the same preview as Albums.
- Images load lazily and are decorative (`aria-hidden`); the row's accessible name stays the
  entity's title.

## Tests and docs

- Go integration test: a cover comes back for an album/label/person that has photos and is
  **absent** for empty ones; assert the batch derivation issues one query, not one per row.
- Vitest: a row rendering the thumbnail, and the fallback to the icon.
- Update `docs/API.md`, `docs/FRONTEND.md` and `docs/PACKAGES.md`.

## Out of scope

- Letting a user pick a cover by hand for labels or people — derived only.
- Redesigning the palette or changing how results are ranked.
