# Task body and comments: render Markdown properly

Task texts (written mostly by the curating agent via `ctl`) are Markdown, but they render badly. Example: https://photos.example.org/tasks/<task uid> — the body has a GFM table (`| fotka | rámeček | … |`), bold, inline code, and links to `https://photos.example.org/photos/<uid>` and `/tasks/<uid>`. The comments in the same task are written in the same Markdown style.

## Diagnosis (verified)
- **Body** (`web/src/pages/task/TaskQuestion.tsx`) goes through `components/Markdown.tsx` = `react-markdown` + `rehype-sanitize` **without `remark-gfm`**. Tables (and strikethrough, task lists, autolinks) are not CommonMark, so the table shows up as raw pipe text. Every link opens in a new tab, even links to Kukátko itself.
- **Comments** (`web/src/components/photo/CommentBody.tsx`) are deliberately plain text (`pre-wrap`, photo-uid tokens turned into links, a thumbnail strip). So `**bold**`, `` `code` `` and `[name](url)` show up as literal markup.

## Requirements
- Add **`remark-gfm`** to `Markdown`. Tables, strikethrough, autolinks and task lists render, still through `rehype-sanitize` (keep it mandatory, and keep raw HTML off).
- **Table styling:** Bootstrap `table table-sm` look, readable in the Superhero theme. Wrap the table in a horizontally scrollable container, so a wide table never overflows the page on a phone (360px). Colours come only from palette tokens.
- **Own-site links:** an absolute link to the instance's own origin (`window.location.origin`) or a relative `/…` link becomes an in-app react-router `Link` and opens in the **same tab**. Inside a task, a link to `/photos/<uid>` carries `?task=<taskUid>` exactly like `photoRefHref` does today, so prev/next and Back work. External links keep the new tab and `noopener noreferrer`.
- **Comments render Markdown** through the same `Markdown` component (task threads **and** photo threads, since they share `CommentBody`). Keep what works today:
  - A bare photo uid token in the text still becomes a link (apply the `splitPhotoRefs` logic to text nodes only, never inside code or existing links).
  - The thumbnail strip lists every referenced photo, both bare uid tokens **and** uids taken from own-site `/photos/<uid>` links. Dedupe them and keep the `COMMENT_STRIP_MAX` cap.
  - The writer's line breaks still show. Treat a single newline as a line break in comments (the `remark-breaks` behaviour) so short typed comments look as typed. For the task body, keep standard Markdown paragraphs.
- Update the `CommentBody` doc comment and the `Markdown` doc comment, which lists its callers. Update the comment-box hint text (cs+en) to say Markdown works.
- Headings inside a body or comment must not outrank the page's own (cap them at a visually small size or map them down a level).
- The welcome modal and the settings preview keep working (they share `Markdown`).

## Tests
- Vitest for `Markdown`: a GFM table renders `<table>`; a `javascript:` link is still stripped; an own-origin link renders as an in-app link without `target`; an external link gets `target=_blank`.
- Vitest for `CommentBody`: bold, inline code and a link render; a bare uid links and appears in the strip; a uid inside a `/photos/<uid>` link appears in the strip once; a uid inside inline code is NOT linked.
- Check visually (static harness or throwaway instance) the example task body, on desktop and at 360px. Attach the screenshots to the task.

## Out of scope
- Changing what the agent writes, and any backend change: the stored text stays as it is.
