# Sign-in returns a different account to the previous account's page

The login page sends the user back to where the route guard caught them (`returnTo()` in `web/src/pages/LoginPage.tsx`, from `location.state.from` or `?returnTo=`). That is right for the same person whose session expired, but it ignores **who** signed in. Signing out as a system administrator on a `/system/...` page and signing in as an ordinary project admin lands the new account on "Sem nemáte přístup — Na tuhle část potřebujete roli správce systému". Returning to `/p/<slug>/...` of a project the new account is not a member of lands on "Stránka nenalezena". The first thing a freshly invited user sees is an error.

## Reproduce

1. Sign in as a system administrator, open `/system/projects`, let the session end or sign out so the guard redirects to `/login` with that page as `from`.
2. Sign in as an account that is a member (any role, even project admin) of exactly one project and is not a system administrator.
3. Observed: URL `/system/projects`, "Sem nemáte přístup". Expected: the account's home (its single project's library `/p/<slug>`, or the project chooser if it has several, the same place a plain sign-in reaches).
Same with a `from` of `/p/<other-slug>/...` for a project the account does not belong to → "Stránka nenalezena".

## Requirements

- After a successful sign-in, use the return target only if the signed-in account may use it:
  - a system-administrator-only route (everything under `/system`, and any other maintainer-only page) only for a system administrator;
  - a `/p/<slug>/...` route only when the account is an approved member of `<slug>` (the `/auth/me` response already lists the account's projects); a route needing a higher project role than the account has (e.g. a project-admin page for a viewer) falls back too.
- Otherwise go to the default landing a sign-in without a return target reaches. No error page, no flash of the forbidden page.
- The same person's normal case must keep working: session expired on `/p/v/photos/<uid>?panel=info` → after sign-in back on exactly that URL, query and hash included.
- The invitation flow's `?returnTo=` (the invite page's "Přihlásit se") must keep working, including for an account that belongs to no project yet. The invite page must stay reachable.
- Keep the existing open-redirect protection of `returnTo` (only same-origin paths).
- Do not reveal whether a foreign project exists: the fallback is silent and identical for an unknown slug and a project the account is not in.
- Tests (Vitest, `LoginPage.test.tsx`): maintainer-only target + non-maintainer → home; foreign project target → home; own project deep link → kept; invite `returnTo` → kept; maintainer + `/system/...` → kept.
