# The people index counts markers and calls them photos

Found while investigating the nameless-subject report on 2026-08-03. The badge under
every subject tile reads "N fotek", but N is the number of **markers**, not the number
of photos the person appears on.

`web/src/components/people/SubjectTile.tsx:75`:

```tsx
{t('people.photoCount', { count: subject.marker_count })}
```

and `people.photoCount_other` in `web/src/i18n/locales/cs/common.json` is
`"{{count}} fotek"`. The value comes from `listSubjectsSQL`
(`internal/people/subjects.go`), which selects `COUNT(p.uid) AS marker_count` over the
markers join — one row per marker, correctly restricted to visible photos, but never
reduced to distinct photos.

Measured on production:

```
subject               markers   distinct photos
(empty name)           16 531             6 767
Miloslav Novotny          982               982
Tomáš Kozák               427               420
Lubomír Němec             293               293
```

For most real people the two are identical, which is why this went unnoticed — a person
is usually detected once per photo. It diverges whenever one photo carries several
markers of the same subject, and the catch-all subject makes it glaring: the UI claims
16 531 photos for a subject that appears on 6 767.

## What to decide

Pick one and make the code say which it is — the current state is the only wrong answer,
because the number and the word disagree:

* **Count distinct photos.** Matches the label, and matches what the subject's gallery
  actually shows when you click through — which is the strongest argument, since the
  badge is a promise about the next page. Costs a `COUNT(DISTINCT m.photo_uid)`.
* **Keep counting markers and relabel.** Cheaper, and arguably more informative for face
  work, but "16 531 tváří" is a different claim and needs the en/cs strings to match.

Prefer the first unless the gallery turns out to be marker-paged too — check before
choosing, and say in the commit message which one the gallery does.

Note `marker_count` is also consumed by `CandidateSearchForm`, `FilterBar`,
`FaceAssignPanel` and `OutlierControls` as a hint next to a subject name. Those are face
tools, where a marker count is the meaningful figure. If the listing switches to distinct
photos, decide deliberately whether those hints follow or keep the marker count under a
separate field — do not let one call site silently change the meaning of the other four.

## Verification

Extend the existing `internal/people` integration tests with a subject carrying two
markers on one photo and assert the listed count. Frontend: Vitest over `SubjectTile`
with the chosen field and both plural forms.
