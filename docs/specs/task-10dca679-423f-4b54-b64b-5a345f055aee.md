# Curator role 1/5 — the role and the gate

Add a `curator` role to the ladder between `viewer` and `editor`, together with its
middleware, so later steps can move endpoints onto it. Nothing is rewired yet.

Read `docs/superpowers/specs/2026-09-26-curator-role-design.md` sections 1, 2, 5 and 6
before starting. This is step 1 of 5 — do not move a single endpoint.

## Requirements

- `internal/auth/role.go`: a `RoleCurator` constant with the value `curator`, accepted by
  `Valid()`, and a `CanCurate()` predicate that is true for a curator and for every role
  that already `CanWrite()`.
- `CanWrite()`, `IsAdmin()`, `CanMaintain()` and `CanImport()` stay byte-for-byte
  unchanged. A curator must fail all four.
- A `requireCurate` requirement constant, its case in `authorize()`, and a
  `RequireCurator` middleware in `internal/auth/middleware.go` alongside the existing ones.
- A migration redefining the `users_role_check` constraint to accept `curator`, following
  the drop-and-re-add shape of `0036_role_maintainer.sql`. Confirm the next free migration
  number at implementation time. No data migration, no new table, no change to
  `sessions.role`.
- Self-registration keeps landing on `viewer`: do not touch `internal/auth/register.go`.
- No API package is rewired and the frontend is not touched, so after this task a curator
  behaves exactly like a viewer and the role cannot even be assigned from the UI. That is
  the intended end state.
- Tests: a table in `internal/auth/role_test.go` covering all five roles against all five
  requirements, plus whatever the package's existing migration coverage expects.
- Docs: `docs/PACKAGES.md` (`internal/auth`), the `internal/auth` line in `CLAUDE.md`'s
  package map, `docs/ARCHITECTURE.md` (the ladder), and one line in `docs/MCP.md` — a
  curator gets the read-only MCP server for free, because `CanWrite()` is unchanged.

## Implementation notes

- Go deliberately has no rank arithmetic for roles; every predicate names its roles
  explicitly, so an inserted rung cannot inherit a permission by accident. Do not
  introduce an `AtLeast()` helper — the numeric ladder stays in the frontend only.
- Known pre-existing failure: `web/src/pages/ReviewPage.test.tsx`, case "leaves no
  snapshot behind a finished round", fails on main under the full vitest suite and passes
  in isolation. If `make check` is red only there, it is not this task's regression.
