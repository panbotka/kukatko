# Metrics: fix the three series that mislead, then add build info and the stale-lock counter

The Prometheus surface instruments the request path, the job runtime and the catalogue's content, but three
existing series answer the wrong question. Fix those first; the additions here are the cheap ones that need no
new SQL and no new package.

## Requirements

- `kukatko_embedding_service_up` must report the sidecar's reachability, not the outcome of the last embed
  call. It only moves inside `embedding.Instrument`, while the two probe loops that actually know the answer
  every 60 s build an uninstrumented client (`cmd/kukatko/capabilities.go`, `cmd/kukatko/wake.go`). Wire the
  registry into both. The two probe different hosts (the box's embed URL vs. the text-embedding URL), so the
  gauge needs a bounded label naming the target; update `SetEmbeddingUp` and its callers/tests with it.
- Quantiles above p50 must be answerable for work that takes minutes. `jobs_execution_duration_seconds`,
  `embedding_request_duration_seconds` and `thumbnail_generation_duration_seconds` use `prometheus.DefBuckets`,
  whose top bucket is 10 s — `image_embed`, `face_detect`, `ocr`, `storyboard`, `metadata` and a RAW/HEIC
  thumbnail routinely exceed it and land in `+Inf`. Give them an exponential bucket set reaching into the
  minutes, in the spirit of `encodeDurationBuckets`. Give `http_request_duration_seconds` the same defaults
  plus a short long tail, because streaming routes (the sweep's NDJSON) outlive every default bucket.
- A permanently failed job must be distinguishable from one that will succeed on the next attempt: add a
  `terminal` outcome to the outcome vocabulary in `internal/metrics/observe.go` and classify
  `worker.Terminal(...)` into it in the worker's `outcomeFor`.
- The job, embedding and video-encode families must exist from process start, at zero, for every label
  combination the instance can produce (each job type the worker has a handler for × each outcome, and so on).
  Today a family with no observation yet exports nothing, so a dashboard cannot tell "nothing failed" from
  "the instrumentation is broken" — on production right now every job series is simply absent.
- Expose `kukatko_build_info{version,commit} 1` from `internal/version`, which today reaches only `/healthz`.
- Expose a counter of jobs whose stale locks were recovered; `RecoverStaleLocks` returns the number and it is
  currently only logged, although a nonzero rate is always a real incident.
- `/metrics` stays unauthenticated: no new label may be per-user or name a photo, album, label or person.
- Leave the deliberate `nil` observer on the avatar/profile-picture thumbnailers alone — it is a decision, not
  an oversight.

## Implementation notes

- `internal/metrics` already has the two shapes to follow: an event observer (`observe.go`) and a scrape-time
  collector (`collectors.go`, `geocodeBudgetCollector` is the smallest one).
- Pre-initialising a label combination is a `WithLabelValues(...)` call at registration time.
- Every new or changed series needs a unit test; `metrics_test.go` and `library_test.go` show the pattern.
- Document the result in `docs/OPERATIONS.md` under "Prometheus metrics", including why the buckets differ per
  family.
- The Grafana dashboard lives in the `rpi` repo (`grafana/provisioning/dashboards/kukatko.json`) and is out of
  scope here; if a panel would need changing, say so in the commit message.
