# The SPA lives under /p/:slug

## Context

Kukátko is becoming multi-tenant. Backend: every project-scoped endpoint is at `/api/v1/p/<slug>/…`; `GET /auth/me` returns `projects: [{uid, slug, name, active, role, approved}]`, `last_project_slug`, `instance_role`. Frontend (previous step): `web/src/services/api.ts` with `apiPath`/`instancePath`/`setCurrentProjectSlug`; `AuthProvider` currently sets the slug from `/auth/me`. Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 3.3; read `docs/FRONTEND.md` (provider tree, routes table) and `web/src/App.tsx`. Step 09 of 40.

Rule from the project: "Back always works" — view state lives in the URL. After this step every project link carries its project; a user with exactly one project notices nothing except the `/p/v/` prefix in the address bar.

## Requirements

- `ProjectProvider` + `useProject()` placed **directly under `AuthProvider`** in the provider tree, exposing `{ project: Membership | null, projects: Membership[], status: 'loading'|'ready'|'not-member', switchProject(slug) }`. The current project is the `:slug` route param matched against `me.projects`; on match call `setCurrentProjectSlug(slug)`; no match → render the existing not-found page (same page as an unknown URL — a non-member must not learn the slug exists). `TaskSummaryProvider` and `NotificationInboxProvider` are keyed by slug so they refetch on change.
- Routes in `App.tsx`: every project-scoped route nests under `/p/:slug` (library, favourites, albums, labels, tasks, `/n/:uid`, notifications inbox, search, saved, map, places, people (+tree), leaderboard, share-target, upload, activity, stats, help, upload-links, people/clusters, faces, expand, recognition, outliers, duplicate-markers, duplicates (+compare), trash, import, review, slideshow, `/photos/:uid`, `/albums/:uid/faces`, `/users`, `/audit`, `/audit/reviews`, `/settings`). Instance-level routes stay unprefixed: `/login`, `/register`, `/password-reset/:token`, `/u/:code`, `/account`, `/system`, `/maintenance`, and a new placeholder `/projects` (a plain list of the user's projects as links — the real chooser is the next step).
- Entry rule (used by `/` and by every redirect): target slug = `last_project_slug` if it is an approved active membership, else the only approved active membership, else `null` → `/projects`.
- Redirects: a catch-all route set for the old unprefixed paths (`/photos/:uid`, `/albums/*`, `/library/*`, `/people/*`, `/tasks/*`, `/n/:uid`, `/search`, `/map`, … — derive the list from the routes you nested, do not hand-type it twice) that `navigate`s with `replace` to `/p/<target slug>/<same path>` **preserving query string and hash**; with no target → `/projects`.
- Links: one hook `useProjectPath()` returning `(path: string) => string` (`/p/<slug>` + path) and a `<ProjectLink to>` wrapper; replace every absolute project link and `navigate('/…')` in `web/src` (`rg -n "to=\"/|to={\`/|navigate\('/|navigate\(\`/" web/src`) — `components/navItems.ts` entries become relative or are resolved in `Layout`. Deep links produced by the app (share target, notification `/n/:uid`, slideshow return path, Web Share URLs, `document.title` links) go through the same hook.
- Role predicates in `useAuth()` (`canCurate`, `canWrite`, `isAdmin`, `canImport`) read the role of the **current project** from `useProject()`; `isMaintainer` reads `instance_role`. `canImport` = `isMaintainer`.
- PWA: `start_url` stays `/` (the entry rule handles it); the service worker's navigation fallback must serve the SPA for `/p/*`.
- Tests (Vitest): entry rule unit tests (three branches); redirect test `/photos/abc?x=1#h` → `/p/v/photos/abc?x=1#h` for a one-project user and → `/projects` for a user with none; `useAuth` predicates read the project role; `ProjectProvider` not-member renders the not-found page; existing page tests updated to render inside `/p/v` (see the memory-style notes in `docs/FRONTEND.md` about `LibraryPage.test` mocks and `navItems.test`/`MobileNavDrawer.test` enumerations).
- Docs: `docs/FRONTEND.md` (`ProjectProvider`, `useProjectPath`, the routes table with the prefix, the entry rule), `README.md` one user-facing paragraph ("addresses now start with /p/<project>").

## Out of scope

The chooser page design and the header switcher (next step), any backend change.
