# Frontend: stale-response and reload correctness in shared data hooks

Three fetch/reload bugs in shared hooks that cause wrong data to render.

## Issues (verified)

1. **Background reload truncates a deeply-scrolled grid to the first page.**
   `web/src/hooks/usePaginatedPhotos.ts:204` (`photos: isInitial ? res.photos : […]`)
   via the background path at `:261` (`fetchPage(0, true, true)`). Used by LibraryPage,
   FavoritesPage, AlbumDetailPage, LabelDetailPage, SearchPage, PlacesPage. After a bulk
   edit, `onEdited→reload()` bumps `reloadKey`, refetches ONLY offset 0, and replaces
   `photos` with those 100 — so a user scrolled to page 4 (400 loaded) is bounced to the
   bottom and loses pages 2-4. Contradicts the hook's own doc ("currently loaded photos
   stay mounted"); the multi-page case is untested.
   - Fix: on a background reload of a multi-page list, re-fetch up to the currently
     loaded count (or preserve prior pages) so scroll position + loaded range survive.

2. **useFaces reconcile after a face-assign has no stale guard.**
   `web/src/hooks/useFaces.ts:150-175` (`runAssign` → `await reload()`), `reload` at
   105-114; `PhotoDetailPage.tsx:123` (`useFaces(uid)`), route not remounted across
   prev/next. `reload()` is called with NO abort signal and does an unconditional
   `setState({status:'ready'})`. Name a face on photo A, page to B before it settles →
   a slow `reload(A)` overwrites B's faces; a later assign builds a request from A's
   `marker_uid` against B and 404s.
   - Fix: guard the reconcile like the initial load — tie the `setState` to the current
     `photoUid` via signal or a monotonic seq ref.

3. **useLibraryFacets year fetch has no stale-response guard.**
   `web/src/hooks/useLibraryFacets.ts:59-74`. Rapid filter changes (A→B): if A's
   `fetchPhotoYears` resolves before the cleanup abort fires, its `.then` runs
   `setYears(A)` after `setYears(B)` → wrong per-year counts flash in the facet
   dropdown. Only `controller.abort()` guards it (a no-op once the response landed).
   - Fix: add a `latestRequest` seq ref (as in `useTimeline`) and drop stale `.then`
     results.

## Requirements
- Fix all three; do not regress the abort/stale handling that already works in the
  other hooks.

## Testing
- Hook/component tests: a multi-page reload preserves the loaded range; a face reload
  for a previous photo does not overwrite the current one; stale year results are
  dropped. `make check` must pass.
