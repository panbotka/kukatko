# Going back from a photo throws away the position in the library

Measured on the live instance: scroll the library to `scrollY = 4000`, open a photo, press
the browser Back button — you land at `scrollY = 195`. Using the viewer's own "Zpět na
seznam" from `scrollY = 6000` lands at 192. The whole document is 369 018 px tall, so 6 000
px is under two percent of the library; even that little is lost.

Browsing a photo library is a constant alternation of grid → photo → grid. When every step
resets the position, the older part of the library becomes unreachable: you scroll down to
the 1 300 photos from 2013, open one, and you are back at 2026. `/help` explicitly promises
the opposite ("Stav prohlížení — filtry, řazení i pozici — si aplikace pamatuje v adrese
stránky, takže tlačítko Zpět vždy funguje.").

## Requirements
- Returning to the grid restores the previous scroll position, for both ways back: the
  browser Back button and the viewer's "Zpět na seznam".
- This must work on the library and equally on the album detail, label detail and person
  detail grids.
- The restored state must be tied to the view (URL/filters), so that changing the filters
  does not restore a position from an unrelated result set.
- Implementation may use `react-virtuoso`'s `restoreStateFrom` / `stateChanged` persisted
  into `history.state` or `sessionStorage` keyed by the URL, or the first visible tile index
  in the URL plus `scrollToIndex` — `PhotoGrid` already exposes `scrollToIndex`.
- Note for verification: jsdom mounts no virtuoso items, so a vitest alone cannot prove
  this. Verify against a real browser on a throwaway instance and describe what you saw in
  the commit message.

## Where it is
`web/src/components/library/PhotoGrid.tsx` (imperative handle around line 169),
`web/src/hooks/usePaginatedPhotos.ts`, `web/src/pages/LibraryPage.tsx`, plus the album,
label and person detail pages.

## Out of scope
No data changes.
