# Project-scoped API prefix

## Context

Kukátko is becoming multi-tenant; every endpoint that reads or writes catalogue data moves under `/api/v1/p/{project}/…` (`{project}` = slug). Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, section 3.2. Step 06 of 40. Already in the tree (verify): `auth.WithProject` (resolves the `project` URL param; when absent it resolves the bootstrap project `v` — the transition rule), `auth.ProjectFromContext`, the `Require*` middlewares reading the project role. The embedded frontend, `kukatko ctl` and MCP clients still call the unprefixed paths, so this step keeps them working through **aliases**; a final step removes the aliases.

`buildServices` in `cmd/kukatko` sits at the `funlen` lint limit (a known trap in `docs/DEVELOPMENT.md`): put the new router construction in a new file, do not grow that function.

## Requirements

- New file `cmd/kukatko/projectapi.go` with one function `mountProjectAPI(r chi.Router, deps …)` that registers **every project-scoped package** on the router it is given: photoapi (incl. trash and stacks routes), globalsearchapi, organizeapi, peopleapi, familyapi, avatarapi, clusterapi, reviewapi, sweepapi, candidatesapi, outlierapi, duplicatesapi, dupmarkersapi, expandapi, bulkapi, phototaskapi, feedbackapi, savedsearchapi, searchhistoryapi, whatsnewapi, placesapi, mapsapi, the upload endpoint, the upload-link **management** routes of uploadlinkapi, the notifications inbox routes of notificationapi, capabilitiesapi, settingsapi, announcementapi, the users name directory (`GET /users`), importapi, processapi, mcpapi. Call it twice: once for `r.Route("/api/v1/p/{project}", …)` wrapped in `auth.WithProject`, once for the existing `/api/v1` router (the alias, same middleware; the absent param resolves to `v`). Comment the alias mount: `// transition alias — removed in the alias-removal step`.
- Instance-wide routes stay where they are, mounted once: `/auth/*`, `/users/{uid}/avatar`, `/auth/picture`, `/push/*`, `/jobs`, `/system`, `/backup`, `/maintenance`, `/restore`, `/audit`, `/metrics`, `/healthz`, the public `/u/{code}` routes (they will resolve their own project from the link row in a later step; for now they run against `v`).
- Own-route media URLs: `internal/mediaurl` and every handler that builds a URL to `/api/v1/photos/{uid}/thumb/...`, `/download`, face crops, subject avatars must build it **with the prefix the request came through** (`/api/v1/p/<slug>/…` when prefixed, `/api/v1/…` through the alias). Add one helper (e.g. `auth.APIBase(ctx) string`, set by `WithProject` from the matched route) and use it everywhere such a URL is built; test both forms.
- MCP: `internal/mcpapi`'s 401 challenge and OAuth protected-resource metadata must advertise the URL the request came through (prefixed or alias).
- Server-level integration test (new `cmd/kukatko/projectapi_integration_test.go` or an `internal/server` test): the same listing returns byte-identical bodies at `/api/v1/photos` and `/api/v1/p/v/photos` (media URLs aside, which differ by prefix — assert that explicitly); `/api/v1/p/nope/photos` → 404; a member of a second project calling `/api/v1/p/v/photos` → 404 with the same body as `nope`.
- Docs: `docs/API.md` — a new top section "Project prefix" (the two mounts, the transition), every project-scoped endpoint's path shown with the prefix; `docs/MCP.md` the URL; `docs/PACKAGES.md` (`cmd/kukatko`).

## Out of scope

Frontend changes, `ctl` changes, removing the aliases, scoping any query.
