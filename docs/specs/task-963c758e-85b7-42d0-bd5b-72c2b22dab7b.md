# Sibling relation without known parents

Recording "these two are siblings" must work even when neither parent is in the library.

## Background

`subject_families` is the node of the genealogy and a family must today have at least one
partner (CHECK `subject_families_has_partner`), so the siblings row in the family strip has
nothing it can write and dead-ends with `family.hints.siblingNoParents` ("add a parent
first"). That message is wrong: the parents exist, they just have no photos here.

## Requirements

- A family may exist with no partners at all — a bare sibling group. New migration (never
  edit 0073): drop the `has_partner` CHECK and make `idx_subject_families_pair` partial, so
  it still forbids a duplicate couple and a second family for one lone parent, but does not
  collapse every parentless family in the library into a single row.
- "Add a sibling" on a subject with no parents creates such a group and records both
  subjects as its children. No placeholder "unknown parent" subject is created — the people
  list must not gain a phantom.
- When parents are already known, nothing changes: the sibling is recorded as a child of the
  existing family and `siblingHint` still names them.
- Adding a parent to anyone in a parentless group attaches that parent to the existing
  family, so every child in it becomes that parent's child. Never a second family for a
  child.
- If the two subjects are already children of two different families, the write fails with a
  message that says so; a child is never moved between families silently.
- A sibling relation may be removed only when the shared family has no parents — the only
  case where the sibling link is the whole relation. With a parent present, keep today's
  "siblings are derived" error. A parentless family that drops below two children is deleted.
- `POST /subjects/{uid}/relations` accepts the `sibling` role, and so does
  `kukatko ctl family add`/`remove`; both follow the rules above and are audited like every
  other family write.
- `families.yaml` (`internal/familyexport`) serializes and round-trips a parentless family;
  the walks in `internal/family` must not assume a family has a partner.
- `family.hints.siblingNoParents` disappears from cs + en; the siblings row gets the same add
  affordance as the other rows.
- Integration tests for: sibling with no parents, a parent later adopting the whole group,
  the two-families conflict, both removal rules, the YAML export.

## Implementation notes

- Probe the migration against populated data before committing (throwaway schema +
  `search_path` + ROLLBACK in the test DB) — the index swap runs over real rows.
- Docs: `docs/PACKAGES.md`, `docs/API.md`, `docs/FRONTEND.md`, and the `internal/family` line
  in the package map — "a couple or lone parent plus their children" stops being the whole
  truth.
