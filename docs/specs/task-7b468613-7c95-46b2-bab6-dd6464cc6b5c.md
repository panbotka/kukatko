## web/src/lib/familyLayout.ts

A PURE function: nodes in, coordinates out. No DOM, no React, no fetching. A classic
tidy-tree (Reingold–Tilford) layout over a tree whose node is a COUPLE box, with children
hanging below it. Descendants are a genuine tree once a couple is one box, which is exactly
why the design splits the two directions.

Purity is the point: this is where the real risk lives, and a pure function is what makes it
unit-testable.

NO new dependency. The frontend's dependency list is deliberately lean — leaflet is its only
visualisation library — and this is roughly two hundred lines of arithmetic. Do not reach for
d3, dagre or elkjs.

## FamilyTreePage at /people/:uid/tree

An SVG renderer on top of the layout: pan, zoom, collapsible branches, and click a node to
re-root. The root and `direction` live in the URL — "Back always works" is a standing project
rule, and this page must honour it.

Reached from the FamilyStrip's "Zobrazit rodokmen" link added in task 3.

## Tests

Vitest over the pure layout: a straight line, a wide sibship, a remarriage (two families
sharing one partner), a collapsed branch, and a cousin marriage where the same person is
reachable twice and must be drawn once. Component tests for the page's URL state.

## Verification

jsdom will not tell you whether the tree LOOKS right. Verify the rendered result with a
standalone static harness driven by agent-browser — the way CSS and layout changes are
verified in this repo — and record what you saw in the task notes. A tree that is correct in
the unit tests and unreadable on screen is a failed task.
