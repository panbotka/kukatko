# Browser storage outlives the account that wrote it

Nothing is cleared at sign-out and most keys carry no user, so one account's UI state follows the
next — in one case hiding an instance-wide warning.

## Background

`web/src/auth/AuthProvider.tsx` calls the API and resets in-memory state on sign-out; it touches
neither `localStorage` nor `sessionStorage`. The only `removeItem` for stored UI state in the whole
app is `lib/reviewSnapshot.ts:99`. So every key survives an account switch, and the `sessionStorage`
ones survive it too when the switch happens in the same tab.

Two modules already do this correctly and are the pattern to copy: `lib/reviewSnapshot.ts:126-129`
refuses a snapshot whose recorded user does not match, and `lib/pushPromptAnswer.ts:7` puts the user
uid in the key.

What leaks:

- `kukatko.announcement.dismissedAt` (`lib/announcementDismissal.ts:7`, read at
  `components/AnnouncementBanner.tsx:36`) is one global key. Account A dismisses an instance-wide
  notice; account B signs in on the same browser and never sees it. For a maintenance or
  storage-full warning that is a real loss — and it is the only leak here that hides information
  rather than misplacing a scroll offset.
- `i18nextLng` (`web/src/i18n/index.ts:37-40`) is the sole language detector and cache, with no
  per-account preference on the server. Account A switching to English leaves account B an English
  UI. Discoverable from the account page, but it changes everything the next person sees.
- `kukatko.review.daily` (`lib/reviewRounds.ts:108`, read at `hooks/useReviewGame.ts:352`) is one
  date string, so the second family member to play today is told their first round is not the daily
  mix and is denied the completion.
- `kukatko.gridScroll` (`lib/gridScroll.ts:29`) is keyed on route and query only. Its restore
  behaviour is ticketed separately; here it needs the user in its key so account B does not restore
  account A's offsets and photo.

A separate bug in the same component: `updated_at` is optional on the announcement type
(`services/announcement.ts:26`). With no timestamp, `AnnouncementBanner.tsx:41-43` stores an empty
string but the comparison then never matches, so dismissing is a permanent no-op and the banner
returns on every mount with no way out of the UI.

## Requirements

- Sign-out clears the app's own stored UI state. Be deliberate about what survives: a genuine
  per-device display preference (grid density, the viewer chrome hint) may stay; anything recording
  what an account has seen, dismissed, played or scrolled must go.
- The keys named above carry the acting user, following one of the two existing patterns rather than
  inventing a third. A key belonging to another user reads as absent instead of being honoured.
- Storage that is unreadable, foreign or corrupt keeps failing in the safe direction: show the
  banner, show the panel, start at the top.
- An announcement with no `updated_at` can be dismissed, and stays dismissed until a different
  message is published.
- Do not add a server-side preference for any of this; it stays browser state.

## Testing

- One test per key: state written as user A is not honoured as user B, and sign-out clears what
  should not survive it.
- The announcement case: a message with no `updated_at` can be dismissed and does not return; a newly
  published message does return.
- Existing `AnnouncementBanner`, `useReviewGame` and i18n tests pass, or are updated where they
  encoded the old global key. Note that locale tests must set the language before rendering.
