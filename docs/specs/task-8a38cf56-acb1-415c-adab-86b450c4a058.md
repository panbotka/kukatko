# The principal knows its project

## Context

Kukátko is becoming multi-tenant. A request is authorised by the account's **role in the current project** (`project_members.role`), while instance operations stay behind the instance role (`users.role = 'maintainer'`, called "system admin" in the UI). Design: `docs/superpowers/specs/2026-10-11-multi-tenancy-design.md`, sections 2.3 and 3.1. Step 04 of 40. Already in the tree (verify): `internal/project` (`Store`, `Role`, `Membership`, `MembershipsOf`, `BootstrapUID`), `project_members` backfilled for every user, `project_id` columns.

Today: `internal/auth/role.go` has the ladder viewer < curator < editor < admin < maintainer and predicates `CanCurate/CanWrite/IsAdmin/CanMaintain/CanImport` (`CanImport` is already "maintainer only"); `middleware.go` `requireRole` → `authenticateRequest` (Bearer token, then the `kukatko_session` cookie) → `authorize(role, req)`; `sessions.role` caches the role and `extendSession` re-reads it from `users`. No route carries a project yet, so **in this step the project is always the bootstrap project**; the `{project}` URL parameter is only honoured when present (the next step mounts routes with it). Production: existing sessions, API tokens and passkeys must keep working after deploy.

## Requirements

- Migration: `users.role` CHECK becomes `IN ('user','maintainer')`; `UPDATE users SET role = 'user' WHERE role NOT IN ('user','maintainer')` runs **before** the constraint swap. Drop the `sessions.role` column (or stop reading it — dropping is cleaner; grep for it).
- `internal/auth`:
  - `Role` keeps only `RoleUser` and `RoleMaintainer` (keep the type name so the blast radius stays small); `CanMaintain()`/`CanImport()` = maintainer. Remove the project-level predicates from this type **or** make them delegate to the project role on the principal — pick one and apply it consistently; the per-project predicates must come from `project.Role`.
  - `Principal` gains `Project *project.Project` and `ProjectRole project.Role` (zero value = "no project context").
  - New middleware `WithProject(store *project.Store)`: reads chi URL param `project` (slug). **Transition rule:** when the param is absent, resolve the bootstrap project (`project.BootstrapSlug`); mark this with a comment "transition: removed in the alias-removal step". Resolution: unknown slug → 404; inactive project → 404 for everyone except a maintainer; membership with `approved_at IS NULL` → 403 JSON `{ "error": "pending_approval" }`; non-member → 404 (**identical** to unknown slug — a tenant must not learn the project exists) except a maintainer, who gets `ProjectRole = RoleAdmin` and the structured access log/audit entries carry `actor_role=maintainer`.
  - `RequireAuth`, `RequireCurator`, `RequireWrite`, `RequireAdmin` evaluate `ProjectRole` (through `project.Role` predicates); `RequireMaintainer` and `RequireImport` evaluate `users.role`. `RequireAuthOrDownloadToken` keeps its behaviour, plus the project resolution.
  - Context helpers `ProjectFromContext(ctx) (*project.Project, bool)` and `ProjectUIDFromContext(ctx) string` (empty when absent). These are the **only** way a handler or store learns the current project; document that in the package doc.
  - Wire `WithProject` in `cmd/kukatko` **before** the Require* middlewares on the existing API router (since the param is absent, it resolves the bootstrap project for every current route).
- `GET /auth/me` adds `instance_role` (`user`/`maintainer`), `projects: [{uid, slug, name, active, role, approved}]` (from `MembershipsOf`) and `last_project_slug`. The existing `role` field now returns the **project** role of the resolved project (bootstrap for now) so the frontend keeps working unchanged; for a maintainer it returns `admin`. Update the TypeScript type in `web/src/services/auth.ts` (additive only).
- Registration (`internal/auth/register.go`): the account is created with `users.role = 'user'` and a `project_members` row (`viewer`, unapproved) in the resolved project (bootstrap for now). Approval (`approval.go`) approves the **membership**, and during the transition also stamps `users.approved_at` so the untouched readers keep working. The maintainer check for approving stays as today (project admin).
- `TouchLastProject` is called at most once per minute per user from `WithProject` (an in-memory map with timestamps is fine).
- Tests (integration, `internal/auth`): existing suites green with the bootstrap fallback; new: foreign member → 404 with the same body as unknown slug; pending → 403 `pending_approval`; inactive → 404 for a member, 200 for a maintainer; maintainer without membership → admin; `/auth/me` shape; registration creates the membership; approval approves it. Seeders: many packages seed users with the old roles — the memory-style note in `docs/DEVELOPMENT.md` warns that tightening `users` breaks ~40 seeders; find them with `rg "role.*'(viewer|curator|editor|admin)'" --type go` and fix them (they should seed `users.role = 'user'` + a membership).
- Docs: `docs/ARCHITECTURE.md` auth section (two ladders), `docs/API.md` (`/auth/me` fields, the `pending_approval` error, the 404 rule), `docs/PACKAGES.md` (`internal/auth`).

## Out of scope
