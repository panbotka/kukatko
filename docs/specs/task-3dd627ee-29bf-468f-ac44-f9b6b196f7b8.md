Findings:
1. Switching project (header switcher, phone drawer, Back/Forward between `/p/v/...` and `/p/r2-b/...`) changes URL, title and header, but the page body keeps the previous project's data: albums (incl. a private album), the library (its photos, featured, what's new), people, labels, tasks. Thumbnails are then requested as `/api/v1/p/<new>/photos/<old uid>/thumb` (404) and any action sends the old project's uids to the new project's API. Only header contexts refetch; a reload fixes it. Cause: route components under `/p/:slug/*` stay mounted across a slug change (`web/src/App.tsx` ~264, `web/src/project/paths.ts` ~123-169) and their fetch effects are not keyed on the project.
2. The upload queue resolves the target API URL per file when that file starts (`web/src/hooks/useUploadQueue.ts` ~228-247, `web/src/services/upload.ts` ~201). Files queued in A keep uploading into B after the user switches project (after confirming "leave"), i.e. A's photos land in a foreign library.

## Requirements
- A project change remounts everything project-scoped below the project layout (e.g. `key={projectSlug}` on the project outlet, or an equivalent that resets all per-project state, caches and in-flight requests). Audit every module-level cache / store / context that holds project data (react query keys if any, memoised fetch caches, localStorage/sessionStorage keys, the command palette, search history, timeline cache) and key it by project or reset it on switch. In-flight responses for the old project must never be applied after the switch (abort or ignore by project).
- Upload queue: each queued item captures its project slug (or the full upload URL) at enqueue time and uploads only there; switching project either keeps uploading the remaining files into their original project (with the UI saying so) or cancels them — pick one, explain in docs/FRONTEND.md. Never send a file to a project other than the one it was queued in.
- Vitest: switching `/p/a/albums` → `/p/b/albums` re-fetches with b and never renders a's albums; a resolved-late response for a is ignored; an upload queued in a goes to a's endpoint after the switch. Tests must fail on the current code.
- Verify in a browser against box staging (http://<host>:6490, the staging admin account, projects `v` and `r2-b` exist; see memory/docs on the vite-proxy method in docs/DEVELOPMENT.md) on desktop and phone: switch on albums, library, people, labels, tasks, a photo detail, Back/Forward.
- Docs: docs/FRONTEND.md.
