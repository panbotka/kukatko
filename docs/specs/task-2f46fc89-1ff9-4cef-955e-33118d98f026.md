# The library search field supports the query language but claims it does not

The search box above the library has the placeholder "Filtrovat podle názvu a popisu…"
and the hint "Filtruje název a popis." Both are false: typing `year:1960-1969` filters the
library down to the 227 photos from the 1960s, exactly like `/search` does. The whole
`key:value` query language works there — the field just denies it.

Second half of the problem: a mistyped key (for example `osoba:Jarmila`, the Czech spelling
of `person:`) returns "Nenalezeny žádné fotky" with no warning at all, while `/search`
correctly says "Těmto filtrům nerozumím (hledám je jako obyčejný text): …". The parser
already returns that warning; the library never renders it. So a typo looks like "not in
the library" rather than "you typed it wrong".

Third: when the query contains `year:1960-1969`, the Year dropdown next to it still reads
"Libovolný rok" — the visible filter state contradicts the results.

## Requirements
- Rewrite the placeholder and the hint (Czech and English) so they describe what the field
  really does, e.g. "Hledat — text, nebo filtr jako `year:1965` či `person:Jarmila`".
- Put the same **?** icon next to the field that `/search` uses to open `SearchQueryHelp`,
  reusing the existing component rather than writing a second help text.
- Render the unknown-filter warning in the library, with the same wording `/search` uses.
- When the query contains `year:`, `album:` or `person:`, either reflect the value in the
  matching control, or visibly mark that control as overridden by the query. Do not let the
  two disagree silently.

## Where it is
`web/src/components/library/FilterBar.tsx` (placeholder, `hint`),
`web/src/components/search/SearchQueryHelp.tsx` (existing help to reuse),
`internal/query` (returns the unknown-filter warning), `web/src/i18n`.

## Out of scope
No changes to the query language itself, no data changes.
