# Face tools: two small fixes

Both verified on the box staging (commit 68e805e, 2026-09-06).

## 1. Najít osobu loses its person in the combobox

`web/src/pages/FacesPage.tsx` keeps its state in the URL (`/faces?subject=<uid>&threshold=50&limit=0`). After running a search, and again after a reload of that URL, the results and the line "Hledá se: Testovací osoba 2" are restored — but the combobox "Vyber osobu k hledání" is blank, showing only its placeholder. The URL is the truth and the control does not reflect it. Screenshot: `/mnt/nas-botka/kukatko-stage-test/44-find-person-results.png`.

### Requirements

- On load with `subject=<uid>` and after a search, the combobox shows the selected person's name (resolve the uid through the subjects API when the page has not loaded that subject yet).
- Clearing the combobox clears `subject` from the URL and the results.
- Tests: Vitest for load-from-URL and for the state after a search.

## 2. Weak identity suggestions invite wrong clicks

In the viewer's face naming popover (`web/src/components/people/FaceAssignPanel.tsx`) the "Návrhy" row offered "Testovací osoba 4 · 10%" as a one-click suggestion for an unnamed face. A 10 % match is noise; a person skimming a crowd will click it. Screenshot: `11-face-select.png` in the same folder.

### Requirements

- Suggestions below a display floor are not offered as primary chips. Choose the floor from the existing measurement in `docs/THRESHOLDS.md` (the identity-suggestion threshold in `internal/facematch` is the reference point; the floor is a display decision, not a new cosine threshold) and write the chosen value and its reasoning into `docs/THRESHOLDS.md`.
- If no suggestion clears the floor, show the strongest one in a muted style labelled as uncertain (e.g. "nejistý návrh · 10 %") so the information is not lost, but it must not look like a recommendation.
- The same rule applies wherever the same suggestion list is rendered (the compact roll-call in the info panel's "Lidé" row, if it shows percentages).
- Tests: Vitest for above-floor, below-floor and no-suggestions cases.

## Out of scope

- No change to how the backend ranks or filters suggestions.
