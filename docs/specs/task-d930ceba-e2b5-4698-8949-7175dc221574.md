# Project mark in the navbar opens the project switch

The desktop navbar starts with the current project's mark: a small square holding its first letter (for example "V"). The project's full name (for example "Veselice") follows it. The mark and the name together link to the project's library, `/p/<slug>`. The name takes width in a bar that is already tight, and the bar's "Knihovna" item already leads to the library.

## Requirements

- The navbar brand shows **only the letter mark** (the existing square with the project's first letter). The project name text is no longer rendered there.
- The full project name stays available to assistive technology and as a hover tooltip, e.g. `aria-label` / `title` "Veselice — přepnout projekt" (i18n: cs and en, formal Czech register).
- **Clicking the mark opens the project switch**: it goes to the chooser at `/projects`, the same destination as the existing "Přepnout projekt" entry in the account menu. Reuse that entry's logic (`useLeaveProject` and the existing leave/switch navigation); do not build a second path.
- **When switching is not offered:** an account that can enter only this one project and is not the system administrator gets `offered: false` from `useLeaveProject`.
  - For such an account the mark is not a switch: it links to the project's library `/p/<slug>`, as today.
  - The tooltip and label then name only the project, e.g. "Veselice".
  - Nothing promises a switch that would lead to a chooser listing a single project.
- Keep the existing "Přepnout projekt" entry in the account menu and the phone drawer. The badge for unread notifications in other projects stays where it is.
- If the phone layout (the bar below 992 px or `MobileNavDrawer`) renders the same project name beside the mark, apply the same rule there. Otherwise leave the phone layout unchanged.
- The navbar must not overflow its container at 992 px, 1200 px and 1440 px. Freeing width is the point of this change.
- Tests:
  - update the Layout/navbar tests: the name is not rendered as text; the mark's link target is `/projects` when switching is offered and `/p/<slug>` when it is not; the accessible names are as above;
  - update `MobileNavDrawer.test` and `navItems.test` if they enumerate this.
- Docs: `docs/FRONTEND.md` (navbar / project mark).
- `make check` must pass.
