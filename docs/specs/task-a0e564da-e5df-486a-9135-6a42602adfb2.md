# Registration screen

The API can create an account by self-service — `POST /auth/register`, taking a username,
display name, e-mail, password and a shared secret — and the instance advertises whether
registration is open at `GET /settings/public`. Give it a screen.

## Requirements

- A new route `/register`, reachable without signing in, laid out like the existing
  sign-in screen so the two read as one flow.
- Fields: username, display name, e-mail, password, repeat password, and the shared
  secret. Every field is required. The two passwords must match before the form submits.
- The shared-secret field explains itself in one short line — the reader has been told the
  word by somebody in the community and needs to know that this is where it goes.
- The sign-in screen gains a link to registration, shown **only** when the instance
  reports registration is open. When it is closed the link is absent, and opening
  `/register` directly shows a plain "registration is closed" message rather than a form
  that cannot succeed.
- On success the form is replaced by a confirmation: the account was created, it is
  waiting for an administrator to approve it, and a mail has been sent. There is a link
  back to sign-in. Do **not** sign the person in.
- Rejections are shown next to the field that caused them wherever the API says which one
  it was — a taken username, a malformed address, a wrong secret. A wrong secret must read
  as "that is not the right word", never as a server error.
- Sign-in gains one more outcome to render: an account that exists but is still waiting
  for approval. Show it as its own explanation, distinct from wrong credentials.
- The screen is usable on a phone: one column, inputs large enough to tap, no horizontal
  scrolling.
- All text goes through i18n with Czech and English strings.

## Definition of done

- Component tests cover: a successful submission, mismatched passwords, a wrong secret, a
  taken username, the closed-registration state, and the waiting-for-approval sign-in
  outcome.
- `docs/FRONTEND.md` describes the new page.
- `make check` passes.
