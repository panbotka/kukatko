# `kukatko ctl`: photo state, uploads and the guarded destructive commands

Let `ctl` move a photo through its lifecycle — in, hidden, archived, and finally
gone — with the irreversible steps behind a deliberate gate.

## Requirements

- **Upload**: `ctl photos upload <path…>` sends files through the normal ingest
  path — SHA256 dedup, metadata, thumbnails and the follow-up jobs all happen
  server-side. It streams; a large original is never held in memory. It reports what
  was ingested and what was a duplicate of something already there.
- `ctl photos archive` / `unarchive` and `hide` / `unhide` are ordinary commands.
  They are reversible, so they need no gate.
- **`purge`, emptying the trash and purging by age are irreversible** and require:
  an explicit confirmation flag (a bare invocation refuses and says so), and a
  `--dry-run` that lists exactly which photos would be destroyed without touching
  anything. A `--dry-run` must be possible without the confirmation flag — showing
  what would be lost is how the decision gets made.
- Merging a duplicate group belongs here too, behind the same gate: it archives the
  copies it did not keep.
- `ctl trash info` reports what is in the trash and what retention will remove next,
  so the gate is informed rather than blind.
- **Nothing may delete an original file.** The purge path is the catalogue's own;
  the CLI must not gain any way around it.
- Everything supports `-o llm`.

## Implementation Notes

- Cobra command in `cmd/kukatko/ctl_*.go`, client and renderer in `internal/ctl/*.go`,
  a `_test.go` next to each. Layer over `internal/ingest`, `internal/trash` and
  `internal/dupmerge` — no new deletion logic anywhere.
- The MCP server deliberately exposes none of this and **must stay that way**; the
  guard test that walks `tools/list` for destructive names has to keep passing.
  The CLI is the door for a human holding a token, MCP is the door for an agent
  running unattended — that distinction is the whole point of putting them here.
- Test the gate itself: a purge without confirmation changes nothing, and a
  `--dry-run` changes nothing while still naming the photos at risk.
- Builds on the `-o llm` format from the earlier `ctl` task.
