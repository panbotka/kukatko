# Stats Page: Charts Dashboard

Turn the counters-only stats page into a small dashboard that answers "what does our library look like?".

## Requirements
- Keep the existing counters and add:
  - **Photos per year** (full history, the library spans 1905–2026) — bar histogram; clicking a year opens the library filtered to that year.
  - **Added to the library per month** for the last 12 months — bar chart.
  - **Top cameras** (top 10 by photo count) — horizontal bars.
  - **Storage** — total size by media type (photo/video/RAW) and library size growth by year of addition.
  - **Coverage meters** — % of photos with GPS, % with embeddings, % of detected faces assigned — compact progress rows (these numbers largely exist already).
- Backend: extend the stats API with the needed aggregates. Each aggregate must be a single, cheap, index-friendly query — fast enough for every stats page view, or briefly cached server-side (decide and document).
- Charts: no new heavy charting dependency — plain SVG/CSS in existing theme colors. Must look right in the dark Superhero theme, be responsive (stacked and readable on a phone), and each chart needs an accessible text alternative (aria-label carrying the key numbers).
- Czech/English i18n including localized month labels.
- Tests: Go integration tests for the new aggregates (including an empty library); component tests for chart rendering with fixture data.
- Update docs/API.md and docs/FRONTEND.md.
