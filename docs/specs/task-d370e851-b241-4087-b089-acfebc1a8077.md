# Toasts never appear on a scrolled page

The toast container is positioned against the document instead of the viewport, so every toast is
painted above the fold whenever the page is scrolled — and where it is visible, its close button sits
in the band iOS owns.

## Background

`web/src/components/toast/ToastProvider.tsx:58` renders react-bootstrap's `ToastContainer` with
`position="top-center"` and the classes `p-3 kk-toast-stack`. It does **not** pass
`containerPosition`, so the container keeps Bootstrap's own `position: absolute` — verified in the
bundled `bootswatch/dist/superhero/bootstrap.min.css`, where `.toast-container` is declared
`position:absolute`. `.kk-toast-stack` (`web/src/styles/tokens.css:1598`) declares only a `z-index`,
and nothing between the container and `#root` is positioned. An absolutely positioned box with no
positioned ancestor resolves against the initial containing block, so `top: 0` means the top of the
**document**, not of the viewport.

Consequence: on any scrolled page the toast is drawn off screen and never seen. Every confirmation
and every error the app reports this way is silently lost. The doc comment at `ToastProvider.tsx:29`
already describes the stack as fixed, so the markup contradicts its own documented intent.

Second, smaller problem: even at the top of a page, `top: 0` plus `p-3` puts the toast and its close
button 16px down, inside the 47–59px inset of the iOS PWA (`web/index.html` ships `viewport-fit=cover`
with `black-translucent`). A tap there scrolls the page instead of dismissing the toast.

## Requirements

- The stack is anchored to the viewport, so a toast is visible at any scroll offset on any page.
- `.kk-toast-stack` adds the top, left and right safe-area insets on top of its existing padding, so
  the toast and its close button clear the status bar in portrait and the notch column in landscape.
- The doc comment at `ToastProvider.tsx:29` ends up true rather than aspirational.
- Nothing about layering changes: the stack already sits above the immersive viewer and stays there.

## Testing

- Assert the container is rendered fixed rather than absolute, at the level that reaches the DOM, so
  a later refactor that drops it fails the suite.
- A CSS assertion in the style of `web/src/styles/safeArea.test.ts` that `.kk-toast-stack` names the
  top, left and right insets.
- Prove the scroll case rather than reasoning about it: raise a toast on a scrolled page and show the
  container's rect is inside the viewport. Report the numbers.
- Existing `ToastProvider` tests must still pass.
