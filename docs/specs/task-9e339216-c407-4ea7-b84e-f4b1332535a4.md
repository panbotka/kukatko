# Tune the map for touch: gesture handling and larger controls

On a phone the map view is a scroll trap and its controls are too small for touch.

## Current behavior

- `web/src/components/map/LeafletMap.tsx` initializes Leaflet with defaults, and
  `web/src/pages/MapPage.tsx` renders the map at ~70vh inside the scrolling app shell.
- Symptoms: a one-finger drag over the tall map pans the map instead of scrolling the
  page, so the user gets "stuck" on the map and can't easily scroll past it; Leaflet's
  default +/- zoom buttons are ~30px (below the 44px touch minimum). A repo-wide search
  found NO `.leaflet-*` CSS overrides anywhere.

## Requirements

- Fix the scroll trap on touch: a one-finger swipe over the map should scroll the PAGE,
  while a deliberate two-finger gesture pans/zooms the map (gesture-handling behavior).
  Implement via Leaflet options (e.g. disable one-finger `dragging` in favor of a
  gesture-handling approach, keep pinch `touchZoom`) or an equivalent — the goal is
  that the user is never trapped on the map. Do NOT add a new heavy dependency if a
  small config/handler achieves it; if a tiny gesture-handling plugin is the standard
  solution, that's acceptable, but keep the bundle lean.
- Enlarge the zoom controls (and any other Leaflet controls) to a ≥44px touch target on
  coarse-pointer devices via `.leaflet-bar` / `.leaflet-control` CSS overrides.
- Keep desktop mouse behavior unchanged (wheel-zoom / drag-pan as today).
- Optionally size the map with `dvh` instead of `vh` so it uses usable height under the
  mobile browser chrome.

## Testing

- Add a test where practical (control sizing / options wiring). CSS/gesture behavior is
  hard to unit-test; a config assertion is acceptable.
- `make check` must pass. Note the change in `docs/FRONTEND.md`.

Note: dark-theme styling of the map popups/attribution is handled by a SEPARATE task;
this task is only gestures + control sizing (+ optional dvh height). Keep them apart.
