# Bulk Taken-Date Assignment

Fix scanned photos with missing or nonsense dates in one action instead of photo by photo.

## Requirements
- The bulk edit flow (multi-select → bulk actions) gains "Set taken date" with precision options: exact date, month + year, year only, or decade.
- Applying it sets the taken date on all selected photos in one transaction, audited; the UI confirms the scope first ("Nastavit rok 1974 pro 36 fotek?") and reports how many photos changed.
- Photos must then sort and filter into the right period everywhere: library timeline, period filter, year facets, and the query language's year filter.
- Approximate precision (year/decade) must match how the app already stores year-only or approximate dates from imports — investigate the existing convention first and follow it. If none exists, choose one, document it in docs/ARCHITECTURE.md, and make sure the photo detail does not display a fabricated exact day for year-precision dates if the detail currently renders full dates.
- Guard rails: the action never touches file EXIF or originals — catalog metadata only (the existing sidecar-rewrite job picks the change up automatically).
- Editor role. i18n cs/en.
- Integration tests: each precision level, transactionality, timeline/facet effect. Component test for the new bulk-edit field including the confirmation.
- Update docs/API.md and docs/FRONTEND.md.
