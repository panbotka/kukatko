# Virtualize the albums grid

Unlike the photo grids (which use `react-virtuoso`), the albums index renders every
album card into the DOM at once. On a large album collection this inflates the DOM and
starts many cover-thumbnail loads; covers are `loading="lazy"` so it is bounded, but it
scales worse than the virtualized grids.

## Current behavior

- `web/src/pages/AlbumsPage.tsx` (around lines 78-90): a plain CSS `display:grid`
  (`minmax(160px,1fr)`) mapping over the full album list, each an `AlbumTile` with a
  lazy-loaded cover. No virtualization.

## Requirements

- Virtualize the albums grid so only the visible (plus a small buffer) album cards are
  mounted, matching how the photo grid uses `react-virtuoso` (see
  `web/src/components/library/PhotoGrid.tsx` for the established pattern — reuse it or
  the same approach).
- Preserve the current responsive column behavior (2 columns at 360px, 1 at 320px, more
  on wider screens) and the existing tile appearance/links.
- Preserve URL-driven view state and "back always works" behavior.
- If album counts are always small in practice, keep the change minimal and low-risk;
  the goal is DOM/scroll scalability without changing the visible layout.
