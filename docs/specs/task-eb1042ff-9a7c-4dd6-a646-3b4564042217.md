# The phone column cap exists, is tested, and is never called

On a phone the library grid renders six tiles per row. Measured on the live instance at
390 px wide: six tiles per row, 99 px per tile, and every tile carries a permanently visible
selection circle and favourite heart that together cover a large part of the thumbnail.

The first half of this is **dead code, not a missing feature**. `lib/gridDensity.ts` already
defines `GRID_COLUMN_CAPS` — at most 3 columns below 576 px, at most 4 below 768 px — and
`clampColumnsToWidth()` to apply them, with tests and a comment explaining exactly the defect
seen in production ("eight columns across 393 px leaves tiles under 50 px, where the favourite
heart drawn on a tile is larger than the photograph under it"). Nothing in the app calls
`clampColumnsToWidth`: the only references are its own definition and its tests.

## Requirements

- Apply the existing column cap where the grid decides how many columns to render, so a narrow
  viewport gets at most the capped number of columns whatever the stored density says.
- Keep the cap a display-time clamp: the reader's stored density preference must not be
  rewritten, which is what the existing helper already guarantees. A reader who set eight
  columns on a laptop still has eight columns there.
- Verify in a browser at 390 px that the rendered grid obeys the cap, and at desktop width that
  nothing changed. A unit test alone is not enough — the helper is already unit-tested and the
  app was still shipping six columns.
- Reduce the permanent overlay burden on touch, where the controls cannot hide on hover the way
  they do with a mouse: make the selection affordance small and corner-anchored rather than a
  large disc over the middle of the picture, and take the favourite heart off the phone grid
  tile. Favouriting stays available in the photo detail.
- Selection stays fully usable on touch through the existing press-and-hold-and-drag gesture,
  and a selected tile is still obviously selected.
- Desktop hover behaviour is unchanged.
- Tap targets that remain on a tile meet the app's existing finger-size floor.

## Edge cases

- A tablet-width viewport, which the caps deliberately treat differently from a phone.
- Selection mode active with a small affordance — the selected state must stay unmistakable.
- A grid other than the library's that shares the same density plumbing.
