# Family network 2/3 — one layered drawing on the tree page

Replace the two directional renderers with a single drawing of the whole reachable
network, and drop the controls. This is the step that completes the feature.

Read `docs/superpowers/specs/2026-09-26-family-network-view-design.md` sections 2, 5 and 6
before starting. Requires step 1.

## Requirements

- A new pure layout function `layoutNetwork` in `web/src/lib/familyLayout.ts`, layered:
  the layer is the signed generation the server computed, so
  `y = (generation − minGeneration) * LEVEL_STRIDE`; a couple is one box as today's
  `buildNodes` already treats it; ordering within a layer is seeded breadth-first from the
  root and improved by a few barycentre sweeps (a box's target is the mean position of its
  partners, its children and its parents); coordinates are packed left to right with the
  existing `PERSON_WIDTH`, `SIBLING_GAP` and `COUPLE_GAP` and then nudged toward the
  barycentre. No layout library — the hand-written pure layout is a standing decision.
- `FamilyTreePage` fetches the network once and mounts one canvas. The direction button
  group and the generations select are removed, along with their URL state.
- Reuse unchanged: `TreeStage` with its pan, zoom, fit and centre-on-root, `TreePersonCard`,
  `TreeBox`, the square elbow `edgePath`, and the page's `orderChildren` sort by birth year
  then Czech-collated name.
- Delete `layoutAncestors`, `FamilyPedigreeCanvas`, `FamilyTreeCanvas`,
  `MAX_PEDIGREE_GENERATIONS` and its clamp, and the tests that covered only them.
- The pedigree's empty-slot `+`, which opens `AddRelationModal` to add a missing parent,
  **moves onto the person card**: a `+` on a card opens the same modal under the same
  permission the pedigree's `+` uses today. Adding a missing parent from the drawing must
  not be lost, only relocated.
- The header summary becomes the number of people and
  `max(generation) − min(generation) + 1` generations.
- A truncated response shows a plain banner saying the nearest N of M are drawn.
- Tests: vitest over `layoutNetwork` as a pure function — layer assignment from signed
  generations, a couple as one box, no two boxes overlapping within a layer, a cycle laid
  out without duplication, and the empty graph. Then the page: the controls are gone, one
  drawing mounts, the truncation banner appears, the card's `+` opens the modal.
- Docs: `docs/FRONTEND.md`, `docs/ARCHITECTURE.md` (this revises the tree-view decision of
  the 2026-09-12 spec), `README.md`.

## Implementation notes

- Verify the drawing for real, not only in vitest: jsdom will not tell you whether boxes
  overlap or an elbow crosses a card. Drive the page in a browser against a throwaway
  instance seeded with the production shape — a couple with a child, a parentless sibling
  group, and the sibling's own child, which must all appear on one page.
- `MIN_SCALE = 0.05` already exists in `treeView.ts`, so a wide drawing can be fitted.
