## Goal (user request)
In comments, I want to mention people, e.g. `@Tomáš Kozák`. The mention is **highlighted** and **links to the person**, and the mentioned person gets a **notification**. It must work in both comment threads: on a **photo** and on a **task** (`/tasks/<uid>`).

**Dependency:** the notification part needs the in-app/push/e-mail channel work, task "Notifications 1/4" (`notification.Deliver`, everything off by default). If 1/4 is not on main yet, ship the mention parsing / highlighting / linking and **stop with a note** instead of building on the old push-only path. Or do it all once 1/4 is on main.

## Current state
- `internal/comments`: plain-text threads on a photo or a task, soft delete, audited. Every role may write, viewers included. The endpoints are in `internal/photoapi` and `internal/phototaskapi`.
- Since 597058a, task bodies and comments render as GFM Markdown through the `Markdown` component (`react-markdown` + `rehype-sanitize`, never optional).
- There is an all-authenticated user name directory, `GET /users` (`internal/auth`).
- A user may be linked to a library subject (`subject_uid`; see `internal/personme`). There is **no user profile page**; a subject has `/people/:uid`.

## Decisions (made by the spec; change only with a reason, and document it)
1. **Who can be mentioned:** user **accounts** (they are the ones who can be notified), from the `GET /users` directory. Disabled accounts are not offered. Subjects without an account cannot be mentioned.
2. **Storage: by uid, not by name.** A rename must not break old mentions. The composer inserts a token, e.g. `@[Tomáš Kozák](user:<uid>)`, or another unambiguous syntax of your choice that survives Markdown. Rendering shows `@<current display name>`, falling back to the stored name when the account is gone. A raw `@Tomas` typed without picking from the list stays plain text: no fuzzy matching.
3. **Link target:** the mentioned user's linked subject page `/people/<subject_uid>` when the user has a linked subject. Otherwise there is no link, only the highlight with the name as a tooltip. Never link to admin user management.
4. **Highlight:** a pill/badge styled from palette tokens only (no colour literals; contrast tests must stay green), plus `bi-at` or `bi-person` via the `Icon` component if it reads well. The mention of **me** is emphasised more strongly.

## What to build
- **Frontend composer** (shared by the photo and task comment boxes):
  - typing `@` opens an autocomplete of users (filter by display name, diacritics-insensitive);
  - keyboard: ↑ ↓ Enter Esc; select on mousedown (memory: autocomplete selects on mousedown, so a test `.click()` silently picks nothing);
  - works on touch and at phone width; inputs at 16px on phones (no iOS zoom).
- **Rendering:** a remark/rehype plugin (or a Markdown component extension) that turns the token into the mention element *inside* the sanitized pipeline. `rehype-sanitize` must stay on, and its schema may only be widened for exactly this element/attribute.
- **Backend:**
  - on comment create, parse the mentions: validate the uids exist and are active, de-duplicate, and ignore a self-mention;
  - **editing:** if comments can be edited, notify only newly added mentions;
  - store the mentioned set (e.g. a `comment_mentions` table, FK cascade). It feeds the notification and possible later "mentions of me" filtering;
  - a new table also needs classification in `internal/reset/tables.go` (memory).
- **Notification:** a new kind `comment_mention` (all channels off by default; in the preferences grid, cs + en; Czech mail template):
  - text: "<who> tě zmínil(a) v komentáři u fotky / u úkolu <title>", with a comment excerpt;
  - link: to the photo or task, scrolled/anchored to the comment;
  - delivered through `notification.Deliver` in the comment's transaction, or through a job if fan-out is large;
  - **visibility:** never notify someone who cannot see the photo (private/hidden/archived photo vs. the recipient's role) or the task. Mention them visually, but skip the notification.
- **Deleting** a comment before delivery cancels nothing, which is acceptable (notifications are frozen). Note this choice in the docs.

## Tests
- Go: unit tests for the mention parser (token formats, invalid uid, duplicate, self, Markdown edge cases: inside code spans/blocks a mention is NOT a mention); integration tests for comment create on a photo and on a task → the stored mentions + notifications for the right users; visibility skip.
- Vitest: composer autocomplete (mousedown selection, keyboard), rendering (highlight, link vs. no-link, "me" emphasis, renamed user, deleted user), sanitizer still strips unsafe HTML.
